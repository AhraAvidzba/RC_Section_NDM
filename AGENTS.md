# AGENTS.md — правила проекта RC Section NDM VBA

## 1. Назначение проекта

Проект представляет собой инженерную программу на Excel VBA для расчёта железобетонных поперечных сечений по нелинейной деформационной модели.

Основные расчётные задачи:

* расчёт прочности при действии `N + Mx`;
* расчёт прочности при действии `N + My`;
* расчёт прочности при косом изгибе `N + Mx + My`;
* определение действующих и удерживающих моментов;
* определение коэффициента запаса;
* определение коэффициента использования;
* расчёт напряжённо-деформированного состояния бетона и арматуры;
* расчёт ширины раскрытия уже образовавшихся нормальных трещин;
* обработка нескольких сочетаний нагрузок;
* вычисление геометрических характеристик произвольного сечения.

Основные нормативные документы:

* СП 35 «Мосты и трубы» в актуальной редакции с действующими изменениями;
* СП 63 «Бетонные и железобетонные конструкции. Основные положения» в актуальной редакции с действующими изменениями.

Программа предназначена для инженерных расчётов. Корректность расчётной модели, прозрачность алгоритмов, воспроизводимость и проверяемость результатов важнее скорости написания кода.

## 3. Границы расчётной задачи

### 3.1. Первая группа предельных состояний

Программа должна выполнять расчёт прочности при сочетаниях:

```text
N + Mx
N + My
N + Mx + My
```

Необходимо определять:

* параметры плоскости деформаций;
* положение нейтральной оси;
* форму сжатой зоны;
* деформации бетона;
* деформации арматуры;
* напряжения бетона;
* напряжения арматуры;
* внутренние усилия;
* удерживающие моменты;
* коэффициент запаса;
* коэффициент использования;
* критерий исчерпания несущей способности.

### 3.2. Вторая группа предельных состояний

В программе требуется только расчёт ширины раскрытия уже образовавшихся нормальных трещин.

Не требуется:

* отдельный расчёт образования трещин;
* определение момента образования трещин `Mcrc`;
* отдельный режим `CrackFormation`;
* построение диаграммы растянутого бетона до образования трещины.

При расчёте ширины раскрытия трещин принимать, что нормальные трещины уже образовались.

Расчётная схема трещиноватого сечения:

* сжатый бетон участвует в работе;
* растянутый бетон не создаёт внутренних усилий;
* растянутый бетон имеет нулевое напряжение;
* растянутый бетон имеет нулевую касательную жёсткость;
* вся продольная арматура участвует согласно фактическим деформациям;
* напряжения арматуры определяются при эксплуатационном сочетании нагрузок;
* ширина раскрытия рассчитывается по нормативной методике СП 35 и СП 63.

Площадь растянутого бетона может использоваться только как геометрический параметр нормативной формулы расстояния между трещинами. Это не означает участие растянутого бетона во внутренних усилиях трещиноватого сечения.

## 4. Основные физические предпосылки

Использовать гипотезу плоских сечений.

Поле продольных деформаций:

```text
epsilon(x, y) = epsilon0 + kappaX * y + kappaY * x
```

Неизвестные параметры:

* `epsilon0` — продольная деформация в начале координат;
* `kappaX` — кривизна, связанная с изменением деформации по координате `y`;
* `kappaY` — кривизна, связанная с изменением деформации по координате `x`.

Уравнения равновесия:

```text
Nint  = Next
Mxint = Mxext
Myint = Myext
```

Даже при внешнем воздействии только `Mx` нельзя заранее принимать:

```text
kappaY = 0
```

Для несимметричного сечения, например Г-образного, при:

```text
Mx != 0
My = 0
```

может получиться:

```text
kappaX != 0
kappaY != 0
```

При этом внутренний момент должен удовлетворять:

```text
Myint ≈ 0
```

Все режимы расчёта должны использовать единый трёхпараметрический решатель.

## 5. Система координат и единицы

Система координат, направление положительных осей, знаки продольной силы, моментов, деформаций и кривизн должны быть описаны в:

```text
docs/CoordinateSystem.md
```

Внутренние единицы программы:

```text
длина       — мм
площадь     — мм²
сила        — Н
момент      — Н·мм
напряжение  — МПа, то есть Н/мм²
деформация  — безразмерная
кривизна    — 1/мм
```

Преобразование пользовательских единиц выполнять только:

* при чтении исходных данных;
* при выводе результатов.

Расчётное ядро должно работать только во внутренних единицах.

## 6. Архитектурные принципы

1. Расчётное ядро не должно обращаться напрямую к листам Excel.

2. Разделяй:

   * ввод данных;
   * вывод результатов;
   * геометрию;
   * построение волокон;
   * арматуру;
   * модели материалов;
   * нормативные правила;
   * численный решатель;
   * поиск несущей способности;
   * расчёт ширины раскрытия трещин;
   * диагностику;
   * тестирование.

3. Форма сечения не должна быть зашита в решатель НДМ.

4. Добавление новой геометрии не должно требовать изменения основного решателя.

5. Основной решатель должен получать уже подготовленные:

   * массив бетонных волокон;
   * массив арматурных стержней;
   * модели материалов;
   * внешние усилия;
   * настройки решения.

6. Расчётный класс не должен содержать:

```vba
Range(...)
Cells(...)
Worksheets(...)
ActiveSheet
Selection
```

7. Расчётный класс не должен знать:

   * названия листов;
   * адреса ячеек;
   * тип конкретного сечения;
   * конкретный класс бетона;
   * конкретную таблицу СП.

8. Геометрия должна реализовываться через общий интерфейс, например:

```text
ISectionGeometry
```

9. Модели материалов должны реализовываться через интерфейсы, например:

```text
IConcreteMaterial
ISteelMaterial
```

10. Нормативные правила должны быть отделены от общего численного решателя.

11. Архитектура должна позволять в будущем добавлять:

* круглое сечение;
* прямоугольное сечение;
* скруглённый прямоугольник;
* Г-образное сечение;
* Т-образное сечение;
* произвольный полигон;
* составное сечение;
* сечение с отверстиями.

12. Не проектируй архитектуру, которая выглядит красиво только теоретически, но не компилируется в VBA.

13. Учитывай ограничения VBA на:

* интерфейсы через `Implements`;
* пользовательские типы;
* передачу массивов;
* публичные типы;
* производительность классов в горячих циклах.

14. Для конфигурации и логики допускаются классы.

15. Для десятков тысяч бетонных волокон предпочитай типизированные массивы, а не создание отдельного VBA-объекта для каждого волокна.

## 7. Геометрия и волоконная модель

Геометрия должна предоставлять:

* границы сечения;
* проверку принадлежности точки бетонному контуру;
* площадь;
* центр тяжести;
* геометрические характеристики;
* проверку допустимости параметров;
* данные для построения сетки;
* проверку положения арматуры;
* характерные крайние точки.

Первая новая геометрия:

```text
CGeometryRoundedRectangle
```

Она должна поддерживать:

* ширину;
* высоту;
* радиусы углов;
* положение относительно локальной системы координат.

Архитектура должна допускать четыре независимых радиуса углов.

Проверять:

* положительность размеров;
* неотрицательность радиусов;
* допустимость радиусов;
* отсутствие самопересечений;
* корректность площади;
* корректность центра тяжести;
* симметрию при одинаковых радиусах.

Бетонное сечение разбивается на волокна.

Каждое волокно должно содержать:

```text
X
Y
Area
FillFactor
MaterialID
```

На первом этапе допускается учитывать граничную ячейку целиком, если её центральная точка находится внутри контура.

Архитектура должна позволять позднее добавить:

* коэффициент фактического заполнения ячейки;
* деление граничной ячейки на подячейки;
* адаптивное измельчение;
* отверстия;
* несколько бетонных областей;
* разные материалы.

Сетку создавать один раз до начала итерационного расчёта.

## 8. Геометрические характеристики

По набору элементарных площадок программа должна уметь вычислять:

* площадь;
* статические моменты;
* центр тяжести;
* `Ix`;
* `Iy`;
* `Ixy`;
* моменты инерции относительно исходных осей;
* центральные моменты инерции;
* угол главных центральных осей;
* главные моменты инерции;
* радиусы инерции;
* при необходимости моменты сопротивления.

Геометрические характеристики должны вычисляться независимо от НДМ.

Точность характеристик должна проверяться при уменьшении шага сетки.

Для геометрий, имеющих аналитическое решение, сравнивать численный результат с аналитическим.

## 9. Арматура

Арматуру учитывать отдельно от бетонной сетки.

Каждый стержень должен содержать:

```text
ID
X
Y
Diameter
Area
SteelMaterial
Comment
```

Напрягаемая арматура не входит в область проекта. Программа должна поддерживать только обычную ненапрягаемую арматуру; начальные деформации, преднапряжение и связанные с ними режимы не проектировать и не оставлять как будущую возможность.

Площадь стержня не должна зависеть от размера бетонной ячейки.

Деформация стержня:

```text
epsilonS = epsilon0 + kappaX * yS + kappaY * xS
```

Усилие:

```text
Fs = sigmaS * As
```

Моменты:

```text
MxS = Fs * yS
MyS = Fs * xS
```

Необходимо исключить двойной учёт бетона, замещённого арматурой.

Базовый вариант:

```text
EffectiveSteelStress =
    SteelStress - ConcreteStressAtSameStrain
```

Тогда:

```text
Fadditional = EffectiveSteelStress * As
```

Для касательной матрицы:

```text
EffectiveTangent =
    SteelTangent - ConcreteTangentAtSameStrain
```

Этот подход должен быть проверен контрольным тестом против модели, в которой площадь арматуры геометрически исключена из бетона.

Проверять:

* центр стержня находится внутри сечения;
* весь диаметр стержня находится внутри контура;
* соблюдён защитный слой;
* стержни не пересекаются;
* отсутствуют дубли координат.

## 10. Модели материалов

Расчётное ядро не должно содержать конкретных диаграмм материалов.

Интерфейсы материалов должны предоставлять методы, аналогичные:

```text
GetStress(strain, calculationMode)
GetTangentModulus(strain, calculationMode)
GetSecantModulus(strain, calculationMode)
CheckLimitState(strain, stress, calculationMode)
```

Основные режимы:

```text
StrengthULS
CrackWidthSLS
```

Режим `CrackFormationSLS` не создавать.

### 10.1. Прочность

В режиме `StrengthULS`:

* использовать нормативную диаграмму сжатого бетона;
* использовать нормативную диаграмму арматуры;
* контролировать предельные деформации;
* фиксировать причину исчерпания прочности;
* растянутый бетон не учитывать, если это соответствует выбранной нормативной постановке.

При выключении растянутого бетона одновременно принимать:

```text
Stress = 0
TangentModulus = 0
```

Нельзя оставлять ненулевую жёсткость растянутого бетонного волокна при нулевом напряжении.

### 10.2. Ширина раскрытия трещин

В режиме `CrackWidthSLS`:

* считать сечение трещиноватым;
* сжатый бетон учитывать;
* растянутый бетон не учитывать во внутренних усилиях;
* растянутый бетон должен иметь нулевую касательную жёсткость;
* учитывать всю продольную арматуру;
* определять эксплуатационные напряжения и деформации стержней;
* учитывать нормативные коэффициенты только после подтверждения конкретным пунктом СП.

## 11. Численный решатель

Основной класс:

```text
CSectionSolver
```

Основной метод решения:

* полный метод Ньютона;
* касательная матрица;
* пересчёт касательной матрицы на каждой итерации;
* демпфирование шага;
* line search;
* пошаговое приложение нагрузки;
* использование результата предыдущей ступени как начального приближения.

Основной алгоритм:

1. Принять текущие:

   * `epsilon0`;
   * `kappaX`;
   * `kappaY`.

2. Рассчитать деформации всех бетонных волокон.

3. Рассчитать деформации всех арматурных стержней.

4. Получить напряжения материалов.

5. Просуммировать:

   * `Nint`;
   * `Mxint`;
   * `Myint`.

6. Вычислить:

   * `ResidualN`;
   * `ResidualMx`;
   * `ResidualMy`.

7. Проверить критерии сходимости.

8. Построить касательную матрицу.

9. Решить систему `3 × 3`.

10. Получить поправки:

    * `DeltaEpsilon0`;
    * `DeltaKappaX`;
    * `DeltaKappaY`.

11. Применить демпфирование.

12. Повторять до:

    * сходимости;
    * физического предельного состояния;
    * диагностируемой численной остановки.

Не использовать полный перебор трёх параметров как основной метод.

Полный или локальный перебор допускается только:

* для грубого начального приближения;
* для тестирования;
* для проверки метода Ньютона;
* как аварийный локальный механизм.

Резервные алгоритмы:

* модифицированный Ньютон;
* секущая матрица;
* уменьшение шага нагрузки;
* ограничение максимальных приращений;
* локальный грубый поиск;
* повторный запуск с другим начальным приближением.

Не считать любую потерю сходимости признаком разрушения.

Различать:

* физическое достижение предельной деформации;
* физическое достижение предельного напряжения;
* максимум несущей способности;
* численную несходимость;
* вырожденность матрицы;
* плохую обусловленность;
* ошибку исходных данных.

---

## 12. Решение системы уравнений

Не использовать:

```vba
WorksheetFunction.MInverse
```

Реализовать собственное решение системы `3 × 3`:

* с выбором главного элемента;
* с контролем масштаба;
* с диагностикой вырожденности;
* с оценкой обусловленности;
* с проверкой невязки после решения.

Решение матрицы должно быть отдельным модулем или классом.

---

## 13. Критерии сходимости

Использовать отдельные нормированные критерии:

```text
errorN
errorMx
errorMy
```

Нельзя напрямую складывать силу и момент в одну размерную ошибку.

Результат решателя должен содержать:

* `Converged`;
* число итераций;
* число ступеней нагрузки;
* `epsilon0`;
* `kappaX`;
* `kappaY`;
* внутренние усилия;
* абсолютные невязки;
* относительные невязки;
* положение нейтральной оси;
* угол нейтральной оси;
* крайние деформации;
* крайние напряжения;

## 14. Поиск несущей способности

Использовать отдельный класс:

```text
CCapacitySolver
```

### 14.1. Расчёт Mx

```text
N  = Nspecified
Mx = lambda * MxBase
My = 0
```

### 14.2. Расчёт My

```text
N  = Nspecified
Mx = 0
My = lambda * MyBase
```

### 14.3. Косой изгиб Mxy

```text
N  = Nspecified
Mx = lambda * MxBase
My = lambda * MyBase
```

При косом изгибе направление вектора моментов должно сохраняться.

Определять:

```text
lambdaUltimate
```

Коэффициент запаса:

```text
SafetyFactor = lambdaUltimate
```

Коэффициент использования:

```text
Utilization = 1 / lambdaUltimate
```

При поиске несущей способности:

1. Найти допустимое состояние.
2. Найти верхнюю недопустимую границу.
3. Уточнить предельный множитель устойчивым одномерным поиском.
4. Не считать несходимость автоматически разрушением.
5. Сохранять подробную причину остановки.

## 16. Работа с несколькими сочетаниями

Архитектура должна позволять в будущем рассчитывать не одно, а несколько сочетаний нагрузок за один запуск.

Минимальная целевая возможность:

* до 20 сочетаний нагрузок;
* единая геометрия;
* единая арматура;
* единые материалы;
* различные `N`, `Mx`, `My`.

Для производительности:

* геометрию строить один раз;
* волоконную сетку строить один раз;
* неизменяемые параметры кэшировать;
* не пересоздавать модели материалов;
* использовать результат соседнего сочетания как начальное приближение только при физической оправданности;
* результаты возвращать массивом.

Допускается в будущем реализовать пользовательскую функцию Excel, которая принимает диапазон сочетаний и возвращает массив результатов.

Такая функция:

* не должна быть `Volatile`;
* не должна обращаться к листам внутри горячих циклов;
* не должна пересчитывать геометрию для каждой выходной ячейки;
* должна вызываться один раз для всего массива сочетаний.

## 18. Именованные диапазоны

Все чтение и запись данных листов выполнять через именованные диапазоны.

Прямые адреса допускаются только:

Не создавай отдельное имя для каждой ячейки.

## 19. Производительность

Основная стоимость расчёта — многократный проход по бетонным волокнам.

Обязательные меры:

1. Не обращаться к Excel внутри расчётных циклов.

2. Не обращаться к `Range`, `Cells`, именованным диапазонам и `WorksheetFunction` внутри горячих циклов.

3. Считывать данные с листов один раз.

4. Записывать результаты одним блоком.

5. Использовать типизированные массивы.

6. Не использовать `Collection` для десятков тысяч волокон.

7. Не создавать тяжёлый VBA-объект для каждого бетонного волокна без доказанной необходимости.

8. Не использовать `Variant`, если возможны:

   * `Double`;
   * `Long`;
   * `Boolean`;
   * типизированный массив.

9. Не использовать `ReDim Preserve` внутри горячего цикла.

10. Предварительно вычислять:

    * координаты волокон;
    * площади;
    * произведения координат;
    * неизменяемые геометрические множители.

11. Не пересоздавать сетку на каждой итерации.

12. Кэшировать неизменяемую геометрию.

13. Не делать пользовательскую функцию `Volatile`.

14. Отключение:

    * `ScreenUpdating`;
    * `EnableEvents`;
    * автоматического пересчёта

    выполнять только в управляющем слое.

15. После завершения или ошибки обязательно восстанавливать настройки Excel.

16. Сначала обеспечить корректность и диагностику, затем выполнять оптимизацию.

### 23.4. Несимметричное сечение

Для Г-образного сечения при:

```text
Mx != 0
My = 0
```

допускать:

```text
kappaY != 0
```

при выполнении:

```text
Myint ≈ 0
```

### 23.5. Прямоугольное сечение

Сравнивать НДМ с классическим расчётом по СП 35 при максимально одинаковых предпосылках.

### 23.6. Круглое сечение

Сравнивать с программой из:

```text
reference/round_section/
```

Но не считать её безусловным эталоном.

### 23.7. Произвольное сечение

Сравнивать с программой из:

```text
reference/arbitrary_section_ndm/
```

### 23.8. Сетка

Проверять изменение результата при последовательном уменьшении шага сетки.

### 23.9. Равновесие

Для каждого принятого результата проверять:

```text
Nint ≈ Next
Mxint ≈ Mxext
Myint ≈ Myext
```

Результат без выполненного равновесия не считать корректным.

### 23.10. Трещины

Сравнивать:

* напряжения растянутой арматуры;
* положение нейтральной оси;
* ширину раскрытия;
* коэффициент использования

с ручными расчётами и доверенными программами.

* записывать результаты по одной ячейке внутри расчёта;
* использовать полный перебор трёх параметров как основной решатель;
* считать несходимость физическим разрушением без диагностики;
* скрывать невязки;
* заявлять нормативное соответствие без верификации;
* использовать случайные числовые константы без объяснения;
* изменять референсные файлы без отдельного задания;
* удалять существующий код до завершения анализа;
* оптимизировать код ценой потери прозрачности и проверяемости.

## 27. Приоритеты проекта

Порядок приоритетов:

1. Нормативная корректность.
2. Физическая корректность.
3. Выполнение равновесия.
4. Проверяемость.
5. Диагностируемость.
6. Расширяемость.
7. Производительность.
8. Оформление.
9. Минимальный объём кода.

Сначала программа должна давать объяснимый и проверяемый результат. Только после этого допускается оптимизация скорости и сокращение вывода.

## 28. Дополнительные правила развития архитектуры

Этот раздел фиксирует дополнительные проектные решения для следующих этапов
после аудита текущей реализации.

1. Проект должен оставаться полностью работоспособным в Excel/VBA без
   обязательной установки дополнительных библиотек, внешних DLL, NuGet-пакетов
   или исполняемых файлов.

2. AutoCAD является необязательным внешним приложением. Взаимодействие с ним
   допускается только через Late Binding. Книга должна компилироваться и
   выполнять параметрический расчёт без установленного AutoCAD; недоступными
   должны быть только функции импорта и экспорта AutoCAD.

3. Основной расчёт выполняется в оперативной памяти. Листы Excel не должны
   использоваться как рабочая память численного решателя.

4. Для записи больших таблиц результатов использовать двумерные массивы и одно
   присваивание `Range.Value2`. Построчное заполнение допустимо только для
   небольших служебных блоков до отдельного этапа рефакторинга writer-слоя и
   должно быть отмечено в аудите как технический долг.

5. Настройки на листе `System` должны быть разделены на небольшие смысловые
   группы. Не должно быть дублирующихся параметров, скрытых настроек с
   непонятным назначением и параметров, которые отображаются пользователю, но
   нигде не читаются кодом.

6. Параметры с конечным набором значений должны получать выпадающие списки:
   метод расчёта, метод решателя равновесия, алгоритм поиска несущей
   способности, источник геометрии, режим учёта растянутого бетона и настройки
   AutoCAD.

7. Перед удалением или объединением любой настройки необходимо найти все места
   её чтения и использования. Не удалять параметр только по названию.

8. Для несущей способности целевая архитектура должна поддерживать два
   независимых метода:

```text
SolveByLoadMultiplier
SolveByUltimateStrain
```

   Фактически реализованные методы и настройки должны быть подтверждены аудитом
   до изменения алгоритма.

9. Должен быть создан единый объект результата расчёта, содержащий критическое
   сочетание, исходные и внутренние усилия, `epsilon0`, `kappaX`, `kappaY`,
   коэффициент использования или `lambda`, статус, итерации, бетонные волокна,
   арматуру, деформации, напряжения, силы и признаки растяжения/сжатия.

10. После расчёта наиболее неблагоприятное сочетание должно выгружаться на
    отдельный технический лист как снимок результата. Повторная визуализация и
    повторный экспорт в AutoCAD должны строиться по этому листу без повторного
    расчёта.

11. Геометрия может поступать из параметрического генератора или из готовой
    сетки областей AutoCAD. Оба источника должны формировать один внутренний
    формат бетонных волокон:

```text
ID
X
Y
Area
MaterialID
```

12. Импорт AutoCAD должен принимать уже подготовленные области `Region`.
    Excel не должен повторно строить сетку, выполнять `PointInPolygon` или
    анализировать внешний контур для режима импортированной сетки.

13. Перед каждым крупным этапом выполнять аудит затрагиваемой реализации,
    описывать найденное поведение, вносить минимальные изменения, запускать
    тесты и останавливаться при провале регрессии.

14. Каждый крупный этап завершать обновлением документации, перечнем изменённых
    файлов, результатами тестов, сравнением с исходным поведением и списком
    известных ограничений.

## Дополнительные проектные решения: нормативные параметры и тестовые нагрузки

1. Все нормативные коэффициенты и параметры материалов должны быть видимы пользователю на листе `System`.

2. Нормативные коэффициенты и параметры материалов не должны скрываться внутри VBA-кода.

3. Таблица параметров на листе `System` должна иметь структуру:

```text
Ключ | Значение | Значение по умолчанию | Единица | Назначение | Нормативный источник | Изменено пользователем
```

4. Для каждого коэффициента указывать:

* наименование или ключ;
* текущее значение;
* нормативное значение по умолчанию;
* единицу измерения;
* СП, пункт, таблицу или формулу;
* краткое назначение;
* допустимость изменения пользователем;
* признак изменения пользователем.

5. Пользователь может изменить текущее значение на листе `System`. Расчет должен использовать текущее значение, но диагностика должна показывать, что оно отличается от нормативного значения по умолчанию.

6. Измененное пользователем значение не считается новым нормативным значением по умолчанию.

7. Не перезаписывай пользовательское значение без явной команды пользователя.

8. Если нормативный коэффициент необходим для реализации или тестирования алгоритма, допускается выбрать любой обоснованный вариант, предусмотренный СП 35 или СП 63, при условии что указан источник и область применимости.

9. Если источник СП не подтвержден, оставляй `TODO`, а не подставляй число по памяти.

10. Тестовые нагрузки `N`, `Mx`, `My` могут назначаться произвольно и не обязаны быть взяты из справочных программ. Для каждого теста фиксировать нагрузки, единицы, ожидаемый результат или независимый способ проверки и критерий успешного прохождения.

11. Справочные программы круглого и произвольного сечения не являются обязательным источником нагрузок. Их можно использовать для дополнительных сравнительных тестов, когда это удобно.
