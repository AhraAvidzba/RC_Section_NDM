# Правила проекта

## Ветки и согласованная версия

- Основная ветка проекта — `main`; она хранит согласованную рабочую версию. Историческая `master` не используется как цель новых слияний.
- Для дальнейших изменений создавать отдельную ветку `codex/...` от актуальной `main`. После необходимых проверок и согласования результата пользователем сливать её в `main` и отправлять изменения на GitHub. Незавершённые изменения и чужие локальные файлы в согласованную версию не включать.

## Расчет и нормы

- Единственная постановка - `N + Mx + My`; одноосный изгиб задается нулем второго момента. Поддерживается ненапрягаемая арматура.
- Приоритеты: физическая корректность, равновесие, проверяемость, воспроизводимость, затем скорость. Численная несходимость не означает физическое разрушение.
- Формулы и коэффициенты брать из `norms/`, не по памяти. Неоднозначные трактовки фиксировать в `docs/OpenNormativeQuestions.md`; инженерное допущение не выдавать за требование СП.
- Нормативные параметры должны быть доступны на Config или в контрольных таблицах. Автотесты не означают окончательную нормативную верификацию.

## Данные и геометрия

- Ядро не обращается к Excel. Настройки читаются через `CSystemSettingsReader`, единицы и знаки преобразуются только через `CUnitSystem`.
- Внутри: мм, мм2, Н, Н*мм, МПа; положительное N - растяжение. Ввод по умолчанию: tf, tf*m, положительное N - сжатие.
- Поле деформаций: `epsilon = epsilon0 + kappaX*y + kappaY*x`. Пользовательская точка приложения отсчитывается от центра бетонной сетки без арматуры; перенос нагрузки описан в `docs/CoordinateSystem.md`.
- Генераторы и импорт заполняют один `CSectionModel`. Контуры и несколько отверстий классифицируются как Outer/Opening на уровне геометрии, передаются централизованно и обрабатываются одинаково.
- При пустом слое бетона AutoCAD сетка строится по достоверному Outer и всем Opening через общий `CGeometryRegion`/`CFiberMeshBuilder` с настройками Mesh. Непригодные или отфильтрованные объекты не равны пустому слою. Без сетки и Outer импорт запрещен; происхождение сетки сохраняется в Results.
- Новый параметрический тип описывается одним `ISectionRecipe` через `CSectionDefinitionBuilder` и регистрируется одной записью в `CSectionTypeRegistry`. Общий сборщик готовит бетон, арматуру, сетку и необязательные аннотации; в рецепте нет собственной расстановки стержней. Принадлежность точек и свойства бетона вычисляет общее ядро по контурам, без ветвей по типам в потребителях. При отсутствии отверстий возвращается пустой набор.
- Область трещин: только Opening - наружные границы сетки минус только заданные отверстия; только Outer - сплошной бетон внутри него; Outer и Opening - только заданные границы; ничего не задано - сетка со всеми ее пустотами. Это не меняет сетку НДС.
- Контуры сохраняются в `rngNDMSectionContours`, общие свойства элементов — в `rngNDMSectionGeometry`; область трещин — в аннотациях. Фактические границы связаны по ElementID в 18-колоночной матрице `rngNDMElementGeometry`: Excel выводит её полностью на Results перед аннотациями; File хранит полную матрицу в файле снимка, а на листе оставляет только шапку без подробных строк и остатков прежнего вывода. До расчёта File сохраняет сформированную геометрию как явный `GeometryPreview`: `Snapshot.Kind` размером 1×1, семь технических матриц и формат NDMSNP05, без результатов НДС, LC-сводок и расчётных профилей. Отсутствие расчётных таблиц само по себе не означает preview. Матрица границ обязательна для Contour независимо от носителя; проверка и успешное сохранение геометрии предшествуют очистке Results. Общие контуры не дублировать. Расчетные имена элементов создавать только в `CSectionModel`.
- Нижние таблицы Results идут слева направо: сетка бетона и арматуры, характеристики сечения, диаграммы материалов, достоверные контуры, результаты элементов по сочетаниям, фактические границы элементов, аннотации. В File справочно заполняются только первые четыре, а у остальных сохраняются шапки без подробных строк; в Excel заполняются все семь.
- Бетонный элемент представлен неизменяемым `CConcreteElement`; массивы решателя являются подготовленной числовой проекцией. `Mesh.CellGeometry=Adaptive` сохраняет прежнюю интерпретацию; `Contour` требует фактических прямых/дуг и не допускает восстановления эквивалентной оболочкой при потере границ. Чтение снимка проверяет этот контракт до изменения Results.
- Схема Excel и экспорт AutoCAD выбирают одно сочетание через Output.CombinationMode = Worst/User и Output.CombinationID. Worst берёт сохранённый выбор расчёта и не читает пользовательский ID; User читает точный ID без специального значения Worst. Выпадающие списки ID и профиля ссылаются прямо на исходные видимые таблицы, без скрытых копий.
- В режиме File весь снимок читается из файла с текущим именем Results.SnapshotName без обязательной предварительной загрузки: общие свойства и идентификаторы элементов, их фактические границы, исходные контуры, единицы, аннотации, рассчитанные состояния, сводки и сведения о выполненных проверках. Таблицы Results — справочный вывод: удаление или изменение их содержимого не меняет читаемый снимок и не блокирует расчёт по сохранённой геометрии. Отсутствующий/повреждённый файл не подменять листом. Выбор сочетания, состояния, величины, точности подписей и оформление продолжают читаться из Config; Worst относится к определяющему сочетанию сохранённого расчёта. В Excel источником являются только таблицы Results, независимо от прежней файловой привязки; смена режима не подгружает другой источник скрыто. Повторный расчёт читает текущие нагрузки и расчётные настройки Config, не генерирует и не импортирует геометрию заново. Пока источник сформированной геометрии не сохранён и не проверен, его единственную копию не очищать. Габариты по наружному контуру точные, по сетке — приблизительные.
- AutoCAD: 1 единица чертежа = 1 мм; импорт мм/мм2/мм4, экспорт геометрии всегда в мм независимо от INPUT/OUTPUT. Работать в WCS; импорт при неизвестной или локальной ПСК отклоняется.
- Отсутствие контурных слоев не блокирует импорт. Проверять фактическую замкнутость полилиний; временные объекты убирать, исходники не менять.
- `AutoCAD.Export.ContourFormat`: Region или Polyline. Экспорт добавляет объекты без поиска совпадений и очистки. Ручная очистка сохраняет бетон, арматуру, наружные контуры и отверстия, включая экспортированные копии.
- Импорт обрабатывает все объекты заданных слоев без приоритета исходников и экспортированных копий. За чистоту чертежа и отсутствие наложенных дублей отвечает пользователь.

## Поиск и трещины

- `LoadPath` сочетания - единая настройка несущей способности и трещинообразования: Auto, λ*Mx, λ*My, λ*Mxy, λ*N, λ*NMxy. Пустое значение равно Auto.
- Auto: единственная составляющая масштабируется сразу; при N + M пробуются M, затем N, затем NMxy. Найденный предел с λ < 1 не запускает следующий путь. Явный путь не менять; ошибки ввода не маскировать fallback.
- Момент от эксцентриситета N масштабируется вместе с N. Осевая траектория использует LoadMultiplier из-за вырожденности UltimateStrain на плато.
- Проверять предельные деформации сжатия и растяжения бетона и стали; растяжение бетона активно только при включенной растянутой ветви.
- Неудача трещинообразования не блокирует ширину и продольные трещины при пригодном текущем НДС. В СП 63 недоступное уточнение дает psi_s = 1 с предупреждением только при фактическом использовании коэффициента.
- NotCracked исключает только ширину нормальных трещин; продольные проверяются независимо. Пользовательский psi_s при этом не менять, предупреждение о psi_s = 1 не выводить. В СП 35 такого коэффициента нет.
- Группы СП 35 неделимы: включение в конечную область определяется по центру группы. Ряды нумеруются от бетонной границы к НЛ.
- Боковые границы СП 35: ближайшая арматурная группа отдельно слева/справа, t/L; t - расстояние проекций на НЛ, L - полное расстояние. Ниже порога сохраняется r, иначе min(r; t/2). RowTolerance разделяет ряды, но не меняет границы.
- Область трещин не должна менять прежние A/I и конвейер устойчивости.

## Производительность и оформление

- Сетку, арматуру и материалы готовить один раз на запуск. Горячие циклы - массивы, Excel-вывод - блочные присваивания.
- Целевое время одного сочетания - не более 10 с от штатного запуска до записи Results, включая подготовку, отчет и схему; замер только solver-а недостаточен.
- Кэш - только при точном совпадении всех значимых входов и ревизий; не округлять ключи, не переиспользовать изменяемые состояния. Результаты, диагностика и надежность неизменны.
- Ширина столбцов Results задается только при сборке. В данных и пояснениях перенос отключен; в верхних шапках сохраняется.
- Короткие постоянные списки Config и листа «Сечения» задавать непосредственно в проверке данных, без имён и скрытых копий для отдельных ячеек. Динамические списки сохранять компактно. Значения настроек противоположных сторон независимы. Таблицы обводить полностью, включая правую грань Справки.
- Пользовательские ячейки Config центрировать. В таблицах задания геометрии комментарии выравнивать справа внутри последнего столбца каждого блока, в остальных таблицах Config — слева; перенос строк отключён. Расположение именованных диапазонов, таблиц и объектов, ширины столбцов и высоты строк при полной сборке брать из tools/build_workbook/WorkbookLayout.json, снятого с последней утверждённой книги. Оформление входных листов применять только при сборке; расчёт и обновление схемы не меняют форматирование ячеек и размеры строк/столбцов вне Results. Сама схема обновляется штатно. Формулы оформлять с дробями и индексами, объяснять обозначения.
- Доступные для заполнения ячейки Config и листа «Сечения» выделять очень бледной оранжевой заливкой RGB(255,242,230), включая необязательные пользовательские комментарии и поля отключённых рядов арматуры. Заливка обозначает возможность ввода, а не обязательность заполнения. Вычисляемые поля этим цветом не выделять. Комментарии таблиц геометрии, армирования и профилей выравнивать справа внутри ячейки. Оформление таблиц сечений статическое, без условного форматирования. Количество у сторон отверстия HollowRectangle определяется проекцией и отображается прочерком. Каждый тип имеет одну именованную таблицу General/Main/Extra с собственным армированием на листе «Сечения», который идёт сразу после Config. Общей таблицы армирования нет; клиновидное сечение называется PointedSection.
- Справка описывает действия пользователя и расчетный смысл. Ссылка ведет к своей настройке, без повторения всего соседнего раздела.
- Скриншоты и картинки отправлять как доступные пользователю изображения или вложения. Локальные Markdown-вставки, изображения только в результатах инструментов и страницы Pages с визуализацией скриншота на телефоне пользователя не работают; эти способы больше не предлагать. Не утверждать, что изображение доставлено, без подтверждения его доступности пользователю.
- Ошибки и ResultComment: понятная причина и фактический адрес через именованный диапазон, без жестко заданных ячеек. Сохранять корректный Unicode.
- В диалоговых сообщениях отделять пустой строкой итог, причины, действия пользователя и технические сведения. Счётчики, адреса ввода и путь отчёта выводить отдельными строками. Не разбивать числа, единицы, пути и цитируемые значения; компактные пояснения ячеек Results не превращать в многострочные диалоги.
- Каждый класс, модуль и метод снабжать русской шапкой с назначением и существенными ограничениями. Внутри методов пояснять неочевидные переменные, формулы и решения в конце соответствующей строки. Отдельный комментарий над кодом допустим для общего инварианта нескольких операций, длинного инженерного вывода или ограничений продолжения строк VBA; причина должна быть понятна из содержания. Не пересказывать очевидные присваивания и не добавлять формальные заглушки.
- Имена классов и методов, используемых только для тестов, должны содержать Test. В шапке класса/модуля писать ДЛЯ ТЕСТОВ между принятыми разделителями; перед пояснением тестового метода использовать `' -------------------- ДЛЯ ТЕСТОВ --------------------`. Исключение — обязательные имена событий VBA, реализаций рабочих интерфейсов и имитаций внешнего COM API; такие методы сохраняют контрактное имя в явно тестовом классе. Рабочие методы не помечать тестовыми только потому, что они также проверяются тестами.

## Проверки и защита данных

- Готовая книга по определению имеет актуальную структуру. Завершённые одноразовые миграции не хранятся в рабочем VBA; новые возможности добавляются точечно, без перестройки существующих данных. Обновление новых типов меняет только список Geometry.Type из реестра.

- Объем тестов выбирать по риску. После мелких правок не запускать полный набор; документация не требует расчетных тестов и пересборки.
- Самые долгие полные on/off и Excel UI прогоны - только с отдельного явного согласия пользователя в чате, с указанием состава и длительности.
- Перед новыми процессами при полных прогонах проверять свободную физическую память и запас до общего лимита выделяемой памяти (commit limit). При угрозе исчерпания памяти не запускать новые параллельные процессы; подтверждённо ненужные собственные процессы закрывать после сохранения доказательств и сверки PID с временем запуска. Пользовательские Excel/AutoCAD не закрывать. Независимые проверки допускается выполнять параллельно только при достаточной свободной RAM и запасе commit с резервом для Codex и суммарных пиков всех активных проверок. Перед каждым новым процессом проверять этот общий запас; при его недостатке выполнять проверки последовательно.
- По указанию пользователя от 23.10.2026 наблюдение полного прогона включать при фактическом запуске авторизованного полного набора и самостоятельно отключать после проверки общего PASS всех обязательных этапов и сохранения итогового отчёта. В текущем чате использовать существующее наблюдение `ndm`, без дубликатов: ACTIVE при запуске, PAUSED после успешной полной приёмки. При ошибках сохранять его активным на время разбора и исправлений; направленные повторы не заменяют успешный полный прогон и не дают разрешения на новый долгий набор. Прежнее требование постоянно оставлять наблюдение активным отменено.
- Под «полными прогонами» понимать все действующие наборы приёмки: основные расчётные и интерфейсные ON/OFF, геометрию, СП35, рецепты и обязательный часовой план `docs/FocusedValidationPlan.md`. Последний включает 122 одиночных случая, batch из 15 сочетаний, устойчивость, асимметричную сталь, настоящий AutoCAD и независимый контроль. Пропущенный или незавершённый этап исключает общий PASS; число assertions не заменяет полноту сочетаний.
- Если проверка не прошла, выяснить причину и исправить рабочий код или ошибочные тестовые данные в рамках той же задачи, затем повторить затронутые проверки. Не завершать задачу только отчётом о найденных сбоях; ожидания не ослаблять ради PASS.
- Проверять затронутые пути, статусы, ResultComment, единицы и знаки. Baseline менять только с инженерным объяснением.
- После изменений, попадающих в книгу, проверить output-файл: код, настройки, списки, рамки, заголовки и актуальность `VBA_All_Code.txt`. Сохранять пользовательские данные.
- Любое изменение книги — VBA, настройки, подписи, списки, оформление или структура — сразу отражать в соответствующих исходниках и данных сборки, чтобы следующая полная пересборка воспроизводила актуальный результат. Одной правки готового файла недостаточно; синхронизацию сборки не откладывать на следующую задачу. Для изменений раскладки актуализировать `tools/build_workbook/WorkbookLayout.json`, для остальных изменений — соответствующий каталог, шаблон или исходный компонент.
- Не изменять `norms/`, `reference/`, `control_examples/` и не откатывать чужие правки.
- Не завершать все процессы Excel/AutoCAD; закрывать только собственный проверенный PID.
- После завершения задачи и создания локального коммита выполнять push в соответствующую удалённую ветку, если пользователь явно не указал иное. Подтверждать отправку только после успешного push.
- Команды: `docs/ValidationPlan.md`. Отчеты: `docs/reports/`. Доказательства: `docs/regression/`.
