# AGENTS.md - правила проекта RC Section NDM VBA

## Назначение

Проект - инженерная Excel VBA-программа для расчета железобетонных поперечных сечений по нелинейной деформационной модели.

Текущая расчетная постановка только одна:

```text
N + Mx + My
```

Отдельные пользовательские и расчетные ветви `Mx`, `My` и `Mxy` не развиваются. Одноосный изгиб проверяется как частный случай общей постановки:

```text
N + Mx при My = 0
N + My при Mx = 0
```

## Приоритеты

1. Физическая корректность и равновесие.
2. Проверяемость расчетов.
3. Прозрачность настроек на листе `System`.
4. Воспроизводимая сборка книги.
5. Производительность без потери диагностируемости.
6. Нормативная трассировка по СП 35 и СП 63.

## Нормативные правила

- Нормативные значения, формулы и коэффициенты нельзя придумывать по памяти.
- Основные источники: локальные файлы в `norms/`.
- Если формула или значение прочитаны неоднозначно, вопрос заносится в `docs/OpenNormativeQuestions.md`.
- До закрытия нормативной трассировки результаты считать расчетным прототипом, а не окончательно верифицированным расчетом по СП.
- Методика НДМ принимается по СП 63, а специальные параметры мостовых конструкций - по СП 35 там, где это подтверждено.
- Все нормативно зависимые параметры должны быть видимы на листе `System` или в таблицах точек диаграмм.

## Границы проекта

Поддерживается:

- обычная ненапрягаемая продольная арматура;
- круглая геометрия `Circle`;
- прямоугольное сечение со скруглениями `RoundedRectangle`;
- Г-образная геометрия `LShape`;
- автоматическая расстановка арматуры для круглого и Г-образного сечения;
- пользовательские кусочно-линейные диаграммы бетона и арматуры по точкам;
- прямой расчет НДС;
- поиск несущей способности;
- расчет ширины раскрытия уже образовавшихся нормальных трещин;
- пакет до 20 сочетаний;
- экспорт геометрии и напряжений в AutoCAD;
- импорт расчетной сетки из AutoCAD `Region` на заданных слоях.

Не поддерживается:

- напрягаемая арматура;
- ручной ввод координат арматуры на листе `Расчет`;
- отдельные режимы `SolveMx`, `SolveMy`, `SolveMxy`;
- образование трещин и `Mcrc`;
- окончательная нормативная верификация без ручной проверки источников.

## Единицы И Знаки

Пользовательские единицы и пользовательская система знаков задаются на листе `System` в отдельных именованных диапазонах:

- `rngUnitSettings`;
- `rngSignConventionSettings`.

Внешние значения из Excel и AutoCAD должны проходить через централизованный адаптер `CUnitSystem` до попадания в расчетное ядро. Результаты перед выводом на листы `Расчет` и `Results` и перед AutoCAD export должны преобразовываться обратно в выбранные пользователем выходные единицы и знаки.

Внутренние единицы:

```text
длина      мм
площадь    мм2
сила       Н
момент     Н*мм
напряжение МПа = Н/мм2
деформация безразмерная
кривизна   1/мм
```

Настройки по умолчанию для пользовательского ввода нагрузок:

```text
Force input  = tf
Moment input = tf*m
+N user      = Compression
```

Это не меняет внутреннюю математику: внутри ядра сжатие по-прежнему имеет отрицательный знак.

Поле деформаций:

```text
epsilon(x, y) = epsilon0 + kappaX * y + kappaY * x
```

Подробности зафиксированы в `docs/CoordinateSystem.md`.

## Архитектура

- Расчетное ядро не обращается к Excel-листам напрямую.
- Excel-слой один раз читает `System` через `CSystemSettingsReader` и передает настройки в геометрию, материалы, решатели и writer-ы.
- `CUnitSystem` является единственным местом пересчета пользовательских единиц и знаков во внутренние и обратно.
- `CLoadCombinationReader`, геометрические builders, материалы, solver settings и writer-ы должны работать через `CUnitSystem`; `CLoadCase` и расчетные классы получают уже нормализованные данные.
- `CNDMResultsWriter` после расчета выводит согласованный snapshot на лист `Results` блочной записью массивов: `rngNDMSectionGeometry`, `rngNDMElementResults`, `rngNDMSectionProperties`, `rngNDMSectionAnnotations`.
- AutoCAD export читает последний расчетный снимок с листа `Results`; модель сечения не хранится в памяти между макросами и не импортируется повторно из AutoCAD при экспорте.
- Excel-схема сечения строится только по сохраненному snapshot `Results`; кнопка обновления схемы не запускает решатель, не читает текущие исходные данные геометрии и не меняет `Results`.
- Горячие циклы используют массивы, а не `Range`, `Cells`, `WorksheetFunction.MInverse` или объекты на каждое волокно.
- Геометрия встроенных генераторов реализуется через `ISectionGeometry`.
- Расчетное ядро получает геометрию только через `CSectionModel`; решатели не должны принимать `CFiberMeshBuilder` или `CRebarLayout` напрямую.
- Встроенные генераторы и AutoCAD-импортер заполняют один и тот же `CSectionModel`.
- Расчетные имена элементов (`C1`, `C2`, `R1`, `R2` и т.п.) создаются только в `CSectionModel`; исходные имена генераторов или AutoCAD handles хранятся только как трассировочные поля.
- Материалы передаются как объекты с методами `GetStress`, `GetTangentModulus`, `GetSecantModulus`.
- Сетка, арматура и материалы создаются один раз на расчетный запуск и переиспользуются для всех сочетаний.

## Книга Excel

Листы:

- `Расчет` - таблица сочетаний, единый блок результатов, кнопки запуска/очистки/AutoCAD;
- `System` - все входные настройки и точки диаграмм. Контрольная таблица арматуры и формульный блок трещин на `System` не выводятся.
- `Results` - расчетный снимок последнего запуска: batch summary, расчетная геометрия, LC-зависимые результаты элементов, свойства сечения и semantic-аннотации для AutoCAD export и Excel-схемы.

Именованные диапазоны:

- `rngSystemSettings`;
- `rngUnitSettings`;
- `rngSignConventionSettings`;
- `rngCircleGeometry`;
- `rngRoundedRectangleGeometry`;
- `rngLShapeGeometry`;
- `rngConcreteDiagramPoints`;
- `rngSteelDiagramPoints`;

## Г-Образное Сечение

`rngLShapeGeometry` задается отдельной таблицей по граням `H1`, `B1`, `H2`, `B2`.

Смысл размеров:

- `H1` - высота верхнего прямоугольника;
- `B1` - ширина верхнего прямоугольника;
- `H2` - высота нижнего прямоугольника;
- `B2` - ширина нижнего прямоугольника;
- полная высота сечения равна `H1 + H2`.

Для строк арматуры используется единое обозначение граней `_1` и `_2`. Грань `_1` (`as_1`, `d_1`, `n_1`, `t1_1`, `t2_1`) означает левую грань для `H*` или верхнюю грань для `B*`. Грань `_2` (`as_2`, `d_2`, `n_2`, `t1_2`, `t2_2`) означает правую грань для `H*` или нижнюю грань для `B*`.

Нумерация граней идет слева направо для вертикальных граней `H*` и сверху вниз для горизонтальных граней `B*`.

Для каждой грани задаются две линии арматуры:

- `as_1`, `d_1`, `n_1` - грань `_1`;
- `as_2`, `d_2`, `n_2` - грань `_2`;
- `t1_1` - отступ первого стержня от начала линии `_1` при обходе по часовой стрелке;
- `t2_1` - отступ последнего стержня от конца линии `_1` при обходе по часовой стрелке;
- `t1_2` - отступ первого стержня от начала линии `_2` при обходе по часовой стрелке;
- `t2_2` - отступ последнего стержня от конца линии `_2` при обходе по часовой стрелке.

Для вертикальных граней `H1/H2` параметры `as_1/as_2` соответствуют левой и правой стороне. Для горизонтальных граней `B1/B2` параметры `as_1/as_2` соответствуют верхней и нижней стороне.

Если `n_1 = 0` или `n_2 = 0`, соответствующая линия пропускается без ошибки. Для активной линии шаг стержней:

```text
step_1 = (Lлинии - t1_1 - t2_1) / (n_1 - 1)
step_2 = (Lлинии - t1_2 - t2_2) / (n_2 - 1)
```

## Круглое Сечение

`rngCircleGeometry` задает `Circle.Diameter`, первый ряд арматуры `Rebar.AxisDistance`, `Rebar.Count`, `Rebar.Diameter` и опциональные дополнительные ряды `Rebar.Diameter2`, `Rebar.Diameter3`, `Rebar.Loc2row`, `Rebar.Loc3row`.

Пустой или нулевой диаметр дополнительного ряда означает, что ряд не создается. `Stacked` ставит дополнительный стержень внутрь сечения по радиусу к центру. `SideBySide` ставит дополнительный стержень справа по часовой касательной относительно стержня первого ряда. Третий ряд строится относительно первого ряда; если `Rebar.Loc3row` совпадает с `Rebar.Loc2row` и второй ряд есть, третий ряд перескакивает второй.

Дополнительные ряды арматуры для Г-сечения задаются строками `d_2row_1`, `d_2row_2`, `d_3row_1`, `d_3row_2`, `loc_2row`, `loc_3row`. Суффикс `_1` означает левую грань для `H*` или верхнюю грань для `B*`; суффикс `_2` означает правую грань для `H*` или нижнюю грань для `B*`. Пустой или нулевой диаметр означает отсутствие соответствующего дополнительного ряда. Если первого ряда на этой грани нет, второй и третий ряды этой грани не создаются. Третий ряд ставится относительно первого ряда; если `loc_3row` совпадает с `loc_2row` и второй ряд есть, третий ряд перескакивает второй. Значение `Stacked` ставит дополнительный стержень внутрь сечения, `SideBySide` ставит его вниз для вертикальных граней `H1/H2` и вправо для горизонтальных граней `B1/B2`.

## Расчетное Ядро

- `CSectionSolver` решает систему равновесия `N`, `Mx`, `My`.
- `Solver.Method = Newton` использует касательную матрицу, демпфирование, line search и ограничения приращений.
- `Solver.Method = Secant` использует самостоятельную секущую схему с контролируемыми рестартами.
- `CCapacitySolver.SolveByLoadMultiplier` сохраняет `N = const` и масштабирует `Mx/My` через `lambda`.
- `CCapacitySolver.SolveByUltimateStrain` ищет состояние по равновесию `N`, сохранению направления `Mx/My` и достижению предельной деформации.
- Для `LoadMultiplier` доступны `Bisection`, `Brent`, `Secant`.
- Численная несходимость не является физическим разрушением.

## Трещины

Расчет ширины раскрытия выполняется только для уже образовавшихся нормальных трещин.

Не рассчитываются:

- момент образования трещин;
- условие появления трещины;
- `Mcrc`.

В режиме трещин растянутый бетон во внутренних усилиях игнорируется, если `Concrete.TensionMode = Ignore`.

## Производительность

- Не читать и не писать ячейки построчно в расчетных writer-ах.
- Для вывода использовать массивы и блочные присваивания диапазонам.
- При зависшем Excel сразу предлагать пользователю:

```powershell
Get-Process EXCEL -ErrorAction SilentlyContinue | Stop-Process -Force
```

## Тестирование

Перед завершением значимой задачи запускать:

```powershell
powershell -ExecutionPolicy Bypass -File tools/build_workbook/Validate-Workbook.ps1
powershell -ExecutionPolicy Bypass -File tools/build_workbook/Run-AllTests.ps1
```

Если задача затрагивает только документацию, достаточно проверить отсутствие устаревших ссылок и явно указать, что расчетные тесты не требовались.
