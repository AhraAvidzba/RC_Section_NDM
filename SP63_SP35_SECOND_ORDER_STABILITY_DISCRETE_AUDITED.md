# Учёт продольного изгиба и проверка устойчивости железобетонного стержня по СП 63 и СП 35

**Назначение документа:** зафиксировать расчётную последовательность и исходные данные для двух нормативных алгоритмов — сначала по СП 63.13330.2018, затем по СП 35.13330.2011 — применительно к произвольному железобетонному сечению с ненапрягаемой арматурой.

**Уровень детализации:** нормативная методика, согласованные исходные данные, структура листа `Config`, результаты `rngBatchSummary` и поверхностная интеграция в существующий расчётный pipeline.

**Правило обозначений:** каждый нестандартный символ должен быть расшифрован при первом применении и дополнительно присутствовать в сводном словаре раздела 1.6.

**Ключевой архитектурный принцип:** добавляется только один новый класс `CStabilityCalculator`. Он работает как изолированный фильтр нагрузки: получает подготовленные входные данные и дискретную модель сечения в памяти, выполняет выбранную нормативную ветвь и возвращает исходные либо скорректированные `N/Mx/My` вместе с расчётными диагностическими величинами. Класс не запускает НДМ, не меняет материалы, не читает и не записывает листы.

**Редакции норм, использованные при подготовке:**

- СП 63.13330.2018 «Бетонные и железобетонные конструкции. Основные положения» с действующими Изменениями № 1 и № 2;
- СП 35.13330.2011 «Мосты и трубы» с действующими Изменениями № 1–5.

> **Важно.** СП 63 не распространяется непосредственно на мосты. Для мостовых сооружений основной норматив — СП 35. При этом СП 35 в ряде случаев для косого внецентренного сжатия, непрямоугольных сечений и произвольного распределения арматуры допускает/предписывает использовать общие положения НДМ по СП 63 с характеристиками материалов, принимаемыми по СП 35. Поэтому ниже методики рассматриваются отдельно, а места, где применение к произвольному Г-образному или иному несимметричному сечению является программным/инженерным обобщением, помечены явно.

# 1. Исходные данные и принятые обозначения

## 1.1. Полные и длительно действующие нагрузки

Для каждого расчётного сочетания из основной таблицы сочетаний известны полные усилия:

$$N,\;M_x,\;M_y.$$

Дополнительные нагрузки для коэффициентов длительного действия пользователь задаёт в отдельном именованном диапазоне:

```text
rngStabilityDurationLoads = Config!P27:S47
```

Размер диапазона строго фиксирован:

```text
4 столбца × 20 строк
```

Заголовки располагаются над диапазоном, например в `P26:S26`, и в сам именованный диапазон не входят:

| Столбец | Содержание |
|---|---|
| 1 | `LC` — номер сочетания, совпадающий с номером в основной таблице |
| 2 | `N` |
| 3 | `Mx` |
| 4 | `My` |

Поиск дополнительной нагрузки выполняется **по номеру `LC`**, а не только по номеру строки.

Смысл трёх усилий зависит от выбранного норматива:

- при `Stability.Code = SP63` пользователь вводит **сумму постоянных и длительных нагрузок**:
  $$N_{G+L},\;M_{x,G+L},\;M_{y,G+L};$$
- при `Stability.Code = SP35` пользователь вводит **только постоянные нагрузки**:
  $$N_G,\;M_{x,G},\;M_{y,G}.$$

Это различие находится на ответственности пользователя и должно быть явно описано на листе `Справка`.

Нулевая строка нагрузок является допустимой:

$$N_{ref}=0,\;M_{x,ref}=0,\;M_{y,ref}=0.$$

Она не считается ошибкой сама по себе. Отдельная обработка требуется только в формулах, где возникает деление на величину, близкую к нулю.

### Точка приведения нагрузки

В основной таблице сочетаний точка `0,0` соответствует центру тяжести **бетонного** сечения.

Пользователь может задать смещение точки приложения/приведения:

```text
Load.ReferenceOffsetX
Load.ReferenceOffsetY
```

Полный и дополнительный векторы нагрузок должны быть приведены **одинаковым существующим механизмом** к центру тяжести приведённого сечения до передачи в `CStabilityCalculator`.

Общая запись переноса:

$$M_{new}=M_{old}+r_{tr}\times N.$$

Знаки компонентов переноса должны полностью соответствовать уже реализованному в проекте helper-у `ApplyLoadReference`; отдельная независимая формула знаков внутри класса устойчивости не допускается.

Класс получает:

- исходные значения для вывода;
- полный вектор, перенесённый из пользовательской точки к центру тяжести приведённого сечения;
- дополнительный вектор, перенесённый к тому же центру тяжести приведённого сечения.

Он не должен применять смещение второй раз.

Все усилия должны иметь:

- одну систему координат;
- одну систему знаков;
- одинаковые единицы;
- один нормативный уровень коэффициентов надёжности.

Внутри алгоритма удобно использовать положительную скалярную величину сжатия:

$$N_c=|N|.$$

## 1.2. Длина и коэффициенты расчётной длины

Пользователь задаёт:

- $L$ — **геометрическую свободную длину элемента** (или длину рассматриваемого участка между закреплениями);
- $\mu_1$ — коэффициент расчётной длины для первой главной центральной плоскости сечения;
- $\mu_2$ — коэффициент расчётной длины для второй главной центральной плоскости сечения.

Главные центральные оси `1/2` для устойчивости определяются программой автоматически по приведённому сечению бетон + арматура. Пользователь не задаёт их угол вручную и не обязан знать их ориентацию относительно исходных осей $X/Y$.

Расчётные длины:

$$l_{0,1}=\mu_1L,\; l_{0,2}=\mu_2L.$$

Коэффициенты $\mu_1,\mu_2$ считаются уже определёнными пользователем **именно для главных центральных плоскостей приведённого сечения**. То есть задача приведения реальных условий закрепления к двум расчётным длинам считается решённой до запуска расчёта.

Это сознательное упрощение постановки: программа не моделирует реальные пространственные закрепления стержня и не решает связанную пространственную задачу buckling. Вместо этого используются две независимые нормативные плоские проверки по главным центральным направлениям.

> В СП коэффициент $\mu$ не является универсальным самостоятельным параметром. Это удобная программная форма передачи пользователем уже определённой по расчётной схеме эффективной длины. СП 63, п. 8.1.17, приводит типовые расчётные длины для разных закреплений; для СП 35 расчётная длина также определяется расчётной схемой. Поэтому ответственность за корректный выбор $\mu_1,\mu_2$ остаётся на пользователе.

## 1.3. Материалы, арматура и форма представления сечения

Предполагается:

- вся арматура ненапрягаемая;
- сцепление арматуры с бетоном обеспечено;
- известны $E_b$, $E_s$, $R_b$, $R_{sc}$ и другие характеристики, необходимые выбранному нормативному расчёту;
- расчётный модуль устойчивости **не знает семантики целого сечения**: он не должен различать `Rectangle`, `Circle`, `LShape`, `AutoCADSection` и т. п.;
- единственным источником геометрии для него является нормализованная дискретная модель бетона и арматуры в памяти.

Геометрия может быть получена двумя равноправными путями:

```text
автоматический генератор сечения ─┐
                                  ├─> единая дискретная модель -> расчёт
импорт геометрии из AutoCAD ──────┘
```

После построения дискретной модели происхождение геометрии не должно влиять на алгоритм устойчивости.

Для СП 35 влияние предварительного напряжения в формулах продольного изгиба отсутствует, поэтому для рассматриваемой ненапрягаемой арматуры:

$$\varphi_p=1.$$

## 1.4. Тип системы и направление случайного эксцентриситета

Для правила учёта случайного эксцентриситета требуется:

```text
Stability.SystemType = Determinate / Indeterminate
```

Для главных плоскостей `1/2` пользователь дополнительно задаёт:

```text
Stability.ZeroMomentEccentricitySign1 = +1 / -1
Stability.ZeroMomentEccentricitySign2 = +1 / -1
```

Эти настройки используются **только когда соответствующий преобразованный момент практически равен нулю**.

Для плоскости $j$:

$$s_j\in\{-1,+1\}.$$

Правило выбора:

- если $|M_j|>M_{tol}$:
  $$s_j=sign(M_j);$$
- если $|M_j|\le M_{tol}$:
  $$s_1=Stability.ZeroMomentEccentricitySign1,$$
  $$s_2=Stability.ZeroMomentEccentricitySign2.$$

Тем самым направление случайного эксцентриситета при нулевом моменте задаётся пользователем заранее, и программа не выполняет дополнительные НДМ-расчёты по противоположным знакам.

`M_tol` является внутренним численным допуском программы и не должен становиться отдельным инженерным параметром на листе без необходимости.

## 1.5. Расчётные плоскости для произвольного дискретного сечения

Главные центральные оси `1/2` определяются численно по приведённой дискретной модели бетон + арматура. Пользователь задаёт $\mu_1,\mu_2$ уже для этих двух плоскостей.

Для СП 63:

- оси `1/2` проходят через центр тяжести приведённого сечения;
- $I_{b,1},I_{b,2}$ считаются для бетона;
- $I_{s,1},I_{s,2}$ считаются для всей продольной арматуры относительно тех же осей через центр приведённого сечения.

Для СП 35 формулы п. 7.54 также требуют $I_b$ и $I_s$ относительно осей, проходящих через центр тяжести приведённого сечения. Поэтому обе нормативные ветви используют одну и ту же базу эксцентриситета и осей устойчивости.

Пусть угол между пользовательскими осями $X/Y$ и главными осями приведённого сечения `1/2` равен $\alpha$:

$$[M_1,M_2]^T=R(\alpha)[M_x,M_y]^T.$$

Для дополнительной таблицы нагрузок выполняется то же преобразование:

$$[M_{1,ref},M_{2,ref}]^T=R(\alpha)[M_{x,ref},M_{y,ref}]^T.$$

После расчёта:

$$[M_{x,d},M_{y,d}]^T=R^T(\alpha)[M_{1,d},M_{2,d}]^T.$$

Расчётные длины:

$$l_{0,1}=\mu_1L,\;l_{0,2}=\mu_2L.$$

Класс не распознаёт тип целого сечения и не вводит отдельные статусы применимости для Г-образных, импортированных или иных произвольных сечений. Он применяет выбранный пользователем алгоритм к переданной дискретной модели и использует материалы, уже выбранные текущим расчётным профилем.

Ограничения нормативной области применения и ответственность за выбор `SP63/SP35` должны быть подробно изложены в справке, но не должны порождать отдельный пользовательский статус.

## 1.6. Полный словарь обозначений

Ниже собраны все обозначения, используемые далее. Внутри конкретного раздела более узкое определение имеет приоритет.

Если одна и та же величина записана без индекса $j$, это означает одноосную нормативную запись для текущей рассматриваемой плоскости.

### Индексы, оси и операции

| Обозначение | Значение |
|---|---|
| $X,Y$ | исходные пользовательские оси, относительно которых заданы $M_x,M_y$ |
| $1,2$ | главные центральные оси приведённой дискретной модели бетон + арматура |
| $j$ | индекс рассматриваемой главной плоскости, $j=1,2$ |
| $k$ | индекс бетонного дискретного элемента |
| $m$ | индекс дискретного элемента/стержня арматуры |
| $\alpha$ | угол поворота главных осей `1/2` относительно $X/Y$ |
| $R(\alpha)$ | матрица поворота компонентов момента из $X/Y$ в `1/2` |
| $sign(x)$ | знаковая функция: $+1$ при $x>0$, $-1$ при $x<0$ |
| $M_{tol}$ | малый численный допуск, ниже которого момент считается практически нулевым |
| $s_j$ | знаковый множитель случайного эксцентриситета; при ненулевом $M_j$ равен $sign(M_j)$, при нулевом берётся из `Stability.ZeroMomentEccentricitySign1/2` |

### Усилия, длины и эксцентриситеты

| Обозначение | Значение |
|---|---|
| $N$ | исходная продольная сила сочетания в принятой системе знаков |
| $N_c=|N|$ | положительная скалярная величина сжатия |
| $N_G$ | значение дополнительной продольной силы при расчёте по СП 35: только постоянная нагрузка |
| $N_{G+L}$ | значение дополнительной продольной силы при расчёте по СП 63: постоянная + длительная нагрузка |
| $M_x,M_y$ | исходные моменты в пользовательских осях |
| $M_1,M_2$ | компоненты исходного момента в главных осях `1/2` |
| $M_{x,G},M_{y,G}$ | постоянные составляющие моментов |
| $M_{1,G},M_{2,G}$ | постоянные моменты после перехода в главные оси |
| $L$ | геометрическая свободная длина элемента/участка между закреплениями |
| $\mu_1,\mu_2$ | пользовательские коэффициенты расчётной длины для главных плоскостей `1/2` |
| $l_{0,j}=\mu_jL$ | расчётная длина в плоскости $j$ |
| $e_{stat,j}$ | эксцентриситет из статического расчёта в плоскости $j$ |
| $e_{a,j}$ | случайный эксцентриситет |
| $e_{0,j}$ | начальный эксцентриситет СП 63 после учёта $e_a$ |
| $e_c$ | расчётный эксцентриситет СП 35 |
| $e_{c,sl}$ | случайный эксцентриситет СП 35 |
| $e_{d,j}$ | эксцентриситет после увеличения коэффициентом $\eta_j$ |
| $M_{d,j}$ | расчётный момент второго порядка в плоскости $j$ |
| $M_{x,d},M_{y,d}$ | расчётные моменты после обратного перехода в $X/Y$ |
| $N_d$ | расчётная продольная сила после блока второго порядка; в принятой схеме $N_d=N$ |
| $M_{old},M_{new}$ | момент до и после переноса к другой точке приведения |
| $M_{0,j}$ | момент до умножения на $\eta_j$, соответствующий уже учтённому начальному/случайному эксцентриситету |

### Настройки, профили и диапазоны

| `MaterialModel.Stability.ValueSet` | строка `ULS(I)/SLS(II)` в `rngCalculationProfiles`; выбирает только набор характеристик материала для устойчивости, без диаграмм |

## 1.7. Требования к дискретной геометрии и импорту AutoCAD

Расчёт устойчивости должен работать **только с нормализованной дискретной моделью** и не ветвиться по источнику геометрии.

Минимальный контракт бетонного элемента:

```text
ConcreteElement:
    Area
    CentroidX
    CentroidY
    LocalIx
    LocalIy
    LocalIxy
    Boundary/Vertices OR equivalent local extents
```

Минимальный контракт арматурного элемента:

```text
RebarElement:
    Area
    CentroidX
    CentroidY
    LocalI      # желательно; может быть вычислен из диаметра круглого стержня
```

### Центр тяжести и глобальный тензор инерции

$$A_b=\sum_k A_k,$$

$$x_b=\frac{\sum_kA_kx_k}{A_b},\; y_b=\frac{\sum_kA_ky_k}{A_b}.$$

$$I_x=\sum_k[I_{x,k}^{local}+A_k(y_k-y_b)^2],$$

$$I_y=\sum_k[I_{y,k}^{local}+A_k(x_k-x_b)^2],$$

$$I_{xy}=\sum_k[I_{xy,k}^{local}+A_k(x_k-x_b)(y_k-y_b)].$$

Знак $I_{xy}$ должен соответствовать одной принятой в проекте конвенции. Угол главных осей должен вычисляться одним общим helper-ом и проверяться round-trip тестами преобразования координат/моментов.

### Локальные моменты инерции бетонных элементов

Если бетонная сетка достаточно грубая, использование только $A_kd_k^2$ и игнорирование $I_k^{local}$ заметно занижает $I_b$.

Поэтому предпочтительный вариант:

- автоматический генератор сразу сохраняет точные `LocalIx/LocalIy/LocalIxy` каждой ячейки;
- **при импорте сетки из AutoCAD предпочтительно, чтобы локальные моменты инерции каждого бетонного элемента уже приходили из AutoCAD вместе с импортируемой областью/ячейкой**, если текущий механизм импорта позволяет получить эти характеристики непосредственно из исходной `Region`;
- только если AutoCAD-ветка фактически не передаёт локальные инерции, importer/mesher должен вычислить их один раз из исходной области/полигона до формирования общей дискретной модели;
- stability-класс только читает готовые локальные характеристики и **не должен самостоятельно повторно вычислять геометрию импортированной области**.

> **Подсказка для реализации:** перед добавлением нового вычисления локальных инерций сначала проверить существующий AutoCAD importer и структуру импортируемых `Region`: возможно, площадь, центр тяжести и моменты инерции уже доступны непосредственно при импорте. Предпочтительно расширить существующий контракт импортируемого элемента и сохранить эти значения в `CSectionModel`, а не создавать отдельный расчёт геометрии специально для устойчивости.

Если импортированный элемент содержит **только площадь и центр**, допустим режим `PointFiberApproximation`, в котором $I_k^{local}=0$, но результат должен сопровождаться предупреждением. Такое упрощение уменьшает $I_b$, однако его нельзя объявлять универсально консервативным для всего алгоритма, потому что одновременно могут искажаться главные оси и геометрический размер $h$.

### Определение h без знания типа сечения

Для расчёта $h_j$ семантика `Rectangle/LShape/...` не нужна. В идеальном случае используются геометрические границы дискретных бетонных элементов.

Все вершины/граничные точки проецируются на нормаль к оси $j$:

$$h_j=u_{max,j}-u_{min,j}.$$

Однако при импорте сетки из AutoCAD, вероятно, после преобразования областей в дискретные элементы в общей модели могут сохраняться только площадь и центр тяжести элемента без полного набора его граничных точек.

В таком случае **не следует использовать только диапазон центров ячеек**. Для каждого бетонного элемента можно применять тот же геометрический подход, который уже используется в существующем классе расчёта трещин для определения эффективной границы элемента:

1. по площади элемента $A_k$ определить радиус эквивалентного круга

$$a_k=\sqrt{\frac{A_k}{\pi}},$$

2. центр элемента проецировать на рассматриваемое направление;
3. к проекции центра добавлять и вычитать $a_k$;
4. по всем бетонным элементам определить крайние значения:

$$u_{max,j}=\max_k(u_{k,j}+a_k),$$

$$u_{min,j}=\min_k(u_{k,j}-a_k),$$

5. принять:

$$h_j=u_{max,j}-u_{min,j}.$$

Такой способ не восстанавливает точный исходный контур каждой AutoCAD-области, но учитывает конечный размер дискретного элемента и значительно корректнее диапазона одних центров.

> **Реализация в текущем коде:** проекции бетонных элементов, высоты по повернутым осям и ядровые расстояния сосредоточены в `CSectionPropertiesCalculator`. Расчет устойчивости использует эти методы и не дублирует восстановление внешних границ дискретных элементов.

При наличии реальных границ импортированного элемента они имеют приоритет над эквивалентным кругом. Рекомендуемая иерархия:

```text
Actual element boundary
    -> Equivalent circle from Area
        -> InputErr, если отсутствуют и границы, и корректная площадь
```

Следует явно понимать, что аппроксимация эквивалентным кругом является **дискретным геометрическим приближением**, а не формулой СП 63/СП 35. Поэтому используемый режим геометрии желательно сохранять в диагностике результата, например `BoundaryMode = Actual / EquivalentCircle`.

### Локальная инерция арматуры

Для круглого стержня при известном диаметре $d_s$:

$$I_s^{local}=\frac{\pi d_s^4}{64}.$$

Если арматурный элемент представлен только площадью и центром, собственную инерцию допускается не учитывать:

$$I_s^{local}=0.$$

Для обычной стержневой арматуры это малая поправка относительно $A_sd^2$ и уменьшает $I_s$, то есть действует в безопасную сторону для $D$ и $N_{cr}$. Выбранный режим должен быть виден в диагностике.

### Приведённые характеристики СП 35

$A_{red}$, центр приведённого сечения и $I_{red}$ также вычисляются **суммированием дискретных элементов**, а не по формулам конкретного типа сечения.

Необходимо один раз зафиксировать конвенцию бетонной сетки:

- если бетонная площадь включает места расположения арматуры как часть gross-сечения, коэффициент приведения арматуры должен учитывать отсутствие двойного счёта площади;
- если бетонная сетка уже исключает площадь стали, используется другая эквивалентная сумма.

Это свойство должно быть частью общего геометрического/материального слоя проекта, а не отдельной пользовательской настройкой расчёта устойчивости.

### Что stability-класс не должен делать

Он не должен:

- распознавать тип сечения;
- заново читать AutoCAD;
- заново генерировать бетонную сетку;
- вычислять специальные формулы площади/инерции для круга, прямоугольника, Г-сечения и т. п.;
- читать геометрические характеристики с листа `Results`.

Его вход — одна и та же дискретная модель в памяти независимо от того, как она была получена.

# 2. Методика СП 63.13330.2018

## 2.1. Нормативная постановка

Основные пункты:

- **п. 5.2.9** — общая необходимость учитывать случайные эксцентриситеты и влияние продольного изгиба при расчёте внецентренно сжатых элементов;
- **п. 8.1.2** — влияние прогиба на несущую способность; возможность расчёта по деформированной схеме либо учёта прогиба при расчёте по недеформированной схеме посредством коэффициента $\eta$;
- **п. 8.1.7** — случайный эксцентриситет;
- **п. 8.1.15** — $\eta$, $N_{cr}$, условная жёсткость $D$, $\varphi_l$, $\delta_e$;
- **п. 8.1.17** — расчётная длина $l_0$;
- **пп. 8.1.20–8.1.25** — НДМ, в том числе произвольная форма сечения и действие продольной силы с моментами двух направлений.

СП 63, п. 8.1.2, допускает при расчёте по недеформированной схеме учитывать влияние прогиба умножением начального эксцентриситета на $\eta$, когда


$$\frac{l_0}{i}>14.$$


Если условие не выполнено, отдельное увеличение эксцентриситета по этой упрощённой схеме не требуется; практически можно принимать


$$\eta=1,$$


но случайный эксцентриситет по п. 8.1.7 всё равно должен быть учтён.

Нормативная проверка устойчивости относится к расчету несущей способности сжатого элемента, поэтому для расчета по СП следует выбирать `MaterialModel.Stability.ValueSet = ULS(I)`. Программа не подменяет материалы внутри класса устойчивости: выбранный профиль явно передает набор характеристик, а диаграммы `TwoLine/ThreeLine` для этой проверки не используются.


## 2.2. Шаг 1 — определить расчётные длины

СП 63, п. 8.1.17, позволяет определять $l_0$ по расчётной схеме и приводит типовые значения, например:

- шарнирное опирание с двух концов: $l_0=1.0L$;
- защемление–свободный конец: $l_0=2.0L$;
- защемление–шарнир: около $0.7L$;
- два жёстких несмещаемых защемления: около $0.5L$;
- другие схемы — согласно п. 8.1.17.

В принятой постановке пользователь уже задаёт коэффициенты расчётной длины для двух главных центральных плоскостей:

$$l_{0,1}=\mu_1L,\; l_{0,2}=\mu_2L.$$

Программа не пересчитывает и не поворачивает $\mu_1,\mu_2$, а только использует их для соответствующих главных направлений.

## 2.3. Шаг 2 — определить геометрические характеристики из дискретной модели

Расчёт выполняется только по бетонным и арматурным дискретным элементам.

Для каждой главной плоскости $j=1,2$ нужны:

- $h_j$ — полный размер бетонного сечения в плоскости изгиба;
- $I_{b,j}$ — момент инерции бетона;
- $I_{s,j}$ — момент инерции всей продольной арматуры;
- $i_j$ — радиус инерции для проверки гибкости в принятой нормативной постановке.

$$h_j=u_{max,j}-u_{min,j},$$

где $u$ — проекция **границ бетонных элементов**, а не только их центров, на направление, перпендикулярное оси $j$.

### Момент инерции бетона

$$I_{b,j}=\sum_k(I_{k,j}^{local}+A_kd_{k,j}^2).$$

Здесь $I_{k,j}^{local}$ — локальный момент инерции бетонного элемента $k$, $A_k$ — его площадь, $d_{k,j}$ — расстояние от центра элемента до рассматриваемой оси.

### Момент инерции арматуры

$$I_{s,j}=\sum_m(I_{s,m,j}^{local}+A_{s,m}d_{s,m,j}^2).$$

Если собственная инерция арматурного элемента не хранится, допускается $I_{s,m,j}^{local}=0$ с диагностическим признаком.

> **Важно:** в формуле $D$ СП 63 бетон и арматура учитываются отдельными членами. Нельзя использовать уже приведённый момент инерции `бетон + n·арматура` и затем ещё раз добавлять $E_sI_s$.

### Автоматическая и AutoCAD-геометрия

Для алгоритма они полностью эквивалентны, если обе после построения предоставляют один и тот же набор:

```text
Area + Centroid + LocalInertia + Boundary
```

Если AutoCAD-ветка не формирует локальные инерции или геометрию границ ячеек, исправлять нужно importer/mesher или общий `CSectionModel`, а не добавлять специальные обходы в расчёт устойчивости.

## 2.4. Шаг 3 — случайный эксцентриситет по п. 8.1.7

СП 63 устанавливает:

$$e_a=\max(\frac{L}{600},\frac{h}{30},10\,mm).$$

Для каждой главной плоскости:

$$e_{a,j}=\max(\frac{L}{600},\frac{h_j}{30},10\,mm).$$

Здесь используется геометрическая длина $L$, а не $l_{0,j}$.

### Статически определимая система

$$e_{0,j}=e_{stat,j}+s_je_{a,j}.$$

### Статически неопределимая система

$$|e_{0,j}|=\max(|e_{stat,j}|,e_{a,j}).$$

Знак $e_{0,j}$ принимается по знаку $M_j$, а при $M_j\approx0$ — по пользовательской настройке $s_j$.

### Выбор направления без дополнительных расчётов

Для каждой плоскости:

- при $|M_j|>M_{tol}$:
  $$s_j=sign(M_j);$$
- при $|M_j|\le M_{tol}$:
  $$s_j=s_{j,user},$$
  где $s_{1,user}$ и $s_{2,user}$ заданы на `Config` как `+1/-1`.

Таким образом, для каждого сочетания всегда формируется **один** расчётный вектор случайных эксцентриситетов и один результирующий вектор моментов. Перебор двух или четырёх знаковых комбинаций не выполняется.

## 2.5. Шаг 4 — приведение нагрузки и эксцентриситет статического расчёта

Основная таблица задаёт усилия относительно точки `0,0`, совпадающей с центром тяжести бетонного сечения, с возможным смещением `Load.ReferenceOffsetX/Y`.

Для устойчивости эти усилия затем переносятся к центру тяжести приведённого сечения, потому что СП 63 п. 8.1.7 и СП 35 п. 7.52 задают эксцентриситет продольной силы именно относительно приведённого сечения.

До вызова `CStabilityCalculator` существующая логика программы должна одинаково применить это смещение:

- к полному $N,M_x,M_y$;
- к дополнительному $N_{G+L},M_{x,G+L},M_{y,G+L}$.

После приведения и перехода в главные оси:

$$e_{stat,j}=\frac{M_j}{N_c}.$$

Для СП 63 расчётные оси устойчивости проходят через центр тяжести приведённого сечения. Если внутри существующего `CSectionModel` локальная система элементов имеет другое начало координат, перенос к ней должен выполняться существующим общим helper-ом, а не дублироваться в классе устойчивости.

`Load.ReferenceOffsetX/Y` и использованные моменты до/после переноса выводятся в `rngBatchSummary`.

## 2.6. Шаг 5 — коэффициент длительности φl

По п. 8.1.15:

$$\varphi_l=1+\frac{M_{l1}^{SP63}}{M_1^{SP63}}\le2.$$

Здесь:

- $M_1^{SP63}$ — момент от полной нагрузки относительно центра наиболее растянутого или наименее сжатого дискретного стержня арматуры;
- $M_{l1}^{SP63}$ — момент относительно того же стержня от постоянных + длительных нагрузок.

Для плоскости $j$ выбирается крайний арматурный элемент по направлению текущего $e_{0,j}$. Пусть $z_{s,j}$ — подписанное расстояние от расчётного центра до его центра:

$$M_1^{SP63}=M_j+N_cz_{s,j},$$

$$M_{l1}^{SP63}=M_{G+L,j}+N_{G+L}z_{s,j}.$$

Дополнительный вектор $N_{G+L},M_{x,G+L},M_{y,G+L}$ берётся из строки `rngStabilityDurationLoads`, соответствующей текущему `LC`.

### Общая настройка Auto / PhiL2

В `rngSystemSettings` используется один общий переключатель:

```text
Stability.PhiLMode = Auto / PhiL2
```

Он применяется как к СП 63, так и к коэффициенту длительности для $N_{cr}$ по СП 35.

#### Auto

При `Auto` выполняется нормативная формула:

$$\varphi_l=\min(2,1+\frac{M_{l1}^{SP63}}{M_1^{SP63}}).$$

Нулевые дополнительные нагрузки допустимы. Если $M_1^{SP63}$ практически равен нулю и прямое деление невозможно, программа не должна аварийно делить на ноль; принимается консервативная ветвь:

$$\varphi_l=2,$$

а источник результата фиксируется как `AutoZeroDenominatorPhiL2`.

#### PhiL2

При `PhiL2` сразу принимается:

$$\varphi_l=2.$$

Значения дополнительной таблицы всё равно читаются и выводятся для трассируемости, но в формуле $\varphi_l$ не используются.

Отдельных режимов приближённой трактовки длительных нагрузок быть не должно. При выборе СП 63 пользователь обязан понимать, что в `rngStabilityDurationLoads` указывается сумма постоянных и длительных усилий.

## 2.7. Шаг 6 — относительный эксцентриситет δe

По п. 8.1.15:


$$\delta_e=\frac{|e_0|}{h}.$$


При этом СП ограничивает величину:


$$0.15\le\delta_e\le1.5.$$


Для программы:


$$\delta_{e,j} =\min[ 1.5, \max(0.15,\frac{|e_{0,j}|}{h_j}) ] .$$


**Ограничивается только $\delta_e$ в формуле жёсткости.**

Сам действительный эксцентриситет $e_0$ и момент $Ne_0$ не обрезаются при $e_0/h>1.5$.

## 2.8. Шаг 7 — коэффициенты жёсткости и условная жёсткость D

По п. 8.1.15:


$$k_b =\frac{0.15} {\varphi_l(0.3+\delta_e)}$$


и


$$k_s=0.7.$$


Условная изгибная жёсткость:


$$D =k_bE_bI_b+k_sE_sI_s$$


или для каждой плоскости:


$$D_j =k_{b,j}E_bI_{b,j} +0.7E_sI_{s,j}.$$


Эта $D$ — специальная **условная жёсткость для расчёта влияния продольного изгиба по п. 8.1.15**, а не касательная/секущая матрица жёсткости НДМ, используемая при поиске равновесия сечения.

## 2.9. Шаг 8 — условная критическая сила Ncr

Формула (8.15):


$$N_{cr} =\frac{\pi^2D}{l_0^2}$$


Для двух плоскостей:


$$N_{cr,1}=\frac{\pi^2D_1}{l_{0,1}^2}, N_{cr,2}=\frac{\pi^2D_2}{l_{0,2}^2}.$$


## 2.10. Шаг 9 — коэффициент увеличения эксцентриситета η

Формула (8.14):


$$\eta =\frac{1}{1-N_c/N_{cr}}$$


Для плоскости `j`:


$$\eta_j =\frac{1}{1-N_c/N_{cr,j}}.$$


Если


$$N_c\ge N_{cr,j},$$


знаменатель становится нулевым или отрицательным. Расчёт через $\eta$ по п. 8.1.15 не может быть продолжен как обычное увеличение момента.

Класс должен вернуть внутреннюю причину `N_GE_NCR`. `CBatchStatusPolicy` отображает её на листе как `FAIL`.

Искусственный нормативный предел вроде `EtaMax = 5` или `10` вводить нельзя, если он нужен только как техническая защита чисел.

## 2.11. Шаг 10 — сформировать расчётный момент второго порядка

В рассматриваемой плоскости:


$$e_{d,j}=\eta_j e_{0,j}$$


и


$$M_{d,j}=N_c e_{d,j}=\eta_jN_c e_{0,j}.$$


Если расчёт выполнялся в повернутых осях:


$$[M_{x,d},M_{y,d}]^T=R^T(\alpha)[M_{d,1},M_{d,2}]^T.$$


Продольная сила остаётся исходной:


$$N_d=N.$$


Таким образом, результат блока эффектов второго порядка:


$$(N,M_x,M_y)\rightarrow(N,M_{x,d},M_{y,d}).$$


## 2.12. Что является «проверкой устойчивости» по СП 63

Здесь важно не смешивать понятия.

Для общего внецентренно сжатого элемента СП 63 п. 8.1.15 вводит $N_{cr}$ прежде всего как величину для определения $\eta$. Условие


$$N<N_{cr}$$


само по себе **не является окончательной проверкой несущей способности**.

Полная логика:

1. существует возможность получить конечное $\eta$:


$$N_c<N_{cr};$$


2. формируются увеличенные моменты;
3. сечение должно выдержать


$$N, M_{x,d}, M_{y,d}$$


по принятой методике прочности.

Для произвольного сечения это естественно выполнять НДМ по пп. 8.1.20–8.1.25.

Для каждой главной плоскости выводится коэффициент запаса:

$$K_{cr,j}=\frac{N_{cr,j}}{N_c}.$$

Управляющие значения:

$$N_{cr,min}=\min(N_{cr,1},N_{cr,2}),$$

$$K_{cr,min}=\min(K_{cr,1},K_{cr,2}).$$

При $K_{cr,j}\le1$ нормативное условие не выполнено. Внутренний результат передаётся в `CBatchStatusPolicy`, который формирует `FAIL`.

При $K_{cr,j}>1$ можно получить конечное $\eta_j$ и сформировать увеличенный момент.

При этом $N<N_{cr}$ не заменяет последующую проверку сечения на прочность. Поэтому логика результата остаётся раздельной:

```text
StabilityStatus
Downstream NDM result
```

### Упрощённая ветвь п. 8.1.16

СП 63 содержит специальную упрощённую проверку для определённых прямоугольных внецентренно сжатых элементов при малом эксцентриситете и ограниченной гибкости. Она **не является универсальной методикой для произвольного Г-образного сечения**, поэтому в общий алгоритм произвольного сечения её включать не рекомендуется.

## 2.13. СП 63 — компактный алгоритм

```text
INPUT:
    current profile:
        Calculation.Stability.Enabled
        MaterialModel.Stability.ValueSet
    Stability.Code = SP63
    total N, Mx, My
    duration-row N(G+L), Mx(G+L), My(G+L)
    Load.ReferenceOffsetX/Y
    L, μ1, μ2
    SystemType
    ZeroMomentEccentricitySign1/2
    PhiLMode = Auto / PhiL2
    normalized concrete/rebar discrete model
    material values from MaterialModel.Stability.ValueSet

1. Если Calculation.Stability.Enabled = No:
       вернуть исходные N, Mx, My; StabilityStatus = N/A.
2. Получить полный и дополнительный векторы,
   уже приведённые существующим Load.ReferenceOffset helper.
3. По приведенному сечению определить центр тяжести и главные оси 1/2.
4. Преобразовать оба вектора моментов к центру тяжести приведенного сечения и в оси 1/2.
5. l0,1 = μ1*L; l0,2 = μ2*L.
6. Для j = 1,2:
       6.1 определить h, Ib, Is, i;
       6.2 ea = max(L/600, h/30, 10 mm);
       6.3 определить s:
             sign(Mj), если Mj не нулевой;
             пользовательское +1/-1, если Mj ≈ 0;
       6.4 сформировать e0 по SystemType;
       6.5 определить M1_SP63 и Ml1_SP63 относительно одного стержня;
       6.6 PhiLMode:
             Auto  -> нормативная формула;
             PhiL2 -> phi_l = 2;
       6.7 delta_e = clamp(|e0|/h, 0.15, 1.5);
       6.8 kb = 0.15/[phi_l*(0.3+delta_e)];
       6.9 D = kb*Eb*Ib + ks*Es*Is;
       6.10 Ncr = pi^2*D/l0^2;
       6.11 Kcr = Ncr/Nc;
       6.12 если l0/i > 14:
              eta = 1/(1-Nc/Ncr);
            иначе:
              eta = 1;
       6.13 Md = eta*Nc*e0.
       6.14 проверить Kcr > 1.
7. Вернуть Md1/Md2 в X/Y.
8. Основной выход фильтра:
       Ndesign = N;
       MxDesign;
       MyDesign.
9. Передать внутренние результаты в CBatchStatusPolicy.
10. Никаких дополнительных НДМ-решений для выбора знака ea не выполнять.
```

# 3. Методика СП 35.13330.2011

## 3.1. Нормативная постановка

Основные пункты для рассматриваемой задачи:

- **п. 7.52** — случайный эксцентриситет и общий принцип принятия меньшего результата из расчётов прочности/устойчивости;
- **п. 7.53** и **таблица 7.20** — выбор ветви расчёта по отношению $e_c/r$;
- **п. 7.54**, формулы (7.8), (7.10)–(7.14) — коэффициент $\eta$ и условная критическая сила;
- **п. 7.55**, формула (7.15), таблица 7.21 — отдельный коэффициент продольного изгиба $\varphi$ при $e_c/r\le1$;
- **п. 7.69**, в частности формула (7.31) — отдельная проверка устойчивости;
- **п. 7.70** — расчёт прочности внецентренно сжатых элементов в ветви большого эксцентриситета;
- положения изменений СП 35 о расчёте косого внецентренного сжатия и непрямоугольных сечений методом НДМ по СП 63 с характеристиками материалов по СП 35.

Ключевое отличие от СП 63: СП 35 **нормативно разделяет две ветви**.

Для железобетона по таблице 7.20:

### Ветвь A


$$|e_c|\le r$$


- отдельная проверка прочности;
- отдельная проверка устойчивости по пп. 7.55 и 7.69а;
- увеличение эксцентриситета через $\eta$ в рассматриваемой плоскости не является основной ветвью.

### Ветвь B


$$|e_c|>r$$


- влияние прогиба учитывается через $\eta$ по п. 7.54;
- затем выполняется проверка прочности;
- отдельная проверка через $\varphi$ в той же плоскости по таблице 7.20 не выполняется.

Это принципиально: нельзя без разбора одновременно увеличить момент через $\eta$ и дополнительно уменьшить сопротивление тем же направлением через $\varphi$.

Выбранный `Stability.Code = SP35` переключает только формулы этого класса. Материалы не подменяются автоматически: класс использует набор характеристик из `MaterialModel.Stability.ValueSet` текущего профиля. Диаграммы материалов в формулах устойчивости не участвуют.

Как и для СП 63, нормативный расчет устойчивости следует выполнять с `ULS(I)`, потому что это проверка несущей способности сжатого элемента. Если пользователь выбирает другой набор характеристик, расчет выполняется по явно заданному профилю и должен рассматриваться как осознанная пользовательская настройка.


## 3.2. Шаг 1 — длины

Для алгоритма сознательно разделяются:

- $L$ — геометрическая длина/участок между закреплениями;
- $l_{0,1}$ и $l_{0,2}$ — расчётные длины по двум главным центральным плоскостям.

### Случайный эксцентриситет по п. 7.52

П. 7.52 записывает случайный эксцентриситет как:

$$e_{c,sl}=\frac{L}{400}$$

если использовать в программном обозначении именно **геометрическую длину участка между закреплениями**.

Для $N_{cr}$, гибкости и табличных коэффициентов пользователь задаёт:

$$l_{0,1}=\mu_1L,\; l_{0,2}=\mu_2L.$$

Коэффициенты $\mu_1,\mu_2$ относятся непосредственно к главным центральным плоскостям сечения и не преобразуются программой.

> Рекомендуется в коде различать `GeometricLength`, `EffectiveLength1`, `EffectiveLength2`. Это исключает ошибку использования одной и той же длины и в случайном эксцентриситете, и в расчёте гибкости без учёта закрепления.

## 3.3. Шаг 2 — случайный эксцентриситет по п. 7.52

Для расчёта прочности:

$$e_{c,sl}=\frac{L}{400}.$$

### Статически определимая система

$$e_{c,j}=e_{stat,j}+s_je_{c,sl}.$$

### Статически неопределимая система

$$|e_{c,j}|=\max(|e_{stat,j}|,e_{c,sl}).$$

Направление определяется без дополнительных расчётов:

- при $|M_j|>M_{tol}$:
  $$s_j=sign(M_j);$$
- при $|M_j|\le M_{tol}$:
  $$s_j=s_{j,user},$$
  где пользователь задал `+1/-1` в общих настройках устойчивости.

Таким образом, даже при нулевом моменте формируется один однозначный расчётный вектор.

СП 35, п. 7.52, указывает, что случайный эксцентриситет не учитывается при расчётах трещиностойкости и деформаций. Однако программа не вводит жёсткий запрет по типу профиля: если пользователь включил фильтр для профиля второй группы, класс выполнит расчёт. Это решение и ответственность пользователя должны быть явно описаны в справке.

## 3.4. Шаг 3 — приведённые характеристики и ядровое расстояние из дискретной модели

Для классификации по п. 7.53 требуются характеристики **приведённого сечения**:

$$A_{red},I_{red},i,W_{red},r.$$

Они должны вычисляться суммированием бетонных и арматурных дискретных элементов, а не специальными формулами прямоугольника/тавра/Г-сечения.

$$i=\sqrt{\frac{I_{red}}{A_{red}}}.$$

Для несимметричного сечения нужны направленные крайние расстояния:

$$c_+,\; c_-,$$

$$W_+=\frac{I_{red}}{c_+},\; W_-=\frac{I_{red}}{c_-},$$

$$r_+=\frac{W_+}{A_{red}},\; r_-=\frac{W_-}{A_{red}}.$$

В расчёте используется $r_{dir}=r_+$ или $r_-$ в зависимости от направления $e_c$.

Для получения $c_+,c_-$ также используются проекции **реальных границ бетонных дискретных элементов**, а не предположение о типе целого сечения.

### Особенность AutoCAD-импорта

Если после импорта доступны только центры и площади ячеек, но отсутствуют их границы/локальные размеры, точные $c_+,c_-$, $W_\pm$, $r_\pm$ получить нельзя. Такой набор данных недостаточен для строгой ветви СП 35; внутренняя причина должна быть сопоставлена через `CBatchStatusPolicy` со статусом `InputErr`, а не скрыто заменена диапазоном центров.

## 3.5. Шаг 4 — классификация по ec/r

Для каждой рассматриваемой плоскости:


$$q_j=\frac{|e_{c,j}|}{r_{dir,j}}.$$


Далее:

```text
если q <= 1:
    ветвь отдельной устойчивости по φ;
если q > 1:
    ветвь влияния прогиба по η.
```

Нормативная основа — п. 7.53 и таблица 7.20.

# 3A. СП 35: ветвь |ec| > r — увеличение момента через η

## 3A.1. Коэффициент η

По п. 7.54, формула (7.8):


$$\eta =\frac{1}{1-N_c/N_{cr}}$$


Формально вид совпадает со СП 63, но способ определения $N_{cr}$ другой.

## 3A.2. Коэффициент длительного действия φl

Формула (7.11):

$$\varphi_l=1+\frac{M_l}{M}.$$

Здесь:

- $M$ — момент относительно наиболее растянутой или наименее сжатой грани от полного сочетания;
- $M_l$ — момент относительно той же грани от постоянной нагрузки.

При `Stability.Code = SP35` строка `rngStabilityDurationLoads` трактуется именно как:

$$N_G,\;M_{x,G},\;M_{y,G}.$$

Пользователь самостоятельно отвечает за то, что в этой таблице указаны только постоянные, а не постоянные + длительные нагрузки.

### Stability.PhiLMode = Auto

При одинаковом направлении моментов:

$$\varphi_l=\min(2,1+\frac{M_l}{M}).$$

Если полный и постоянный моменты имеют разные знаки, применяются специальные значения п. 7.54:

$$\varphi_l=1.0, |e_c|\ge0.1h,$$

$$\varphi_l=1.05, |e_c|<0.1h.$$

Если $M$ практически равен нулю и прямое деление невозможно, принимается консервативная вычислительная ветвь:

$$\varphi_l=2,$$

с внутренним признаком `AutoZeroDenominatorPhiL2`.

### Stability.PhiLMode = PhiL2

Независимо от отношения $M_l/M$ принимается:

$$\varphi_l=2.$$

Это общий консервативный пользовательский режим для коэффициента длительности, участвующего в $N_{cr}$. Он не заменяет и не изменяет табличный коэффициент $\varphi_l^{buck}$ из таблицы 7.21.

## 3A.3. Параметр δ

П. 7.54 использует:


$$\delta=\frac{|e_c|}{h},$$


но не менее значения по формуле (7.12):


$$\delta_{min} =0.5 -0.01\frac{l_0}{h} -0.01R_b$$


где $R_b$ подставляется в МПа.

Следовательно:


$$\delta =\max( \frac{|e_c|}{h}, \delta_{min} ).$$


> Ограничение `0.15…1.5` из СП 63 сюда переносить нельзя. Это другая методика.

## 3A.4. Коэффициент предварительного напряжения

Полная методика СП 35 содержит $\varphi_p$ по формуле (7.13).

В программе поддерживается только ненапрягаемая арматура, поэтому нормативное значение по умолчанию:

$$\varphi_p=1.$$

Для прозрачности и тестирования значение хранится в подблоке настроек СП 35:

```text
Stability.SP35.PhiP = 1.0
```

Класс использует переданное значение, но справка должна явно указывать: рабочая область программы — ненапрягаемая арматура, для которой ожидается $\varphi_p=1$.

## 3A.5. Условная критическая сила Ncr

По п. 7.54, формула (7.10), для железобетонного элемента:


$$N_{cr} =\frac{6.4E_b}{l_0^2} [ \frac{I_b}{\varphi_l} ( \frac{0.11}{0.1+\delta/\varphi_p} +0.1 ) +n_1I_s ]$$


где:


$$n_1=\frac{E_s}{E_b}.$$


Для ненапрягаемой арматуры $\varphi_p=1$, поэтому:


$$N_{cr} =\frac{6.4E_b}{l_0^2} [ \frac{I_b}{\varphi_l} ( \frac{0.11}{0.1+\delta} +0.1 ) +\frac{E_s}{E_b}I_s ].$$


### Оси для Ib и Is

П. 7.54 требует определять моменты инерции относительно осей, проходящих через центр тяжести **приведённого сечения**.

Для каждой выбранной расчётной плоскости алгоритм работает только с дискретными элементами:

1. по весам приведённого сечения найти его центр;
2. провести через него ось, параллельную соответствующей главной бетонной оси `1/2`;
3. по бетонным ячейкам суммировать $I_b$ с локальными инерциями и переносом Штейнера;
4. по дискретным арматурным элементам аналогично суммировать $I_s$.

Никакого знания о том, является ли сечение Г-образным, коробчатым или полученным из AutoCAD, не требуется.

## 3A.6. Обязательное ограничение N/Ncr

СП 35, п. 7.54, формула (7.14):


$$\frac{N_c}{N_{cr}}\le0.7$$


Это значительно строже простого математического условия $N<N_{cr}$.

Если


$$\frac{N_c}{N_{cr}}>0.7,$$


нельзя просто продолжать расчёт с большим $\eta$ и считать это расчётом по п. 7.54.

Внутренний результат этой проверки передаётся в `CBatchStatusPolicy`, который выводит на лист только статус `FAIL`.

## 3A.7. Увеличенный момент

После вычисления $\eta$:


$$e_d=\eta e_c$$


и


$$M_d=N_c\eta e_c.$$


Для двух расчётных плоскостей значения $M_{d,1}$, $M_{d,2}$ затем возвращаются в глобальные $M_x,M_y$.

## 3A.8. Принятое постоянное значение η по длине элемента

Изменение $\eta$ по длине элемента в программе **не учитывается**.

Не вводятся:

- координата проверяемого сечения по длине;
- эпюра изменения $\eta$;
- интерполяция к $\eta=1$ у опор.

Для любого проверяемого сечения применяется полное вычисленное значение:

$$\eta(x)=\eta_{max}.$$

Это упрощение должно быть явно описано на листе `Справка`. Отдельная пользовательская настройка распределения $\eta$ по длине не требуется.

## 3A.9. Итог ветви |ec| > r

Для рассматриваемой плоскости:

1. выполнено условие


$$N_c/N_{cr}\le0.7;$$


2. вычислены $N_{cr}$ и коэффициент запаса $K_{cr}=N_{cr}/N_c$;
3. момент увеличен через $\eta$;
4. прочность сечения проверена на увеличенный момент.

То есть логически:


```text
ULS35 = CriticalLoadCheck AND StrengthCheck
```

## 3B.1. Область ветви

## 3B.4. Разделение постоянной и временной продольной силы

При выборе СП 35 дополнительная таблица содержит постоянную нагрузку:

$$N_l=|N_G|.$$

Временная часть:

$$N_m=N_c-N_l.$$

Нулевая постоянная строка допустима:

$$N_l=0, N_m=N_c.$$

Она означает, что вся действующая сжимающая сила рассматривается как временная.

Если знаки или уровень коэффициентов дополнительной нагрузки не согласованы с полной нагрузкой, либо $N_l>N_c$ без физически объяснимой причины, класс должен вернуть внутреннюю причину ошибки для последующего отображения через `CBatchStatusPolicy`.

Отдельного режима `без N_G` и автоматической подмены $N_l=N_c$ не предусматривается: пользователь всегда заполняет фиксированную таблицу, даже если значения в ней равны нулю.

## 3B.5. Итоговый коэффициент продольного изгиба φ

П. 7.55, формула (7.15):


$$\varphi =\frac{\varphi_m} { \frac{N_l}{N_c}\frac{\varphi_m}{\varphi_l^{buck}} +\frac{N_m}{N_c}}$$


Здесь необходимо **не путать** два разных параметра СП 35:

- $\varphi_l$ из формулы (7.11) — коэффициент длительности для расчёта $N_{cr}$;
- $\varphi_l^{buck}$ из таблицы 7.21 — коэффициент продольного изгиба при постоянной нагрузке.

В коде им нужны разные имена, например:

```text
DurationFactorForNcr35
BucklingPhiPermanent35
```

## 3B.6. Проверка устойчивости по п. 7.69а

Для ненапрягаемой арматуры при сцеплении с бетоном формула (7.31) приводится к виду:


$$N_c \le \varphi( R_bA_b+R_{sc}A_s )$$


где:

- $A_b$ — площадь бетона;
- $A_s$ — площадь всей ненапрягаемой продольной арматуры, учитываемой по данной формуле;
- $R_b$, $R_{sc}$ — расчётные сопротивления по СП 35.

П. 7.69 содержит специальное уточнение для большого процента армирования: если площадь арматуры превышает установленный в пункте уровень (3 %), площадь бетона следует корректировать, исключая площадь арматуры в соответствии с нормативным текстом.

Предельная сила по устойчивости:

$$N_{ult,stab}=\varphi(R_bA_b+R_{sc}A_s).$$

Коэффициент запаса, выводимый в `rngBatchSummary`:

$$K_{stab}=\frac{N_{ult,stab}}{N_c}.$$

Коэффициент использования:


$$U_{stab}=\frac{N_c}{N_{ult,stab}}=\frac{1}{K_{stab}}.$$


Условие:


$$U_{stab}\le1.0.$$


При этом прочность сечения должна проверяться **отдельно**. По п. 7.52 несущая способность сжатого элемента определяется по более неблагоприятному из результатов прочности и устойчивости.

## 3B.7. Итог ветви |ec| ≤ r


```text
ULS35 = StrengthCheck AND StabilityCheck
```


Это действительно самостоятельная нормативная проверка устойчивости, в отличие от вспомогательного контроля $N<N_{cr}$ в методике $\eta$.

# 3C. СП 35 и произвольное несимметричное сечение

## 3C.1. Принятая программная постановка

Класс работает с произвольной дискретной сеткой бетона и арматуры и не знает семантики целого сечения.

Для каждой главной плоскости он:

1. определяет необходимые приведённые характеристики;
2. вычисляет направленное ядровое расстояние;
3. выполняет ветвление $e_{c,j}/r_j$;
4. применяет соответствующие формулы СП 35;
5. возвращает расчётные моменты и результаты устойчивости.

Окончательная прочность произвольного сечения остаётся задачей существующего НДМ-решателя.

## 3C.2. Материалы

Выбор `Stability.Code = SP35` **не означает автоматической подмены материалов на характеристики СП 35**.

`CStabilityCalculator` использует строго те значения:

$$E_b,\;E_s,\;R_b,\;R_{sc},$$

которые уже выбраны пользователем в `rngCalculationProfiles` и переданы в класс существующей цепочкой.

Класс не изменяет:

- `CalculationPurpose`;
- `LimitStateGroup`;
- тип диаграмм;
- сопротивления;
- модули упругости;
- коэффициенты материалов.

Поэтому кодовые статусы вида `` не вводятся. Нормативные ограничения и ответственность за сочетание выбранного СП с материалами описываются только в справке.

## 3C.3. Две главные плоскости

1. определить главные центральные оси `1/2`;
2. перевести в них полный и дополнительный векторы моментов;
3. использовать $\mu_1,\mu_2$ непосредственно для этих плоскостей;
4. определять $h,I,r,N_{cr},\eta,\varphi$ в согласованных направлениях;
5. вернуть увеличенные моменты в исходные $X/Y$;
6. передать один итоговый вектор дальше по существующей цепочке.

$$l_{0,1}=\mu_1L,\;l_{0,2}=\mu_2L.$$

Для ветви с $\eta$:

$$M_{d,1}=\eta_1M_{0,1},\;M_{d,2}=\eta_2M_{0,2}.$$

$$[M_{x,d},M_{y,d}]^T=R^T(\alpha)[M_{d,1},M_{d,2}]^T.$$

# 3D. СП 35 — компактный алгоритм

```text
INPUT:
    current profile:
        Calculation.Stability.Enabled
        MaterialModel.Stability.ValueSet
    Stability.Code = SP35
    total N, Mx, My
    permanent-row NG, MxG, MyG
    Load.ReferenceOffsetX/Y
    L, μ1, μ2
    SystemType
    ZeroMomentEccentricitySign1/2
    PhiLMode = Auto / PhiL2
    SP35.PhiP (default 1.0)
    rngSP35Table721 loaded into memory
    normalized concrete/rebar discrete model
    material values from MaterialModel.Stability.ValueSet

1. Если Calculation.Stability.Enabled = No:
       вернуть исходные N, Mx, My; StabilityStatus = N/A.
2. Получить полный и постоянный векторы,
   уже приведённые существующим Load.ReferenceOffset helper.
3. Определить главные оси 1/2 и преобразовать моменты.
4. l0,1 = μ1*L; l0,2 = μ2*L.
5. Для j = 1,2:
       5.1 получить Ared, Ired, i, rdir, Ib, Is, h;
       5.2 ec,sl = L/400;
       5.3 определить s:
             sign(Mj), если Mj не нулевой;
             пользовательское +1/-1, если Mj ≈ 0;
       5.4 сформировать ec по SystemType;
       5.5 q = |ec|/rdir.

6. Если q > 1:
       6.1 получить M и Ml относительно одной крайней грани;
       6.2 PhiLMode:
             Auto  -> (7.11) или специальная ветвь 1.0/1.05;
             PhiL2 -> phi_l = 2;
       6.3 delta_min по (7.12);
       6.4 delta = max(|ec|/h, delta_min);
       6.5 phi_p из настройки, default = 1.0;
       6.6 Ncr по (7.10);
       6.7 Kcr = Ncr/Nc;
       6.8 проверить Nc/Ncr <= 0.7;
       6.9 eta = 1/(1-Nc/Ncr);
       6.10 Md = eta*Nc*ec.

7. Если q <= 1:
       7.1 lambda = l0/i;
       7.2 получить phi_m и phi_l_buck
           из массива rngSP35Table721;
       7.3 Nl = |NG|; Nm = Nc-Nl;
       7.4 phi по (7.15);
       7.5 Nult,stab = phi*(Rb*Ab + Rsc*As);
       7.6 Kstab = Nult,stab/Nc;
       7.7 проверить Kstab >= 1;
       7.8 eta = 1;
       7.9 Md = Nc*ec.

8. Вернуть итоговые M1/M2 в X/Y.
9. Основной выход фильтра:
       Ndesign = N;
       MxDesign;
       MyDesign.
10. Материалы брать из MaterialModel.Stability.ValueSet, диаграммы не использовать.
11. Передать внутренние результаты в CBatchStatusPolicy.
12. Никаких дополнительных НДМ-решений для выбора знака ea не выполнять.
```

# 5. Исходные данные и настройки на листе Config

## 5.1. Строки в rngCalculationProfiles

В существующий диапазон профилей добавляются две строки:

| Ключ/строка | Значения | Назначение |
|---|---|---|
| `Calculation.Stability.Enabled` | `Yes / No` | применять фильтр продольного изгиба и выполнять проверку устойчивости |
| `MaterialModel.Stability.ValueSet` | `ULS(I) / SLS(II)` | выбрать набор характеристик материала для устойчивости без выбора диаграмм |

Флаг относится к каждому профилю отдельно. Если он выключен, усилия передаются дальше без изменения, а `StabilityStatus = N/A`. Если включен, один изолированный класс устойчивости сначала рассчитывает продольный изгиб/устойчивость, затем передает скорректированные `N/Mx/My` в существующую цепочку НДМ.

Для расчета по СП следует выбирать `ULS(I)`, потому что устойчивость относится к проверке несущей способности сжатого элемента. Диаграммы `TwoLine/ThreeLine` в этой проверке не выбираются и не используются.

## 5.2. Блок Stability в rngSystemSettings

Блок должен быть визуально разделён на три подблока.

### Общие настройки

| Ключ | Значения/единицы | Смысл |
|---|---|---|
| `Stability.Code` | `SP63 / SP35` | выбор нормативной ветви |
| `Stability.ElementLength` | длина | геометрическая свободная длина $L$ |
| `Stability.Mu1` | безразмерно | $\mu_1$ для первой главной плоскости |
| `Stability.Mu2` | безразмерно | $\mu_2$ для второй главной плоскости |
| `Stability.SystemType` | `Determinate / Indeterminate` | правило учёта случайного эксцентриситета |
| `Stability.ZeroMomentEccentricitySign1` | `+1 / -1` | направление случайного эксцентриситета при $M_1\approx0$: $e_a$ для СП 63 или $e_{c,sl}$ для СП 35 |
| `Stability.ZeroMomentEccentricitySign2` | `+1 / -1` | направление случайного эксцентриситета при $M_2\approx0$: $e_a$ для СП 63 или $e_{c,sl}$ для СП 35 |
| `Stability.PhiLMode` | `Auto / PhiL2` | единый режим коэффициента длительности для $N_{cr}$ |

`PhiL2` имеет одинаковое пользовательское значение для обоих СП: принять $\varphi_l=2$. Формула `Auto` различается по выбранному нормативу.

### Настройки СП 63

| Ключ | Default | Комментарий |
|---|---:|---|
| `Stability.SP63.Ks` | `0.7` | коэффициент при $E_sI_s$ |
| `Stability.SP63.DeltaEMin` | `0.15` | нижняя граница $\delta_e$ |
| `Stability.SP63.DeltaEMax` | `1.5` | верхняя граница $\delta_e$ |

### Настройки СП 35

| Ключ | Default | Комментарий |
|---|---:|---|
| `Stability.SP35.PhiP` | `1.0` | для ненапрягаемой арматуры |
| `Stability.SP35.NOverNcrLimit` | `0.7` | ограничение формулы (7.14) |

Программа поддерживает только ненапрягаемую арматуру. Изменение `PhiP` допускается как пользовательская тестовая настройка, но справка должна указывать ожидаемое рабочее значение `1.0`.

## 5.3. rngStabilityDurationLoads

Размещение:

```text
Config!P27:S47
```

Имя:

```text
rngStabilityDurationLoads
```

Размер:

```text
20 × 4
```

Структура:

| `LC` | `N` | `Mx` | `My` |
|---:|---:|---:|---:|

Требования:

- `LC` соответствует номеру основной таблицы сочетаний;
- поддерживается не более 20 сочетаний;
- номера `LC` должны быть уникальны;
- нулевые значения во всех трёх усилиях допустимы;
- единицы и оси совпадают с основной таблицей;
- `Load.ReferenceOffsetX/Y` применяется к обеим таблицам одинаково;
- при СП 63 это `G + длительные`;
- при СП 35 это только `G`.

## 5.4. Табличные данные СП на Config

Любые коэффициенты, получаемые из нормативной таблицы, запрещено дублировать в коде.

Для текущего алгоритма обязательна таблица 7.21 СП 35:

```text
rngSP35Table721 = Config!AI60:AP77
```

Рекомендуемая компоновка:

- `AI58:AP58` — название: `СП 35.13330.2011, таблица 7.21`;
- `AI59:AP59` — ссылка на пункт/таблицу СП;
- `AI60:AP60` — заголовки;
- `AI61:AP77` — числовые значения.

Таблица размещается обособленно от пользовательских расчётных блоков. При добавлении других нормативных таблиц они располагаются ниже или правее начиная с области `AI60`.

В коде допускаются:

- чтение диапазона в массив;
- проверка структуры;
- поиск узлов;
- интерполяция.

В коде не допускаются:

- встроенная резервная копия чисел таблицы;
- `Select Case` со значениями таблицы;
- скрытая замена отсутствующей таблицы hardcoded-значениями.

## 5.5. Достаточность данных

При наличии:

- полного сочетания;
- строки `rngStabilityDurationLoads`;
- $L,\mu_1,\mu_2$;
- типа системы;
- двух знаков при нулевом моменте;
- выбранного `PhiLMode`;
- дискретной геометрии;
- материалов текущего профиля;
- таблицы 7.21 для СП 35;

данных достаточно для согласованного упрощённого алгоритма без координаты сечения по длине и без отдельного beam-column solver.

Строка дополнительных нагрузок считается заполненной даже при трёх нулевых усилиях. Ошибкой являются не нули, а:

- отсутствие требуемого номера `LC`;
- дублирование `LC`;
- нечисловые данные;
- невозможное деление без предусмотренной специальной ветви;
- неполная геометрическая модель.

# 6. Общий алгоритм фильтра нагрузки

## 6.1. Подготовка

1. Получить нормализованную дискретную модель, построенную автоматическим генератором либо AutoCAD importer/mesher.
2. Получить полный и дополнительный векторы нагрузок по `LC`.
3. Одинаково применить существующий `Load.ReferenceOffsetX/Y`.
4. Получить материалы, уже выбранные текущим профилем.
5. Прочитать профильные флаги и общие настройки.
6. По приведенному сечению определить центр тяжести и главные оси `1/2`.
7. Вычислить необходимые характеристики без знания типа сечения.
8. Преобразовать полный и дополнительный векторы к центру приведенного сечения и в `1/2`.

## 6.2. Однозначное направление случайного эксцентриситета

Для $j=1,2$:

При $|M_j|>M_{tol}$:

$$s_j=sign(M_j).$$

При $|M_j|\le M_{tol}$:

$$s_j=s_{j,user}.$$

Пользовательские $s_{1,user},s_{2,user}$ равны `+1` или `-1`.

Программа не создаёт альтернативные знаковые сочетания и не запускает НДМ несколько раз только ради поиска направления случайного эксцентриситета.

## 6.3. Ветвление по выбранному СП

```text
Stability.Code = SP63 -> выполнить раздел 2
Stability.Code = SP35 -> выполнить раздел 3
```

Выбор СП меняет только формулы внутри класса. Материалы не меняются.

## 6.4. Флаг профиля

Если `Calculation.Stability.Enabled = Yes`, класс формирует:

$$N_d=N,$$

$$M_{x,d},\;M_{y,d}.$$

Если `Calculation.Stability.Enabled = No`, основной выход является pass-through:

$$N_d=N,\;M_{x,d}=M_x,\;M_{y,d}=M_y.$$

Если флаг выключен, `StabilityStatus = N/A`. Если флаг включен, класс одновременно учитывает продольный изгиб и возвращает расчетные величины устойчивости для Summary.

## 6.5. Передача дальше

Класс возвращает ровно один итоговый вектор:

$$N_d,\;M_{x,d},\;M_{y,d}.$$

Он передаётся дальше в уже существующую цепочку расчётов текущего профиля.

Класс не решает, какие именно downstream-проверки будут запущены. Поэтому при включённом фильтре скорректированные моменты передаются дальше в те проверки, которые запросил текущий профиль.

## 6.6. Проверка устойчивости и запас

СП 63:

$$K_{cr,j}=\frac{N_{cr,j}}{N_c}.$$

СП 35, ветвь $e_c/r>1$:

$$K_{cr,j}=\frac{N_{cr,j}}{N_c}.$$

СП 35, ветвь $e_c/r\le1$:

$$K_{stab,j}=\frac{N_{ult,stab,j}}{N_c}.$$

Для общего информационного поля `StabilityReserveFactor` принимается минимальное применимое значение по двум главным плоскостям.

В СП 35 поле `Ncr` в ветви $e_c/r\le1$ не подменяется величиной $N_{ult,stab}$: обе величины выводятся под собственными названиями.

Названия могут быть скорректированы по стилю проекта, но порядок областей ответственности должен сохраняться.

## 7.2. Вход класса

Класс не читает Excel. Существующие readers/orchestrator передают ему:

```text
- CSectionModel / нормализованную дискретную модель;
- полный вектор нагрузки;
- дополнительный вектор нагрузки, найденный по LC;
- исходные значения до Load.ReferenceOffset для отчётности;
- значения `Load.ReferenceOffsetX/Y` для отчётности и уже приведённые существующим helper-ом векторы;
- L, μ1, μ2;
- SystemType;
- ZeroMomentEccentricitySign1/2;
- PhiLMode;
- Code = SP63/SP35;
- Calculation.Stability.Enabled обрабатывается orchestrator-ом до вызова класса;
- MaterialModel.Stability.ValueSet текущего профиля;
- массив rngSP35Table721 при необходимости.
```

В класс должны передаваться уже приведённые существующим helper-ом нагрузки. Значения `Load.ReferenceOffsetX/Y` передаются только для трассируемости и не применяются классом повторно.

## 7.3. Выход класса

Основной выход:

```text
DesignN
DesignMx
DesignMy
```

Дополнительно класс хранит read-only расчётные свойства, необходимые для `rngBatchSummary`.

Отдельный результат-класс не создаётся. После `Calculate` вызывающий код копирует значения в уже существующий `CCombinationResult` либо другой существующий контейнер результата.

Класс не:

- запускает `CSectionSolver`;
- запускает `CCapacitySolver`;
- запускает расчёт трещин;
- выбирает `CalculationPurpose`;
- переключает материалы;
- очищает/создаёт snapshot;
- пишет на лист;
- формирует пользовательские текстовые статусы.

## 7.4. Положение в pipeline

```text
Config + rngCalculationProfiles + LC
        ↓
существующие readers
        ↓
CSectionModel в памяти
        ↓
существующий ApplyLoadReference
  для полного и дополнительного векторов
        ↓
CStabilityCalculator
  pass-through / SP63 / SP35
        ↓
DesignN, DesignMx, DesignMy
        ↓
существующая цепочка расчётов профиля
        ↓
существующий CCombinationResult
        ↓
CBatchStatusPolicy
        ↓
CBatchResultWriter / rngBatchSummary
```

`CStabilityCalculator` является фильтром между подготовленной нагрузкой и существующей цепочкой. Он не меняет внутреннюю архитектуру НДМ.

## 7.5. Поведение при ошибке фильтра

Запрещено:

```text
ошибка Stability
-> молча использовать исходные Mx/My
-> продолжить расчёт
-> получить общий OK
```

Если скорректированный вектор не может быть получен, вызывающий код не должен подменять его исходным. Внутренняя причина передаётся в `CBatchStatusPolicy`.

Если устойчивость не прошла, но скорректированные моменты конечны, downstream-расчёты могут выполняться для диагностики, однако общий итог формируется централизованной политикой статусов.

## 7.6. Материалы

Класс получает материалы текущего профиля и использует их без изменений.

Выбор `SP63/SP35` не вызывает:

- загрузку другого материала;
- смену I/II группы;
- смену диаграммы;
- автоматический выбор `Rb/Rsc/Eb/Es`.

Это позволяет использовать фильтр в любом профиле, но требует подробного предупреждения в справке.

## 7.7. Лист Справка

На листе `Справка` создаётся отдельный подробный блок по аналогии с существующим блоком расчёта трещин.

Он должен содержать:

- назначение двух профильных флагов;
- различие `SP63/SP35`;
- полный алгоритм $e_a/e_0$ для СП 63 и $e_{c,sl}/e_c$ для СП 35, $\varphi_l$, $D$, $N_{cr}$, $\eta$, $\varphi$;
- ссылки на все применённые пункты и таблицы СП;
- трактовку `rngStabilityDurationLoads` для каждого СП;
- правило `+1/-1` при нулевом моменте;
- связь $\mu_1,\mu_2$ с главными осями;
- описание `Load.ReferenceOffsetX/Y`;
- явное указание, что арматура только ненапрягаемая;
- ожидаемое $\varphi_p=1$;
- указание, что изменение $\eta$ по длине не учитывается;
- предупреждение, что класс не ограничивает запуск по группе предельного состояния;
- описание `Auto/PhiL2`;
- расшифровку коэффициентов запаса и статусов;
- указание, что материалы берутся из профиля и автоматически не заменяются.

# 9. Зафиксированные архитектурные решения

1. Добавляется **один** новый класс `CStabilityCalculator`.
2. Класс является изолированным фильтром нагрузки и не вмешивается в НДМ.
3. Два независимых профильных флага находятся в `rngCalculationProfiles`.
4. Норматив выбирается общей настройкой `Stability.Code`.
5. Общие, СП 63 и СП 35 настройки визуально разделены в `rngSystemSettings`.
6. Дополнительные нагрузки читаются из `rngStabilityDurationLoads = P27:S47`.
7. Для СП 63 таблица означает `G + длительные`; для СП 35 — только `G`.
8. Все нулевые дополнительные нагрузки являются допустимыми входными данными.
9. Направление случайного эксцентриситета при нулевом моменте задаётся пользователем как `+1/-1`.
10. Дополнительные НДМ-решения по противоположным знакам не выполняются.
11. `Stability.PhiLMode` общий для двух СП: `Auto/PhiL2`.
12. Таблица 7.21 хранится на `Config`, а не в коде.
13. Материалы берутся из текущего профиля и не подменяются при выборе СП.
14. Арматура считается только ненапрягаемой; `PhiP` по умолчанию равен `1.0`.
15. `Load.ReferenceOffsetX/Y` одинаково применяется к полному и дополнительному векторам.
16. Изменение $\eta$ по длине элемента не учитывается.
17. Координата проверяемого сечения по длине и эпюры нагрузок не вводятся.
18. Класс может быть запущен для любого профиля и любой группы по решению пользователя.
19. Все расчётные данные СП 63/СП 35 выводятся в отдельных подблоках `rngBatchSummary`.
20. На лист выводятся только статусы из `CBatchStatusPolicy`.
21. Ни одна ошибка фильтра не должна молча превращаться в pass-through с общим `OK`.
22. Геометрия поступает только как единая дискретная модель независимо от AutoGenerate/AutoCAD.
23. На листе `Справка` создаётся подробный нормативный и пользовательский раздел.

## 9.1. Проверка геометрических данных

Внутренние проверки должны выявлять:

- отсутствие бетонных элементов;
- неположительную площадь;
- невозможность определить центр/главные оси;
- неполные локальные инерции;
- отсутствие данных для определения $h$;
- разные единицы/системы координат бетона и арматуры;
- нечисловой или вырожденный тензор инерции.

Эти причины не являются отдельными пользовательскими статусами.

Рекомендуемое отображение:

- отсутствующие/неполные входные данные → `InputErr`;
- численная невозможность получить конечные характеристики → `NumFail`.

Режим аппроксимации границ эквивалентным кругом и режим локальных инерций выводятся отдельными информационными полями, но не заменяют статус.

# 11. Краткий итог

## СП 63

```text
профильные флаги
-> полный LC + строка G+L
-> одинаковый Load.ReferenceOffset
-> главные оси

-> D

```

## СП 35

```text
профильные флаги
-> полный LC + строка G
-> одинаковый Load.ReferenceOffset
-> главные оси
-> μ1/μ2
-> ec,sl и однозначный знак
-> ec/r
-> ветвь eta или ветвь phi
-> Ncr/Kcr либо Nult,stab/Kstab
-> один итоговый Mx/My
-> существующая цепочка НДМ
```

Класс не знает семантики сечения, не переключает материалы, не решает НДМ и не пишет на лист.

Пользователь управляет:

- применением продольного изгиба;
- выполнением проверки устойчивости;
- выбором СП;
- коэффициентами $\mu_1,\mu_2$;
- направлением случайного эксцентриситета при нулевом моменте;
- режимом `Auto/PhiL2`;
- содержанием дополнительной таблицы нагрузок.

`rngBatchSummary` обеспечивает полную трассируемость обеих нормативных ветвей, а все статусы проходят только через `CBatchStatusPolicy`.
