# Техническое задание
## Универсальная программа расчёта железобетонных сечений по НДМ на Excel VBA

---

# 1. Назначение проекта

Необходимо разработать инженерную программу на Excel VBA для расчёта железобетонных поперечных сечений по нелинейной деформационной модели.

Программа должна выполнять:

- расчёт прочности при действии `N + Mx`;
- расчёт прочности при действии `N + My`;
- расчёт прочности при косом изгибе `N + Mx + My`;
- определение действующих и удерживающих моментов;
- определение коэффициента запаса;
- определение коэффициента использования;
- определение напряжённо-деформированного состояния бетона и арматуры;
- расчёт ширины раскрытия уже образовавшихся нормальных трещин;
- обработку нескольких сочетаний нагрузок;
- вычисление геометрических характеристик сечения относительно исходных, центральных и главных осей;
- контроль сходимости и выполнения уравнений равновесия.

Первой новой геометрией должно быть прямоугольное сечение со скруглениями по углам.

Архитектура должна позволять в дальнейшем добавлять без изменения основного расчётного решателя:

- круглое сечение;
- обычное прямоугольное сечение;
- Г-образное сечение;
- Т-образное сечение;
- составное сечение;
- произвольное полигональное сечение;
- сечение с отверстиями;
- сечение из нескольких бетонных областей;
- сечение с различными материалами в разных областях.

Программа предназначена для инженерных расчётов. Нормативная и физическая корректность, выполнение равновесия, прозрачность алгоритмов и проверяемость результатов важнее скорости разработки и минимального объёма кода.

# 3. Границы расчётной задачи

## 3.1. Первая группа предельных состояний

Выполнять расчёт прочности нормального сечения при сочетаниях:

```text
N + Mx
N + My
N + Mx + My
```

Определять:

- `epsilon0`;
- `kappaX`;
- `kappaY`;
- положение и угол нейтральной оси;
- форму сжатой зоны;
- деформации и напряжения бетонных волокон;
- деформации и напряжения арматурных стержней;
- внутреннюю продольную силу;
- внутренние моменты;
- действующие моменты;
- удерживающие моменты;
- коэффициент запаса;
- коэффициент использования;
- критерий исчерпания несущей способности;
- предельные деформации бетона и арматуры;
- статус и точность сходимости.

## 3.2. Вторая группа предельных состояний

Выполнять только расчёт ширины раскрытия уже образовавшихся нормальных трещин.

Не выполнять:

- отдельную проверку образования трещин;
- определение момента образования трещин `Mcrc`;
- отдельный режим `CrackFormation`;
- построение диаграммы растянутого бетона до образования трещины.

При расчёте ширины раскрытия трещин принимать, что нормальные трещины уже образовались.

Расчётная схема трещиноватого сечения:

- сжатый бетон участвует в работе;
- растянутый бетон не создаёт внутренних усилий;
- растянутый бетон имеет нулевое напряжение;
- растянутый бетон имеет нулевую касательную жёсткость;
- вся продольная арматура участвует в соответствии с фактическими деформациями;
- напряжения арматуры определяются при эксплуатационном сочетании нагрузок;
- ширина раскрытия определяется по нормативной методике СП 35 и СП 63.

Площадь растянутого бетона может использоваться как геометрический параметр нормативной формулы расстояния между трещинами. Это не означает участие растянутого бетона во внутренних усилиях трещиноватого сечения.

# 5. Основные физические предпосылки

Использовать гипотезу плоских сечений.

Поле продольных деформаций:

```text
epsilon(x, y) = epsilon0 + kappaX * y + kappaY * x
```

Неизвестные параметры:

- `epsilon0` — продольная деформация в начале координат;
- `kappaX` — кривизна, связанная с изменением деформации по координате `y`;
- `kappaY` — кривизна, связанная с изменением деформации по координате `x`.

Уравнения равновесия:

```text
Nint  = Next
Mxint = Mxext
Myint = Myext
```

Даже при внешнем воздействии только `Mx` нельзя заранее принимать:

```text
kappaY = 0
```

Для несимметричного сечения, например Г-образного, при:

```text
Mx != 0
My = 0
```

может получиться:

```text
kappaX != 0
kappaY != 0
```

При этом должно выполняться:

```text
Myint ≈ 0
```

Все режимы расчёта должны использовать единый трёхпараметрический решатель.

# 7. Архитектурные принципы

1. Расчётное ядро не должно обращаться напрямую к листам Excel.
2. Разделять ввод, вывод, геометрию, волокна, арматуру, материалы, нормативные правила, решатель, несущую способность, трещины, диагностику и тесты.
3. Форма сечения не должна быть зашита в решатель НДМ.
4. Добавление новой геометрии не должно требовать изменения основного решателя.
5. Основной решатель должен получать уже подготовленные массивы волокон и стержней, модели материалов, внешние усилия и настройки.
6. Расчётный класс не должен содержать `Range`, `Cells`, `Worksheets`, `ActiveSheet`, `Selection`.
7. Расчётный класс не должен знать названия листов, адреса ячеек, конкретный тип сечения, класс бетона и таблицу СП.
8. Геометрия должна реализовываться через общий интерфейс `ISectionGeometry`.
9. Модели материалов должны реализовываться через `IConcreteMaterial` и `ISteelMaterial`.
10. Нормативные правила должны быть отделены от общего численного решателя.
11. Для конфигурации и логики допускаются классы.
12. Для десятков тысяч волокон применять типизированные массивы, если отдельные объекты снижают производительность.
13. Архитектура должна реально компилироваться в VBA и учитывать ограничения `Implements`, публичных типов, передачи массивов и совместимости 32/64-bit Excel.

# 11. Арматура

Арматуру учитывать отдельно от бетонной сетки.

Каждый стержень должен содержать:

```text
ID
X
Y
Diameter
Area
SteelMaterial
Comment
```

Напрягаемая арматура не входит в область проекта. Расчетная модель должна поддерживать только обычную ненапрягаемую арматуру. Начальные деформации арматуры, признаки преднапряжения и специальные режимы преднапряженной арматуры не реализовывать и не закладывать как будущую возможность.

Площадь стержня не должна зависеть от размера бетонной ячейки.

Деформация стержня:

```text
epsilonS = epsilon0 + kappaX * yS + kappaY * xS
```

Усилие:

```text
Fs = sigmaS * As
```

Моменты:

```text
MxS = Fs * yS
MyS = Fs * xS
```

Необходимо исключить двойной учёт бетона, замещённого арматурой.

Базовый вариант:

```text
EffectiveSteelStress = SteelStress - ConcreteStressAtSameStrain
Fadditional = EffectiveSteelStress * As
```

Для касательной матрицы:

```text
EffectiveTangent = SteelTangent - ConcreteTangentAtSameStrain
```

Этот подход должен быть проверен контрольным тестом против модели, в которой площадь арматуры геометрически исключена из бетона.

Проверять:

- центр стержня находится внутри сечения;
- весь диаметр стержня находится внутри контура;
- соблюдён защитный слой;
- стержни не пересекаются;
- отсутствуют дубли координат.

---

# 12. Модели материалов

Расчётное ядро не должно содержать конкретных диаграмм материалов.

Создать интерфейсы:

```text
IConcreteMaterial
ISteelMaterial
```

Минимальные методы:

```text
GetStress(strain, calculationMode)
GetTangentModulus(strain, calculationMode)
GetSecantModulus(strain, calculationMode)
CheckLimitState(strain, stress, calculationMode)
```

Основные режимы:

```text
StrengthULS
CrackWidthSLS
```

Режим `CrackFormationSLS` не создавать.

## 12.1. Прочность

В режиме `StrengthULS`:

- использовать нормативную диаграмму сжатого бетона;
- использовать нормативную диаграмму арматуры;
- контролировать предельные деформации;
- фиксировать причину исчерпания прочности;
- растянутый бетон не учитывать, если это соответствует выбранной нормативной постановке.

При выключении растянутого бетона одновременно принимать:

```text
Stress = 0
TangentModulus = 0
```

Нельзя оставлять ненулевую жёсткость растянутого бетонного волокна при нулевом напряжении.

## 12.2. Ширина раскрытия трещин

В режиме `CrackWidthSLS`:

- считать сечение трещиноватым;
- сжатый бетон учитывать;
- растянутый бетон не учитывать во внутренних усилиях;
- растянутый бетон должен иметь нулевую касательную жёсткость;
- учитывать всю продольную арматуру;
- определять эксплуатационные напряжения и деформации стержней;
- учитывать нормативные коэффициенты только после подтверждения конкретным пунктом СП.

# 13. Основной решатель НДМ

Создать основной класс:

```text
CSectionSolver
```

Он не должен знать тип геометрии, адреса ячеек, названия листов, конкретный класс бетона и конкретную нормативную таблицу.

Входные данные:

- массив бетонных волокон;
- массив арматурных стержней;
- модель бетона;
- модель арматуры;
- режим расчёта;
- внешние усилия;
- настройки решателя;
- начальное приближение.

Основной алгоритм:

1. принять `epsilon0`, `kappaX`, `kappaY`;
2. рассчитать деформации бетонных волокон;
3. рассчитать деформации арматурных стержней;
4. получить напряжения материалов;
5. просуммировать `Nint`, `Mxint`, `Myint`;
6. вычислить `ResidualN`, `ResidualMx`, `ResidualMy`;
7. проверить критерии сходимости;
8. построить касательную матрицу;
9. решить систему `3 × 3`;
10. получить `DeltaEpsilon0`, `DeltaKappaX`, `DeltaKappaY`;
11. применить демпфирование;
12. повторять до сходимости, физического предельного состояния или диагностируемой численной остановки.

Основной метод решения:

- полный метод Ньютона;
- касательная матрица;
- пересчёт касательной матрицы на каждой итерации;
- демпфирование шага;
- line search;
- пошаговое приложение нагрузки;
- использование результата предыдущей ступени как начального приближения.

Не использовать полный перебор трёх параметров как основной метод.

Полный или локальный перебор допускается только для грубого начального приближения, тестирования, проверки метода Ньютона или аварийного локального механизма.

Резервные алгоритмы:

- модифицированный Ньютон;
- секущая матрица;
- уменьшение шага нагрузки;
- ограничение максимальных приращений;
- локальный грубый поиск;
- повторный запуск с другим начальным приближением.

Не считать любую потерю сходимости признаком разрушения.

Различать:

- достижение предельной деформации;
- достижение предельного напряжения;
- максимум несущей способности;
- численную несходимость;
- вырожденность матрицы;
- плохую обусловленность;
- ошибку исходных данных.

---

# 14. Решение системы уравнений

Не использовать:

```vba
WorksheetFunction.MInverse
```

Реализовать собственное решение системы `3 × 3`:

- с выбором главного элемента;
- с контролем масштаба;
- с диагностикой вырожденности;
- с оценкой обусловленности;
- с проверкой невязки после решения.

Решение матрицы должно быть отдельным модулем или классом.

# 15. Критерии сходимости

Использовать отдельные нормированные критерии:

```text
errorN
errorMx
errorMy
```

Нельзя напрямую складывать силу и момент в одну размерную ошибку.

Результат решателя должен содержать:

- `Converged`;
- число итераций;
- число ступеней нагрузки;
- `epsilon0`;
- `kappaX`;
- `kappaY`;
- внутренние усилия;
- абсолютные и относительные невязки;
- положение и угол нейтральной оси;
- крайние деформации и напряжения;
- критерий предельного состояния;
- причину остановки;
- применённые резервные алгоритмы.

# 16. Поиск несущей способности

Использовать отдельный класс:

```text
CCapacitySolver
```

## 16.1. Расчёт Mx

```text
N  = Nspecified
Mx = lambda * MxBase
My = 0
```

При этом решатель всё равно определяет `epsilon0`, `kappaX`, `kappaY`.

## 16.2. Расчёт My

```text
N  = Nspecified
Mx = 0
My = lambda * MyBase
```

## 16.3. Косой изгиб Mxy

```text
N  = Nspecified
Mx = lambda * MxBase
My = lambda * MyBase
```

При косом изгибе направление вектора моментов должно сохраняться.

Определять:

```text
lambdaUltimate
SafetyFactor = lambdaUltimate
Utilization = 1 / lambdaUltimate
```

При поиске несущей способности:

1. найти допустимое состояние;
2. найти верхнюю недопустимую границу;
3. уточнить предельный множитель устойчивым одномерным поиском;
4. не считать несходимость автоматически разрушением;
5. сохранять подробную причину остановки.

# 17. Расчёт ширины раскрытия трещин

Использовать отдельный класс:

```text
CCrackWidthCalculator
```

Он должен получать уже найденное напряжённо-деформированное состояние трещиноватого сечения.

На вход передавать:

- положение нейтральной оси;
- форму растянутой зоны;
- геометрию сечения;
- деформации и напряжения всех стержней;
- расположение арматуры;
- параметры нагрузок;
- нормативные коэффициенты;
- допустимую ширину раскрытия.

Класс должен определять:

- расчётную растянутую арматуру;
- площадь растянутого бетона, необходимую нормативной формуле;
- эффективную площадь растянутой зоны;
- базовое расстояние между трещинами;
- среднюю деформацию арматуры между трещинами;
- коэффициенты продолжительности;
- коэффициенты профиля арматуры;
- расчётную ширину раскрытия;
- допустимую ширину;
- коэффициент использования:

```text
CrackUtilization = CalculatedCrackWidth / AllowableCrackWidth
```

Отдельный расчёт `Mcrc` не выполнять.

# 18. Работа с несколькими сочетаниями

Архитектура должна позволять рассчитывать несколько сочетаний нагрузок за один запуск.

Минимальная целевая возможность:

- до 20 сочетаний нагрузок;
- единая геометрия;
- единая арматура;
- единые материалы;
- различные `N`, `Mx`, `My`.

Для производительности:

- геометрию строить один раз;
- волоконную сетку строить один раз;
- неизменяемые параметры кэшировать;
- не пересоздавать модели материалов;
- результаты возвращать массивом;
- сочетания обрабатывать одним вызовом управляющего метода.

В дальнейшем допускается реализовать пользовательскую функцию Excel, которая принимает диапазон сочетаний и возвращает двумерный массив результатов.

Такая функция:

- не должна быть `Volatile`;
- не должна обращаться к листам внутри горячих циклов;
- не должна пересчитывать геометрию для каждой выходной ячейки;
- должна вызываться один раз для всего массива сочетаний;
- должна иметь механизм кэширования неизменяемой геометрии и арматуры.

Основная первая версия может использовать кнопку или обычный макрос запуска, если это упрощает отладку и проверку. Возможность функции должна быть предусмотрена архитектурой, но не обязана быть реализована на первом этапе.

# 19. Структура книги Excel

Основные пользовательские листы:

```text

```

Допускаются технические и тестовые листы, но они не должны включаться в основную пользовательскую печатную форму.

## 19.1. Лист `Расчет`

На одном листе должны располагаться четыре горизонтальных блока, слева направо:

```text
[ Исходные данные ] [ Расчёт Mx ] [ Расчёт My ] [ Расчёт Mxy ]
```

Требования к печати:

- формат бумаги — А4;
- ориентация — книжная;
- один блок — одна печатная страница;
- каждый блок должен начинаться с новой страницы;
- при печати всего листа должны получаться четыре отдельные страницы;
- использовать вертикальные разрывы страниц;
- настроить область печати;
- каждый блок вписывать на одну страницу;
- обеспечить одинаковую общую стилистику четырёх страниц.

Не создавать четыре отдельных пользовательских листа.

## 19.2. Блок `Исходные данные`

Выводить только основные параметры, необходимые для лаконичного инженерного оформления:

- объект или элемент;
- тип сечения;
- основные размеры;
- радиусы скруглений;
- класс бетона;
- класс арматуры;
- основные данные армирования;
- компактную таблицу продольной арматуры;
- защитный слой;
- продольную силу;
- `Mx`;
- `My`;
- основные данные сочетания;
- допустимую ширину раскрытия;
- при необходимости геометрическую длину элемента;
- другие основные параметры, необходимые для печатного расчёта.

Не выводить:

- тип решателя;
- шаг сетки;
- настройки демпфирования;
- параметры line search;
- число итераций;
- служебные коэффициенты;
- внутренние допуски;
- параметры диаграмм;
- критерии матрицы;
- технические флаги;
- служебные идентификаторы.

## 19.3. Блок `Расчёт Mx`

Расчётное сочетание:

```text
N = заданное значение
Mx = заданное значение
My = 0
```

Основные результаты:

- продольная сила;
- действующий момент `Mx`;
- удерживающий момент `Mx,ult`;
- коэффициент запаса;
- коэффициент использования;
- положение нейтральной оси;
- размеры или положение сжатой зоны;
- максимальная деформация бетона;
- максимальные напряжения и деформации арматуры;
- критерий исчерпания прочности;
- ширина раскрытия трещин;
- допустимая ширина;
- коэффициент использования по трещинам;
- краткий статус сходимости.

## 19.4. Блок `Расчёт My`

Расчётное сочетание:

```text
N = заданное значение
Mx = 0
My = заданное значение
```

Состав результатов аналогичен блоку `Расчёт Mx`.

## 19.5. Блок `Расчёт Mxy`

Расчётное сочетание:

```text
N = заданное значение
Mx = заданное значение
My = заданное значение
```

Основные результаты:

- действующие `Mx` и `My`;
- предельные `Mx,ult` и `My,ult`;
- коэффициент использования;
- коэффициент запаса;
- угол результирующего момента;
- угол нейтральной оси;
- `epsilon0`;
- `kappaX`;
- `kappaY`;
- максимальные деформации;
- напряжения значимых стержней;
- критерий предельного состояния;
- ширина раскрытия трещин при косом изгибе после реализации и проверки соответствующего алгоритма;
- статус сходимости.

На раннем этапе допускается реализовать расчёт ширины трещин сначала для `Mx` и `My`, а затем для `Mxy`.

# 24. Производительность

Основная стоимость расчёта — многократный проход по бетонным волокнам.

Обязательные меры:

1. не обращаться к Excel внутри расчётных циклов;
2. не обращаться к `Range`, `Cells`, именованным диапазонам и `WorksheetFunction` внутри горячих циклов;
3. считывать данные с листов один раз;
4. записывать результаты одним блоком;
5. использовать типизированные массивы;
6. не использовать `Collection` для десятков тысяч волокон;
7. не создавать тяжёлый объект для каждого волокна без необходимости;
8. не использовать `Variant`, если возможен конкретный тип;
9. не использовать `ReDim Preserve` внутри горячего цикла;
10. предварительно вычислять координаты, площади, произведения координат и неизменяемые множители;
11. не пересоздавать сетку на каждой итерации;
12. кэшировать неизменяемую геометрию;
13. не делать пользовательскую функцию `Volatile`;
14. отключать `ScreenUpdating`, `EnableEvents` и автоматический пересчёт только в управляющем слое;
15. после завершения или ошибки обязательно восстанавливать настройки Excel;
16. сначала обеспечить корректность и диагностику, затем оптимизировать.

# 25. Диагностика

Расчёт должен поддерживать подробный журнал:

```text
Iteration
LoadFactor
Epsilon0
KappaX
KappaY
Nint
Mxint
Myint
ResidualN
ResidualMx
ResidualMy
StepAlpha
MatrixDeterminant
MatrixConditionEstimate
ActiveConcreteFibers
InactiveTensionFibers
YieldedRebars
LimitState
StopReason
```

Журнал должен включаться настройкой и при выключенном состоянии не должен заметно замедлять расчёт.

Не записывать журнал на лист на каждой итерации. Сначала сохранять данные в массив, затем выгружать одним блоком на лист `System`.

Не скрывать несходимость.

Любой результат должен содержать:

- признак сходимости;
- число итераций;
- невязки;
- причину остановки;
- сведения о применённых резервных алгоритмах.

# 26. Верификация

## 26.1. Геометрия

Проверять:

- площадь;
- центр тяжести;
- `Ix`;
- `Iy`;
- `Ixy`;
- главные моменты;
- угол главных осей;
- симметрию;
- граничные точки;
- некорректные размеры и радиусы;
- сходимость при уменьшении шага сетки.

## 26.2. Упругие задачи

При линейных материалах сравнивать с классической теорией сопротивления материалов.

## 26.3. Симметрия

Для симметричного сечения с симметричной арматурой при:

```text
Mx != 0
My = 0
```

проверять:

```text
kappaY ≈ 0
Myint ≈ 0
```

## 26.4. Несимметричное сечение

Для Г-образного сечения при:

```text
Mx != 0
My = 0
```

допускать:

```text
kappaY != 0
```

при выполнении:

```text
Myint ≈ 0
```

## 26.5. Прямоугольное сечение

Сравнивать НДМ с классическим расчётом по СП 35 при максимально одинаковых предпосылках.

Различия объяснять формой диаграммы, дискретизацией, различием секущего и касательного подхода, нормативными коэффициентами и критериями предельного состояния.

## 26.6. Круглое сечение

Сравнивать с программой из:

```text
/reference/round_section/
```

Но не считать её безусловным эталоном.

## 26.7. Произвольное сечение

Сравнивать с программой из:

```text
/reference/arbitrary_section_ndm/
```

## 26.8. Сетка

Проверять изменение результата при последовательном уменьшении шага сетки, например:

```text
50 мм
25 мм
12,5 мм
```

Оценивать изменение площади, центра тяжести, моментов инерции, удерживающего момента, коэффициента использования и максимальных деформаций.

## 26.9. Равновесие

Для каждого принятого результата проверять:

```text
Nint ≈ Next
Mxint ≈ Mxext
Myint ≈ Myext
```

Результат без выполненного равновесия не считать корректным.

## 26.10. Трещины

Сравнивать напряжения растянутой арматуры, положение нейтральной оси, ширину раскрытия и коэффициент использования с ручными расчётами и доверенными программами.

## 26.11. Несколько сочетаний

Для пакетного расчёта проверять:

- совпадение пакетного режима с отдельным расчётом каждого сочетания;
- отсутствие повторного построения геометрии;
- устойчивость к различному порядку сочетаний;
- корректность возвращаемого массива;
- обработку несошедшихся сочетаний без остановки всего пакета.

## Дополнительные проектные решения: нормативные параметры и тестовые нагрузки

Все нормативные коэффициенты и параметры материалов должны быть видимы пользователю на листе `System` и не должны скрываться в VBA-коде.

Рекомендуемая структура таблицы:

```text
Ключ | Значение | Значение по умолчанию | Единица | Назначение | Нормативный источник | Изменено пользователем
```

Для каждого коэффициента или нормативно зависимого параметра указывать:

- наименование или ключ;
- текущее значение;
- значение по умолчанию;
- единицу измерения;
- СП, пункт, таблицу или формулу;
- краткое назначение;
- допустимость изменения пользователем;
- признак изменения пользователем.

При первоначальном создании книги подтвержденные нормативные параметры должны заполняться значениями по умолчанию из СП 35 и СП 63. Если норматив допускает несколько вариантов, можно выбрать вариант, соответствующий принятому контрольному примеру, при условии что источник и область применимости описаны.

Если значение еще не подтверждено пунктом, таблицей или формулой СП, в шаблоне использовать `TODO`, а не числовое предположение.

Пользователь может изменить текущее значение на листе `System`. Расчет должен использовать измененное значение, но диагностика должна указывать, что применено пользовательское значение, отличающееся от нормативного значения по умолчанию. Измененное значение не считается новым нормативным значением по умолчанию.

Сборщик книги и управляющие макросы не должны автоматически перезаписывать измененное пользователем значение без явной команды.

Тестовые нагрузки `N`, `Mx`, `My` могут назначаться произвольно. Они не обязаны быть взяты из справочных программ круглого или произвольного сечения.

Для каждого теста фиксировать:

- `N`;
- `Mx`;
- `My`;
- единицы;
- ожидаемый результат или независимый способ проверки;
- критерий успешного прохождения.

Справочные программы можно использовать как дополнительные сравнительные материалы, но основные модульные тесты должны быть независимыми.

## Дополнительное проектное решение: этап 4 и временные параметры материалов

Открытые нормативные вопросы по формулам диаграмм материалов не блокируют разработку численного нелинейного решателя.

Для разработки и тестирования этапа 4 разрешается использовать временные параметризованные диаграммы и предварительные значения параметров материалов. Такие параметры должны иметь статус:

```text
PROVISIONAL_FOR_SOLVER_TESTING
```

Временные значения по умолчанию:

Бетон B30:

- `Eb = 32500 МПа`;
- `Rb = 15.5 МПа`;
- `Rbt = 1.10 МПа`;
- `Eps1 = -0.0015`;
- `EpsU = -0.0035`;
- работа растянутого бетона в режиме `StrengthULS` отключена.

Обычная ненапрягаемая арматура A400:

- `Es = 200000 МПа`;
- `Rs = 350 МПа`;
- `Rsc = 350 МПа`;
- `EpsY = Rs / Es`;
- `EpsU = 0.025`.

Все временные параметры должны находиться на листе `System`, быть видимыми пользователю, допускать ручное изменение и считываться через `rngSystemSettings`. Они не должны быть единственным образом зашиты в VBA-коде.

Диагностика и результаты расчетов с такими параметрами должны указывать, что расчет выполнен с предварительными параметрами материалов и не является окончательно верифицированным нормативным расчетом.

Различать:

- проверку численного алгоритма;
- предварительные параметры материалов;
- окончательно верифицированные нормативные параметры.

Открытые нормативные вопросы должны быть закрыты до признания результатов окончательно соответствующими СП и до выпуска инженерной версии.
