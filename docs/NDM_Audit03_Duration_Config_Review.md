# Audit03: Дополнительные Нагрузки Устойчивости

## Контракт

Таблица `rngStabilityDurationLoads` содержит ссылку на сочетание и три
компоненты N/Mx/My. Они вводятся в INPUT-единицах и пользовательских знаках
полного сочетания и переводятся только через `CUnitSystem`. Для СП 63 вводится
постоянная плюс длительная часть, для СП 35 постоянная часть. Этот срез
проверяет передачу существующих исходных данных, не меняет нормативные формулы.

Пустая числовая ячейка и отсутствующая строка данного ID означают нулевую
дополнительную часть. Непрочитанный диапазон, ошибочная формула, нечисловой
текст, неопределенное значение и переполнение не эквивалентны пустоте.
Неиспользуемые ID и профили с отключенной устойчивостью не активируют
числовые поля таблицы. Сопоставление ID нечувствительно к регистру; при
повторении используется первая соответствующая строка, как до исправления.

Ошибка компоненты относится только к устойчивости данного LC. Ее meta:
`rsInvalidInput / rcInvalidInput`, `Calculated=False`, внешний `InputErr`
формируется общей policy. Прочность и трещины продолжаются с исходными
усилиями. Writer получает готовый ResultComment, а не определяет статус
по тексту и не восстанавливает адрес по строке шаблона.

Структурно недоступная таблица или ошибочная ссылка Combination ID не позволяют
надежно сопоставить дополнительные нагрузки. Для запрошенной устойчивости
сохраняется адресная причина исправления таблицы или ее имени. Числовые
значения с корректно выбранных строк не публикуются как частичный успешный ввод.

## Ответственные Места

| Владелец | Обязанность |
| --- | --- |
| modWorkbookCalculation.LoadStabilityDurationLoadsFromWorkbook | Чтение реального Range одним массивом, активные ID, адреса ячеек, различение пустоты/ошибки и перевод через CUnitSystem. |
| TryReadDurationLoad | Разбор одной числовой компоненты; только ошибки чтения/переполнения становятся причиной ввода, неожиданные ошибки не маскируются. |
| CBatchSectionCalculator | Хранение нормализованных duration loads и отдельной причины их ввода; ранний отказ только устойчивости соответствующего LC. Сброс при новом чтении. |
| CStabilityCalculator / CStabilityResult | Существующие инженерные формулы, величины и typed результат; новой формулы длительности нет. |
| CResultStatusPolicy / writers | Единственный внешний словарь статусов и размещение готовых comments собственных subtrees. |

Новых классов не добавлено. У существующего workbook-reader изменена
доступность с Private на Public, чтобы его реально использовали и пользовательский
сценарий, и направленный reproducer; параллельный reader в тестах не создавался.

## Отрицательное Доказательство

`duration_negative_v177b_2026-10-03.txt`: `7926 passed / 576 failed`,
606 параметризованных случаев, watchdog exit=1, source unchanged=True.
Production в этой копии сохранял прежнее поведение; изменена только доступность
reader-а, тест не подменял его собственным разбором данных.

- Текст вместо активной N/Mx/My давал необработанный Type mismatch.
- Ошибка формулы могла превращаться в число и давать успешную устойчивость.
- Недоступный диапазон заменялся нулями без InputErr.
- Не сохранялись нужные typed meta, флаг невыполненного расчета и адресная причина.
- Все проверки допустимых чисел, единиц/знаков, компонентов и PhiL прошли.

Первый v177 не дошел до расчетных checkpoints. В новом тесте был использован
зарезервированный идентификатор Variant; v177b исправляет объявление переменной.
Журнал v177 не считается доказательством production-дефекта или PASS.
