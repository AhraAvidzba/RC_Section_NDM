# Audit03: Геометрия Через Config

Дата: 2026-10-03. Срез v134, продолжение K02/F05/F07/D01.
Это адресная приемка, не завершение всего Audit03.

## Воспроизведенный Дефект

В `AppendHollowRectangleMainRebars` наружный счетчик добавлялся только при
`IsNumericSettingText=True`. Текст `abc` и `CVErr(2015)` отбрасывались:
`GetLong(..., 0)` получал отсутствующий ключ, и соответствующая грань
выключалась без ошибки. Это подтверждено на production v133 с новым тестом
в изолированной negative-книге, а не выводом из статического поиска.

Negative v134: `161/40`, watchdog exit=1, source unchanged=True. Все 24
параметра формы прошли; 40 failures относятся к четырем наружным счетчикам:
неверный текст/ошибка Excel не отвергались, отсутствовал адрес Config,
отрицательное значение давало только сообщение builder-а без ключа/ячейки.
Дробь и превышение Long уже отвергались, но также не имели фактического адреса.

Исправление:

- Наружные `.n` сохраняются как исходные значения с фактическими row/column.
- Ошибку формулы перехватывает существующий `ConfigCellText`.
- Нечисловой текст, дробь и непредставимое число проверяет существующий
  `GetLong`; инженерный запрет отрицательного числа остается у builder-а.
- Сообщение отрицательного количества содержит Config, ключ, ячейку,
  физическую грань и способ исправления.
- Служебные количества у отверстия не читаются как пользовательский ввод:
  число определяет проекция наружной арматуры.
- Пустая ячейка и 0 сохраняют выключение наружной грани.

## Направленные Проверки

`modTestGeometryConfig.RunAudit03ShapeConfigTests` проверяет реальные таблицы:
6 параметров RectSet, 10 RoundedRectangle, 8 HollowRectangle и 4 наружных n.
Новых классов нет; тесты добавлены в существующий standard module и UI-suite.

Проверены активные изменения площади/центра/габаритов, недопустимые значения,
recovery, неактивные таблицы при Circle, три режима RectSet, игнорирование
W/R2 при Simple и смещения в Rectangle/LSection, эквивалентный ввод mm/cm.
Каждая тестовая таблица восстанавливается по исходным Formula-массивам.

Для счетчиков проверены 3 -> 4 на конкретной наружной грани, blank/0,
`abc`, -1, 0.5, CVErr и 2147483648; после каждого отказа повторен нормальный
ввод. Общий ненулевой layout не используется как доказательство сохранности
счетчика: проверяется его собственная `BarAnnotationGroupName`.

Первый positive gate: `201/0`. Окончательный расширенный: `213/0`,
watchdog exit=0, source unchanged=True. Независимые контрольные значения
проверяют площадь и центр RectSet, центр симметричного RoundedRectangle,
площадь и центр смещенного HollowRectangle.

У HollowRectangle уточнены только комментарии к площади/центру: они берутся
по polygon-представлению, как у RoundedRectangle. Каждая четверть дуги имеет
12 хорд; независимый oracle использует этот утвержденный контракт.
Математика геометрии, число сегментов и mesh/solver tolerance не менялись.

## Открытые Геометрические Gates

Остаются полный контракт blank/error-cell/missing для размеров/enum,
непрерывные геометрические границы, остальные поля армирования и pairwise.
Runtime-default в evidence фиксирует фактический вызов, а не окончательное
одобрение скрытого fallback отсутствующей обязательной настройки.

Дополнительно выявлены кандидаты F07 для следующего цельного среза:
`barCount + 1`, суммы `mRequestedCount` и `nextIndex` в некруглых builders.
Их ранняя представимость и предельные сочетания количества еще не приняты;
данный positive gate не проверяет миллиардное построение/практическую память.

## Счетчики Некруглых Builders v135

Предыдущий Config-срез принят коммитом `78fd486`. Следующий общий F07 gate
проверяет счетчики RectSet, RoundedRectangle и HollowRectangle до размещения.
Negative на production v134: `7/18`, source unchanged=True. В двух случаях
с корректными размерами/отступами получен настоящий VBA Overflow=6:
RoundedRectangle H и HollowRectangle B, n=2147483647, выражение `n + 1`.
В остальных случаях неверный отступ специально завершает старый маршрут
до огромного массива/цикла. Их лог доказывает отсутствие ранней проверки,
но не является наблюдением исчерпания памяти или миллиардного построения.

Исправления не вводят нормативный предел количества арматуры:

- Чистый численный helper считает запрошенные позиции в Double до удаления
  дублей, включая активные дополнительные ряды и нечетные EverySecondBar.
- Каждый builder до размещения сверяет сумму с технической границей Long,
  оставляя представимым следующий шаг обхода. Выключенные линии не участвуют;
  нижние грани режима Rectangle остаются неактивными.
- Наружный запрос Hollow проверяется до накопления массивов проекций.
  Количество Opening по-прежнему определяется фактическими проекциями;
  его не подменяют завышенной предварительной оценкой.
- CRebarLayout дополнительно проверяет фактический счетчик до добавления,
  включая проекции Opening и импорт. Эта редкая предельная ветвь просмотрена
  статически: тест не создает миллиарды реальных стержней ради достижения ее.
- Пользователь получает русское сообщение с блоком Config, количеством
  и указанием уменьшить запрос/число активных рядов вместо VBA Overflow.

Directed positive `29/0`, source unchanged=True: девять ранних отказов,
выключенные линии, обычное восстановление трех builders, неактивные нижние
грани и независимая арифметика Even/Odd/MaxLong. Не менялись координаты

Общие численные assertions с v134 `5577/5577`, missing=0, differences=0.
Полный On `23335/0`, все восемь suites; общие числа с v134 `5582/5582`,
missing=0, differences=0. Universal `827/0`, palette `351/0`: Results и
