# Audit03: Ревизия ResultComment

Статус на 2026-10-02: содержательная ревизия продолжается. Это не финальная приемка.

## Адресные Причины Ввода v141-v143

910 LC-cases нового полного адресного набора читают готовый OverallComment
и сравнивают его с фактической ячейкой batch writer-а. Ошибки ID, профиля,
N/Mx/My, пути, пользовательского комментария и overflow пересчета должны
содержать фактический адрес Config; путь и причина формируются reader-ом.
Первый завершенный negative `9863/424` обнаружил 420 потерянных адресов.
Повтор после reader-fix `10283/4` устранил именно их, не скрыл два реальных
Capacity NumFail. Типизированный журнал указал место numerical failure.
После подключения retained-boundary для LambdaN с fixed моментами и
повторного общего Newton из сохраненной противоположной деформации
directed `11021/0`: все 910 cases, физические Capacity/Formation points,
Results save/reopen=True, source unchanged=True. Полные Off/On gates этого
среза выполняются отдельно; весь F05 этим набором не закрывается.

Открытый scope-дефект: общий reader InputErr повторяется в отключенных
Capacity/Stability branches. Он не исправляется текстовой подменой в writer;
нужен направленный тест применимости ветвей при известном/неизвестном
профиле и сохранение причины в ответственном result-tree.

`5601/5601` и `5606/5606`, missing=0, differences=0. Clean/update help
`2559/2559`, объединения совпадают; обе книги `27/27` read-only checks.
Palette `351/0` и Universal clean On `827/0`, Results save/reopen=True.
Этот срез не является окончательной приемкой остальных ResultComment.

- Читается каждый фактический leaf/meta, в том числе комментарий успешного результата.
- Отказы, блокировки и предупреждения требуют русской причины с указанием расчетной стадии.
- Strength, Crack и Stability получают только комментарии своего subtree; Batch получает их согласованную совокупность.
- Writers и txt-report выводят готовые комментарии, не назначают статусы по тексту и не придумывают инженерные причины.
- Полная причина сохраняется в зависимом leaf. В сводном Crack/Batch одна общая причина текущего НДС не должна повторяться для каждой blocked-проверки.
- Auto сохраняет причины предыдущих путей и фактически принятый путь; fixed path не подменяется другим.
- Проверяются реальные четыре output-блока, execution report и сохраненный/повторно открытый Results.

Directed `444/0` и фактический batch `240/0` дополнены явными assertions:
подтвержденный NotCracked сохраняет заданный PsiS=0.25, включая режим User;
комментарии Width и Batch не содержат предупреждения psi=1. Формула не
вызывается, поэтому в Results ячейки примененного psi и рассчитанной ширины
остаются пустыми. Results и status-style после save/reopen совпали; исходная
тестовая книга не изменилась. Production после v136 не менялся.

Переключение Stability.Code между SP35/SP63 в этих случаях проверяет только
независимость gate от методики устойчивости. Оно не выбирает норму формулы
ширины: текущая Width-реализация использует СП63. Нельзя подавлять ее реально
примененное предупреждение только из-за Stability.Code=SP35 или выдавать этот
тест за проверку еще не реализованной формулы ширины СП35.

Пользователь подтвердил, что ширина по СП35 относится к отдельному будущему
этапу и цели, не к текущему Audit03. Для этого этапа сохраняется контракт:
предупреждение о psi=1 выводится только если коэффициент фактически принят
и использован; формула без коэффициента такого предупреждения не получает.

## Сверка Численных Эталонов С Baseline

Статический `expected_preservation_required_geometry_v137_2026-10-03.txt`
сравнил AssertClose с baseline `df10412f`: 540 выражений/допусков неизменны,
две записи одного метода требуют явной инженерной сверки. Сырой gate имеет
exit=1 и не объявляется зеленым. В TestAudit02PsiSignedInputsAndFallbackModes
прежние две условные записи `.value` (User=0.65, остальные=1) заменены одной
записью 1 для каждого из трех режимов; абсолютный допуск 0 не изменен.

Это согласованное изменение fallback при отсутствии пригодной Formation-точки,
а не подгонка физического эталона: пользователь потребовал psi=1 и предупреждение
при продолжении Width по допустимому текущему НДС. После объединения путей
фиксированный Mxy при единственной силе N имеет нулевую масштабируемую часть:
Formation сохраняет rcInvalidInput, фиктивный Post не создается, но Width
продолжается по утвержденному fallback. Случай отличается от подтвержденного
NotCracked, который вообще не вызывает формулу и сохраняет User PsiS.
Три `.value`, `.warningComment`, `.noPost` и `.formationCode` проверяются
реальным Crack-suite текущего Off/On. Остальные физические expected/tolerance
этой сверкой не изменены; объединение двух синтаксических записей не является
удалением соответствующих трех параметризованных runtime-сценариев.

## Ошибочный Ввод При NotCracked v139

В прежнем production ранний подтвержденный NotCracked оставлял 20 неверных
селекторов/неположительных коэффициентов без InputErr и комментария. Final
negative `1515/120` и positive `1635/0` используют один oracle для 55 вариантов
десяти настроек, адресов Config, отсутствия solve и восстановления обычного
NotCracked. Первый negative `1480/155` содержал также 35 ошибок oracle popup:
сообщение показывает отдельную причину ввода, не склейку всего OverallComment.
Ни этот первый лог, ни его неверный oracle не переписываются задним числом.

Ошибку диапазона/режима формирует Width; reader добавляет место ввода.
Batch не анализирует текст для решения о допустимости или назначения статуса.
Корректный NotCracked по-прежнему сохраняет исходный PsiS, не вызывает формулу
и не получает предупреждение psi=1. Ширина СП35 не добавлялась. Полные suites
Off/On завершены `26264/0` и `26275/0`; общие actual-числа с v137 совпали
в 5601/5606 assertions без пропусков. Чистая сборка и окончательная приемка
после этого изменения еще выполняются.
