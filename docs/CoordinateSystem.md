# CoordinateSystem

Дата актуализации: 2026-09-21.

## Пользовательская Точка Приложения

Пользовательские усилия `N`, `Mx`, `My` задаются относительно центра тяжести бетонного сечения плюс оффсеты `Load.ReferenceOffsetX` и `Load.ReferenceOffsetY`.

Центр тяжести бетонного сечения определяется по бетонной волоконной сетке без учета продольной арматуры. Это соответствует обычной привязке внешней расчетной модели к оси бетонного элемента.

При `Load.ReferenceOffsetX = 0` и `Load.ReferenceOffsetY = 0` чистая осевая сила приложена через центр тяжести бетона. Для симметричного армирования это обычно не создает кривизну. Для несимметричного армирования бетонный и приведенный центры могут не совпадать, поэтому небольшая кривизна может быть физическим следствием выбранной точки приложения силы.

Для расчета продольного изгиба и устойчивости действует дополнительный
нормативный перенос: СП 35 и СП 63 задают эксцентриситет продольной силы
относительно центра тяжести приведенного сечения бетон + арматура. Поэтому
пользовательский ввод остается привязанным к бетонному центру, но перед
`CStabilityCalculator` программа переносит моменты к приведенному центру
выбранного набора характеристик материала.

Перед запуском решателей моменты переносятся в рабочие координаты волокон.
Эту математику централизует `CSectionLoadState`, чтобы DirectState, Capacity,
Crack и Stability не считали смещение точки приложения нагрузки каждый по-своему:

```text
Mx_internal = Mx_user + N * (Yaxial + Load.ReferenceOffsetY)
My_internal = My_user + N * (Xaxial + Load.ReferenceOffsetX)
```

Где `Xaxial`, `Yaxial` - координаты центра тяжести бетонного сечения.

## Точка приложения пользовательских нагрузок

В таблице `rngLoadCombinations` пользователь задает `N`, `Mx`, `My` относительно фактического центра тяжести построенной бетонной волоконной сетки с учетом оффсета:

```text
Xref = Xcentroid(mesh) + Load.ReferenceOffsetX
Yref = Ycentroid(mesh) + Load.ReferenceOffsetY
```

Если `Load.ReferenceOffsetX = 0` и `Load.ReferenceOffsetY = 0`, моменты пользователя относятся к центру тяжести бетонной сетки для любой поддерживаемой геометрии: `Circle`, `RectSet`, `RoundedRectangle`, `HollowRectangle` и импортированной AutoCAD-сетки.

Расчетное ядро по-прежнему суммирует моменты относительно текущих координат волокон. Поэтому перед запуском решателей входные моменты переносятся:

```text
Mx_internal = Mx_user + N * Yref
My_internal = My_user + N * Xref
```

## Внутренние единицы

Пользовательские единицы задаются на листе `Config` в `rngUnitSettings`. Перед расчетом все внешние данные переводятся во внутренние единицы; перед выводом результаты переводятся в выбранные `OUTPUT`-единицы.

| Величина | Единицы |
|---|---|
| Длина | мм |
| Площадь | мм2 |
| Сила | Н |
| Момент | Н*мм |
| Напряжение | МПа = Н/мм2 |
| Деформация | безразмерная |
| Кривизна | 1/мм |

Пользовательские пересчеты выполняются только при вводе и выводе. Расчетное ядро работает во внутренних единицах.

По умолчанию пользовательский ввод нагрузок выполняется в `tf` и `tf*m`, а вывод также настроен на `tf` и `tf*m`. Это только настройка интерфейса; внутри используются `N` и `N*mm`.

## Оси

Используется локальная декартова система `X, Y` с координатами в миллиметрах.

Для параметрических генераторов локальная система задается самим типом сечения. Для импортированной AutoCAD-сетки координаты берутся из чертежа в миллиметрах.

## Знаки

Пользовательская система знаков задается на листе `Config` в `rngSignConventionSettings`. Она едина для ввода и вывода. Внутренняя система фиксирована:

| Величина | Внутренний положительный знак |
|---|---|
| `+N` | растяжение |
| `+Mx` | растяжение зоны `+Y` |
| `+My` | растяжение зоны `+X` |

По умолчанию для пользователя `+N` означает сжатие. Поэтому положительная сжимающая сила в `tf` перед расчетом преобразуется в отрицательное внутреннее значение в `N`.

В коде принята формула:

```text
epsilon(x, y) = epsilon0 + kappaX * y + kappaY * x
```

Сжатие бетона в текущих диаграммах задается отрицательными деформациями и отрицательными напряжениями.

Моменты внутренних усилий суммируются как:

```text
Mx = F * y
My = F * x
```

Знак внешних `N`, `Mx`, `My` сначала преобразуется из пользовательской системы знаков во внутреннюю. `CLoadCase` и решатели не должны знать о пользовательской системе знаков.

## Перенос начала координат

При переносе начала координат на:

```text
x' = x - dx
y' = y - dy
```

кривизны физически не меняются:

```text
kappaX' = kappaX
kappaY' = kappaY
```

Параметр `epsilon0` меняется:

```text
epsilon0' = epsilon0 + kappaX * dy + kappaY * dx
```

Моменты относительно нового начала должны быть преобразованы согласованно с принятой формулой моментов. Это проверяется регрессионным тестом `origin_shift`.

## Результирующий момент

Для capacity:

```text
MomentUltimate = Sqr(MxUltimate^2 + MyUltimate^2)
```

В выводе на лист `Results`, на Excel-схему и в AutoCAD моменты переводятся из внутренних `Н*мм` в выбранную пользователем единицу `OUTPUT` для `Moment`.

Геометрический масштаб AutoCAD фиксирован: координаты, размеры, диаметры,
контур, оси и точка приложения нагрузки экспортируются всегда в мм,
независимо от `Units.Length.Output`. Одна единица чертежа соответствует 1 мм.
При импорте геометрия Region тоже читается в мм/мм2/мм4 независимо от INPUT.
Координаты X/Y и размеры трактуются как мм, Area - как мм2, моменты и
произведение инерции - как мм4. Масштаб по INSUNITS не определяется:
численные характеристики бетонных и арматурных Region должны соответствовать
миллиметрам до импорта. Изменение INPUT/OUTPUT не конвертирует исходный DWG.
Это не относится к введенному на Config порогу `AutoCAD.Import.MinArea`:
он задается в выбранной INPUT-единице площади и переводится в мм2 перед
сравнением с площадью Region. Например 25 mm2 = 0.25 cm2 = 0.000025 m2.
Export reader восстанавливает внутренние мм/мм2/мм4 из единиц сохраненного
Results; текущие OUTPUT-настройки не меняют уже сохраненный расчетный снимок.
При импорте writer записывает геометрию в текущих OUTPUT-единицах. После
смены единиц расчет восстанавливает старый snapshot по его заголовкам и
записывает новые результаты в новых OUTPUT-единицах, без повторного импорта.
Это правило масштаба геометрии не заменяет единицы расчетных значений в подписях.
