# MathematicalModel

Дата актуализации: 2026-08-05.

## Основная постановка

Расчет выполняется только для общей задачи:

```text
N + Mx + My
```

Одноосные случаи являются частными:

```text
N + Mx при My = 0
N + My при Mx = 0
```

Отдельных расчетных ветвей `SolveMx`, `SolveMy`, `SolveMxy` нет.

## Гипотеза плоских сечений

Поле продольных деформаций:

```text
epsilon(x, y) = epsilon0 + kappaX * y + kappaY * x
```

Неизвестные:

- `epsilon0`;
- `kappaX`;
- `kappaY`.

## Внутренние усилия

Для бетонных волокон:

```text
epsilon_i = epsilon0 + kappaX * y_i + kappaY * x_i
sigma_i = Concrete.GetStress(epsilon_i)
F_i = sigma_i * A_i
Mx_i = F_i * y_i
My_i = F_i * x_i
```

Для арматуры:

```text
epsilon_s = epsilon0 + kappaX * y_s + kappaY * x_s
sigma_s = Steel.GetStress(epsilon_s)
sigma_c = Concrete.GetStress(epsilon_s)
F_s = (sigma_s - sigma_c) * As
Mx_s = F_s * y_s
My_s = F_s * x_s
```

Так учитывается нелинейное замещение бетона арматурой.

Суммарное равновесие:

```text
Nint  = Next
Mxint = Mxext
Myint = Myext
```

## Прямой нелинейный решатель

`CSectionSolver` поддерживает:

- `Newton`;
- `Secant`.

`Newton` строит касательную матрицу `3 x 3`, решает систему через `CLinearSystem3x3`, применяет ограничения приращений и line search.

`Secant` является отдельной веткой прямого решателя с приближенной матрицей чувствительности и контролируемыми рестартами.

Численная несходимость фиксируется как `NumericalFailure` и не считается физическим разрушением.

## Линейный матричный режим


Он решает линейную систему по упругим жесткостям и возвращает НДС для заданных `N`, `Mx`, `My`. Поиск несущей способности и расчет трещин в этом режиме не выполняются.

## Несущая способность: универсальная λ-траектория

Для каждого сочетания пользователь выбирает `CapacityLoadPath`: какие
компоненты нагрузки надо умножать на предельный множитель `lambda`.
Расчетная постановка одна:

```text
N  = N0  + lambda * Nbase
Mx = Mx0 + lambda * Mxbase
My = My0 + lambda * Mybase
```

Частные случаи:

- `λ*Mx`: масштабируется только пользовательский `Mx`, `N` и `My` остаются постоянными;
- `λ*My`: масштабируется только пользовательский `My`, `N` и `Mx` остаются постоянными;
- `λ*Mxy`: масштабируются оба пользовательских момента `Mx/My`, `N` остается постоянной;
- `λ*N`: масштабируется продольная сила, а момент от ее эксцентриситета масштабируется вместе с `N`;
- `λ*NMxy`: масштабируется весь вектор внутренних усилий текущего LC.

Если точка приложения `N` смещена от центра тяжести бетонного сечения, момент
от эксцентриситета относится к той же части траектории, что и сама `N`. При
`λ*N` и `λ*NMxy` он масштабируется; при `λ*Mx`, `λ*My` и `λ*Mxy` остается в
постоянной части, потому что `N` в этих режимах не масштабируется.

## Несущая способность: Auto

`Capacity.SolutionStrategy = Auto` для обычных моментных и смешанных траекторий сначала
запускает `UltimateStrain` для выбранной λ-траектории. Если этот прямой поиск
предельной плоскости деформаций не сошелся численно, программа повторяет
расчет через `LoadMultiplier` по той же самой траектории
`N0/Mx0/My0 + lambda * Nbase/Mxbase/Mybase`.

Такой fallback не меняет физический критерий предельного состояния и не
добавляет искусственную прочность. Он только выбирает более устойчивый
численный путь для случаев, где `UltimateStrain` плохо определен, например
при чистой продольной силе на горизонтальном плато диаграммы материала.

Для силовой осевой траектории `λ*N`, а также для `λ*NMxy` при нулевых
пользовательских моментах `Mx/My`, batch сразу использует одномерный
`LoadMultiplier`. Причина в том, что осевая предельная сила на плато может не
задавать единственную предельную плоскость деформаций: разные близкие
равномерные деформации соответствуют одной и той же силовой границе.
Фактический метод, который дал результат, выводится в Results в поле
`CapacitySolutionMethod`.

## Несущая способность: LoadMultiplier

Алгоритм:

1. Проверить допустимость исходных данных.
2. Проверить состояние при `lambda = 0`.
3. Расширять верхнюю границу `lambda` до физического предельного состояния или `Capacity.MaxLambda`.
4. Уточнить предельное значение выбранным методом:
   - `Bisection`;
   - `Brent`;
   - `Secant`.
5. Возвращать последний физически допустимый результат.

Целевая функция:

```text
f(lambda) = CriticalStrainUtilization(lambda) - 1
```

## Несущая способность: UltimateStrain

Метод решает состояние, в котором одновременно выполняются:

- равновесие по постоянным компонентам выбранной траектории;
- одинаковый `lambda` для всех масштабируемых компонент выбранной траектории;
- критический бетон или арматура достигает предельной деформации.

Критический элемент определяется заново на каждой итерации.

После нахождения `lambdaValue` результат записывается только если:

```text
0 < lambdaValue <= Capacity.MaxLambda
```

Иначе возвращается `NumericalFailure`, без частичного заполнения предельных
компонент `Nultimate`, `MxUltimate`, `MyUltimate`.

## Предельные состояния

Различаются:

- `ConcreteStrainLimit`;
- `ConcreteTensionStrainLimit`;
- `SteelStrainLimit`;
- `NumericalFailure`;
- `SingularTangent`;
- `InvalidInput`.

## Трещины

`CCrackWidthCalculator` получает исходное раскрытое НДС текущего LC уже готовым от batch-конвейера. В режиме `Auto`, если первая проверка с `psi_s = 1` не проходит, внутри калькулятора выполняется специальная ветвь Mcrc. Для общего случая с изгибной эпюрой ищется `BeforeMcrcState` с растянутым бетоном, затем отдельно решается `AfterMcrcState` без растянутого бетона для определения `sigma_s,crc`. Для истинного центрального растяжения порог трещинообразования определяется по расчетной силе `Ncrc`; в этом случае `BeforeMcrcState` не создается, а для проверки `sigma_s,crc` решается состояние сразу после появления трещины `AfterMcrcState`.

Расчет относится к продолжительному раскрытию нормальных трещин по II группе. При `SLS.Crack.PsiMode = User` раскрытие считается по уже найденному НДС текущего LC, а `psi_s` берется из `SLS.Crack.PsiS`. При `SLS.Crack.PsiMode = Auto` программа сначала делает проверку с `psi_s = 1`; только если раскрытие не проходит, дополнительно определяется уровень нагрузки, при котором появляется трещина. Для двузначной эпюры принимается `eps_bt,ult = eps_bt2`; для однозначно растянутой эпюры с ненулевой кривизной используется формула (8.54); центральное растяжение идет отдельной веткой через `Ncrc`. В общей изгибной ветке сохраняются `BeforeMcrcState` и `AfterMcrcState`; в центральной ветке `BeforeMcrcState` не создается, а `AfterMcrcState` сохраняется, если он нужен для `sigma_s,crc`. Отдельный самостоятельный расчет `Mcrc` вне проверки трещин не поддерживается.

Текущий расчет трещин использует:

- растянутую арматуру;
- максимальную растягивающую деформацию и напряжение стали;
- настройки `SLS.Crack.*`: включение расчета, `a_crc,ult`, режим `psi_s` и способ выбора зоны `Abt`;
- отдельная прозрачная методика расчета трещин будет оформлена после уточнения нормативного алгоритма.
