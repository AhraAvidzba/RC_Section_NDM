# Адресное чтение результатов

`Results.SnapshotStorage` выбирает источник: Excel или File. Схема и экспорт выбирают сочетание, профиль и состояние из каталога, затем читают только соответствующие участки. Несмежные участки одного ключа сохраняются в исходном порядке. `indexOnly` возвращает первую исходную строку каждой пары сочетание/состояние, без загрузки остальных строк. Не найденное состояние даёт только шапку.

`CResultBlockIndex` задаёт общие правила ключей и относительных строк. `CResultReadSource` представляет выборочный источник и не является полным `CCalculationSnapshot`. Полное восстановление вызывается явно. После расчёта вывод использует подготовленный снимок из памяти; постоянного кэша всего расчёта между командами нет.

## File: NDMSNP06

Последовательность записи: заголовок, общие таблицы, независимые блоки состояний, общий словарь ElementID/MaterialType, каталог, footer. Относительные строки, смещения, размеры и SHA256 блоков накапливаются при записи. Общее перечисление элементов не повторяется в каждом состоянии. Числовые колонки сохраняются как Double; смешанные значения, Unicode, пустые строки и отрицательный ноль поддерживает общий колонковый кодек.

- Заголовок 96 байт: `NDMSNP06`, Long-версия 6, Double RunID/ElapsedSeconds, Long-число таблиц; затем 64 ASCII-символа SHA256 первых 32 байт.
- Каталог: матрица из 17 колонок — ключ, вид блока, нулевое смещение, размер, SHA256, строки, колонки, относительная первая строка и девять ячеек представительской строки. RunID общих записей связывает каталог с заголовком.
- Footer 88 байт: Long-смещение/размер каталога, Double RunID, SHA256 каталога, `NDMIDX06`.
- Отдельный блок состояния: число строк, четыре общих ключа; адресация общего словаря элементов; strain/stress; колонка физического состояния. При совпадающей последовательности ID она не повторяется. Разные количества и порядок элементов используют собственный вектор индексов.

Адресный просмотр проверяет заголовок, каталог, размеры/границы и SHA256 прочитанных блоков. **Это не полная проверка файла:** повреждение непрочитанного состояния выявляется при его выборе, при `CCalculationSnapshotStore.VerifyFile(workbook)` либо полном `LoadFile`. Полное восстановление дополнительно проверяет семантику всех таблиц.

Запись идёт через собственный `.part` и атомарную замену. Занятый чужой `.part` не удаляется. Привязка v6 использует идентичность каталога без полного SHA-прохода; обновление времени изменяет заголовок и его SHA. Save As переносит только подтверждённый снимок, проверяет все блоки копии и не подменяет другой файл назначения. Смещения/размеры представлены Long: файл ограничен адресуемым диапазоном до 2 ГиБ.

NDMSNP04/05 и расширение `.ndms` читаются без конвертации. Для них используется полное чтение с общей SHA256. `.ndm` имеет приоритет; повреждённый `.ndm` не подменяется `.ndms` или листом.

## Excel

Видимая девятиколоночная `rngNDMElementResults` записывается одним массивом. Существующие таблицы имеют собственные фиксированные схемы, поэтому каталог размещён в одном новом якоре `rngNDMElementResultIndex` справа от аннотаций с двумя пустыми столбцами. В шаблоне это **Results!DL156:DY…**; координаты берутся из `WorkbookLayout.json`. Runtime использует именованные якоря и относительные строки.

Каталог `NDMResultIndex02` содержит шапку, строку RunID/размеров/числа блоков и одну запись на фактический непрерывный участок. Границы собираются при формировании результатов. При выборе читаются малые метаданные и только нужные диапазоны Offset/Resize/Value2. Поиска высоты по всему RunID-столбцу нет. Проверяется ключ **каждой** выбранной строки.

Результаты элементов и индекс защищены от ручной сортировки, вставки/удаления и редактирования; остальные области доступны, работа схемы не блокируется. Это структурная защита, не криптографическая. Рабочие макросы восстанавливают UserInterfaceOnly после открытия. Снятие защиты или удаление опубликованного индекса вызывает явный отказ. Внешняя автоматизация, намеренно обходящая защиту, должна заново публиковать индекс вместе с таблицей; произвольные правки результатов таким способом не поддерживаются.

Перед новой записью индекс становится Invalid. Частичная запись не возвращает прежние или смешанные результаты. Очистка удаляет состояния. Перенос целой таблицы средствами VBA с обновлением имени сохраняет относительную адресацию. В книге без индекса допустимо однократное построение по четырём ключевым столбцам и представительским строкам; затем книгу нужно сохранить. Противоречивый опубликованный индекс молча не перестраивается.

Оформление использует общий `CNDMResultsWriter.FormatResultsBlock` и `General.ReformatResultsEnabled`. Ширины задаёт только сборщик.
