# Независимые этапы работы книги

Статус: реализовано и проверено 21.10.2026. Исходная версия — `c941afac`,
безопасная точка Git — `ndm-before-section-workflow-20261021`. Книга сохраняет
пользовательские входные данные и прежние Results; перед следующим расчётом
нужно явно нажать «Сформировать сечение».

## Пользовательские команды

1. **Сформировать сечение** — читает Geometry.Source. Для Generated строит
   сечение по выбранной таблице листа «Сечения»; для AutoCAD импортирует
   активный чертёж. Сохраняет полный снимок в Results без расчёта сочетаний
   и сразу показывает его через существующую функцию предварительной схемы,
   если Plot.Enabled = Yes. Флаг автообновления после расчёта здесь не используется.
2. **Выполнить расчёт** — читает сохранённый снимок и текущие расчётные
   настройки, материалы, профили и нагрузки. Не генерирует и не импортирует
   геометрию. После записи результатов обновляет схему по прежним флагам
   Plot.Enabled / Plot.AutoUpdateAfterCalculation.
3. **Обновить схему** — читает Results; до расчёта показывает сформированную
   геометрию, после расчёта — выбранное сохранённое НДС.
4. **Экспорт в AutoCAD** — использует сохранённый Results, без повторного
   получения геометрии и без расчёта.
5. **Очистить подписи в AutoCAD** — удаляет только оформление. Если в активном
   чертеже нет целевых слоёв, завершается до обхода ModelSpace.

Положение кнопок задаётся при сборке через WorkbookLayout.json.
Изменение Geometry.Source, Geometry.Type, размеров, армирования или сетки
не меняет уже сформированное сечение. Для применения этих правок требуется
снова нажать первую кнопку. Отсутствующий снимок вызывает понятную ошибку;
автоматического получения новой геометрии внутри расчёта нет.

## Сохранённые данные

Координаты остаются в rngNDMSectionGeometry, достоверные границы — только
в rngNDMSectionContours. Отдельная таблица метаданных удалена. Геометрия
содержит 16 столбцов: прежние 15 и необязательный ExtraData. Все обязательные
числа находятся в отдельных ячейках. В ExtraData записывается JSON только
со сведениями об источнике: исходное имя/handle, обозначение материала,
класс стали и связь с правилом расстановки. Эти сведения не определяют
численные материалы: диаграммы по-прежнему задаются расчётными настройками.

Аннотации содержат 24 столбца: прежние 22, CoordinateUnit и ExtraData.
CoordinateUnit сохраняет единицы координат независимо от переключения OUTPUT.
Необязательный JSON сохраняет исходный текст, значение, единицу и комментарий
аннотации, чтобы повторное оформление не округляло уже округлённый текст.
Без JSON схема использует готовую подпись; без оформительских аннотаций расчёт
восстанавливает модель по числам геометрии и контурам. Области взаимодействия
трещин в аннотациях — результаты, они не подменяют исходную бетонную область.

Минимальное чтение использует три таблицы: свойства, геометрию и контуры.
Оно не разбирает JSON и комментарии. Полное восстановление дополнительно
читает аннотации. Обязательные 14 полей геометрии проверяются адресно;
отсутствие необязательных столбцов Comment/ExtraData допускается.

При расчёте координаты, контуры и единицы их таблиц не перезаписываются.
Обновляется только связь строк с новым результатом; состояния, свойства,
диаграммы и аннотации записываются в текущих выходных единицах. Поэтому
повторные расчёты не накапливают погрешность преобразования координат.

## Границы ответственности

- modSectionSnapshot — общее чтение сохранённых таблиц и восстановление
  CSectionModel. Выделен из модуля экспорта; не обращается к AutoCAD и не
  вызывает генератор или решатель.
- modWorkbookCalculation — последовательность пользовательских действий.
- CNDMResultsWriter — сохранение снимка и результатов, включая дополнительные
  исходные сведения модели.
- modWorkbookMessages — Unicode-сообщения, абзацы и возможные решения.
- Существующие генератор, импортёр, расчётчики, построитель схемы и экспортёр
  сохраняют свои предметные обязанности. Формулы ядра не меняются.

Таблицы читаются через Value2 в массивы. Кэш действует только в течение
одной операции и для одной конкретной книги; индексы строк метаданных
создаются один раз. В проходах по элементам и аннотациям нет обращений
к отдельным Range. Фактический адрес вычисляется в ветви сообщения об ошибке.
Поиск границ таблиц выполняется блоками через SnapshotAnchoredExtent.

## Ошибки формирования

Прежний снимок не очищается при отказе получения новой геометрии.
Проверка расположения выходных таблиц также выполняется до их очистки.
Ошибка показывается независимо от флага необязательных сообщений.

Сообщение сохраняет конкретную причину. Для AutoCAD отдельными абзацами
показываются указанные на Config слои, действия для исправления и вариант
автоматического сечения: выбрать Generated и тип, задать размеры и арматуру
на листе «Сечения», повторно нажать «Сформировать сечение». Каждый шаг
располагается на новой строке. Источник ошибки и код остаются в конце
общего сообщения. Источник геометрии самопроизвольно не переключается.

## Направленная приёмка

- Полный снимок mm/cm/m: геометрия, инерции, материалы, исходные сведения,
  связи стержней, аннотации, предупреждения, контуры.
- Блочное чтение пяти основных таблиц и освобождение кэша; масштабирование
  времени на разном количестве элементов.
- Отсутствие снимка, повреждения и сохранение предыдущего сечения при
  неудачном формировании; причина, имена слоёв AutoCAD и отдельные шаги
  решения проверены в сообщении. Настоящий импорт проверен отдельно.
- Неверная геометрия в Config не подменяет снимок при расчёте; новые нагрузки
  и материалы применяются без повторной генерации/импорта.
- Повторные расчёты, смена OUTPUT и сохранение/открытие книги; координаты
  таблиц не изменяются, аннотации не получают повторного округления текста.
- Сравнение численных результатов и статусов с исходной версией на тех же
  сечениях, нагрузках и профилях; схема и экспорт по Results.
- Порядок и назначения всех пяти кнопок; оформление входных листов
  не меняется при выполнении команд.
- Итоговый VBA, ALL CODE, справка и воспроизводимость полной сборки.

Доказательства: docs/regression/SectionWorkflowLayers_2026-10-21.
Длительный полный ON/OFF и общий часовой план этой новой задачи не запускались.

Результаты: 151 проверка снимка, 17 проверок команд, по 89 расчётных
проверок OFF/ON, 86 проверок независимости автообновления схемы.
Сохранение и повторное открытие сохранили все значения Results.
На пяти формах и трёх сочетаниях в обоих режимах сопоставлены
489 456 полей с прежней версией: статусы и сообщения совпали,
наибольшее нормированное расхождение чисел — 1,02·10⁻²⁰.
Два направленных прогона настоящего AutoCAD дали 447 и 503 успешные проверки.

Расчёт читает профили без полей Visualization. Они проверяются на этапе
оформления и экспорта. Ошибка оформления возвращает отдельное предупреждение
после сохранения расчёта; исправление требует только «Обновить схему».
При первоначальной реализации пять основных таблиц загружались целыми
массивами; после упрощения расчёт читает три, полное восстановление — четыре.
Их границы ищутся небольшими блоками; счётчик таблиц не включает эти служебные чтения.
Медиана чтения 1000 стержней — 0,063 с, 5000 — 0,297 с.

## Компактное сохранение и скорость, 21.10.2026

Счётчики формирования и расчёта охватывают команду от входа до завершения,
включая восстановление Excel и схему. Предупреждения о сформированной геометрии
показываются на этапе формирования, сохраняются в Results, но не повторяются
после расчёта. Чтение и запись данных выполняются массивами.

Общая подпись ALL импортированного сечения привязана к глобальному верхнему
габариту бетона. К нему применяется обычный отступ Config. Для этой аннотации
плоттер не ищет локальную границу через середину подписи.

Общий CFiberMeshBuilder повторно использует принадлежность общих углов
соседних ячеек только при точном совпадении координат. Нет округления ключей,
смены допуска, пропуска отверстий или изменения подъячеечного разбиения.
Массивы проверки имеют размер одной строки сетки; рецепты не изменены.

Сверены 30 сеток десяти форм с шагами 20, 7,3 и 10,1 мм: 915 964 поля
совпали побитно. Все 120 прямых решений трёх назначений материалов сохранили
статусы и 1080 чисел точно. Направленная приёмка: 425/0 в каждом режиме.
Полный ночной набор эти проверки не заменяют; он не запускался.

Замеры круга D300 с 8 стержнями и 884 бетонными элементами: построение
модели 0,21 → 0,15 с; вся команда формирования 1,09 → 0,96 с. Чтение
сохранённого сечения при расчёте — около 0,08 с из 1,34 с всей команды;
основное время занимают вывод и схема. Малый выигрыш после разделения
этапов этим объясняется; скрытой генерации при расчёте нет.

Актуальный отчёт: `docs/reports/CompactSectionSnapshot_2026-10-21.md`.

Оформление схемы дополнительно ускорено временными ShapeRange по индексам:
фигуры остаются отдельными, совпадают их имена, порядок и оформление.
Подробные таблицы читают тексты заголовков блочно для нижних индексов;
сводка не сбрасывает оформление повторно после уже выполненной очистки.
На контрольном круге схема 0,52 → 0,43 с, таблицы 0,59 → 0,53 с.
Шесть растров совпали пиксель в пиксель, 4395 записей свойств фигур и
37 173 ячейки Results совпали; 115 ячеек с индексами также без изменений.
Согласованное исключение — выравнивание последних столбцов JSON вправо.

Рабочие писатели не назначают высоту строк или ширину столбцов. Размеры
задаёт сборка, затем сохраняются пользовательские изменения. Выравнивание
и числовые форматы применяются к диапазонам; статусы читаются массивом
и окрашиваются группами одинакового цвета. Динамические рамки и расчётные
шапки Results обновляются по фактическому размеру вывода.
