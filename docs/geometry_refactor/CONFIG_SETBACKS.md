# Концевые отступы типовых рецептов

Источник интерфейса — `modSectionRecipeSetup.UpdateSectionRecipeConfig`.
Это явно запускаемое обновление; расчёт не изменяет Config. Из PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/build_workbook/Update-SectionRecipeConfig.ps1 -WorkbookPath <отдельная-книга.xlsm>
```

Перед вызовом в книгу импортируются актуальные source modules. Основной
Build-Workbook вызывает updater после импорта VBA. Старые значения as/d/n,
дополнительных рядов и LC сохраняются. Обновление повторяется идемпотентно.

В основном армировании RoundedRectangle и HollowRectangle колонки 5/6
становятся StartSetback/EndSetback; прежние единицы и пояснения из этих
колонок переносятся в 7/8 с сохранением формул. Нули записываются только
при однократной миграции старой таблицы. При обычном чтении активное пустое
или ошибочное поле отклоняется; отсутствующий обязательный ввод не заменяется
нулём. Рецепты находят новые колонки по заголовку, диагностируют фактический
адрес и переводят длину через CUnitSystem один раз.

RectSet сохраняет существующие значения концевых отступов; меняются только
подписи t нач./t кон. на канонические названия. Полное кольцо Circle получает
явное пояснение ClosedUniform: отступы неприменимы. Для открытого участка
окружности используются обычный аналитический путь и общие options.

StartSetback/EndSetback измеряются вдоль подготовленного осевого пути в
единице INPUT Length. У независимого ряда они сокращают рабочую длину,
сохраняя EndMode. У ProjectFrom они ограничивают целевой участок и отсекают
непопавшие проекции, без перераспределения оставшихся стержней. Дополнительный
зависимый ряд следует за фактически созданными позициями источника. Внутренний
ряд с выключенным источником не требует своих новых отступов/extra selectors;
геометрические as соседних ограничителей сохраняют прежний смысл.

Список Geometry.Type создаётся из RegisteredRecipeTypes реестра. Одно новое
имя `rngSectionRecipeTypes` служит стабильным источником validation. Новая
регистрация появляется после явного обновления интерфейса; Root/LC/Results
не переключаются автоматически. Табличный Custom не создаётся.

## Проверка Этапа

На отдельной ConfigSetbacks-книге после удаления старых компонентов:

- native compilation/source comparison — PASS;
- 765 geometry + 14 Rounded input + 14 Hollow input — PASS;
- 55 idempotence/nonzero/error-state checks — PASS;
- 20 actual setback/projection checks — PASS;
- 75 unit checks мм/см/м — PASS;
- 20376 geometry records совпадают побитно с принятым retirement milestone
  при новых нулях. Это дополнительная проверка миграции UI, а не подмена
  исходного pre-refactor baseline. Input records исключены только из этого
  сравнения, потому что формат таблицы изменён;
- независимая XML-сверка 4507 named cells — PASS: все прежние значения,
  формулы и references сохранены с явно заданным переносом единиц/пояснений;
  addedNames=[rngSectionRecipeTypes], removedNames=[];
- исходный основной output сохраняет baseline SHA-256.

Артефакты: `docs/regression/GeometryDeclarative_2026-10-12/ConfigSetbacks/`.
Неудачные пробы сохранены отдельно: конфликт имени Circle в новом VBA module,
цикл повторного Err.Raise при вынужденной ошибке (исправлен On Error GoTo 0),
неполная временная таблица units-test. Исторический TIMEOUT не считается PASS.
Пересечение read-only проверки с незавершённым импортом дало file-lock; принят
только повтор после завершения сохранения. Допуски и расчётный baseline не менялись.

Этот этап закрывает доступность новых полей в source/native staging. Для
окончательного R13 остаются связанное покрытие всех требований общего API,
визуальные направленные проверки и итоговая основная книга/Справка.
