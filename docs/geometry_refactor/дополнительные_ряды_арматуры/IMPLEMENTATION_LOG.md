# Независимые отступы дополнительных рядов — ход реализации

Исходная версия: `f88e960d`, ветка `codex/linked-rebar-row-offsets`.
ТЗ находится в этой папке. Пробел в прежнем имени папки убран в соответствии
с путём в ТЗ. Пользовательский execution_report не изменять и не коммитить.

## Исходное состояние

- Рабочая книга и ALL CODE сохранены; контрольные суммы —
  `docs/regression/DependentRowOffsets_2026-10-17/Before.json`.
- Независимая исходная книга: `Baseline.xlsm` в той же папке доказательств.
- Полное чтение Config без Excel: `ConfigBefore.json`, 36 236 ячеек,
  17 именованных таблиц, 55 правил validation. Анализ расположения продолжается.
- Существующий сборщик: `Build-Workbook.ps1` и `SettingsCatalog.ps1`.
  `UpdateSectionRecipeTypes` меняет только список типов и не будет мигратором.
- Контактные смещения считает `CRebarContactBuilder`; координаты размещает
  `CRebarRuleExecutor`. Оба дополнительных правила остаются связаны с Main.

## Дополнение пользователя 17.10, во время реализации

## Замечание по схеме и исправление центра (17.10, после примеров)

- Пользователь заметил кажущийся сдвиг Ø16 у скругления и смещение подписи.
  Перенос верен: для SideBySide при d2=20/d3=16 расстояние 18 мм по касательной;
  у данного скругления ΔX=14.9666295472, ΔY=10 мм. Нормальный отступ 100 мм,
  скалярное произведение нормального/касательного переносов равно нулю.
- Ошибка подписи подтверждена: RuleExtremeEnds исключал основной стержень
  на дуге и брал X=0..380 вместо -380..380, смещая центр на 190 мм.
  Исправлен общий метод через существующий RuleBounds; рецепты и координаты
  стержней не менялись. Аннотационный oracle четверти окружности теперь
  ожидает охват всех трёх позиций 0..100 при опорной прямой Y=100.
- `OpeningCenter01`: 10 + 187 + 92, 0 отказов. `OffsetExamples04`: шесть схем
  созданы, 36 НДС и шесть пакетных сочетаний записаны. На нагруженных случаях
  возможен инженерный FAIL; текущие 36 НДС сошлись, NumFail не обнаружен.
- После этого исправления выполняется `AfterCenterZero`: физическая геометрия
  должна остаться прежней; изменение координат аннотаций на скруглениях —
  отдельное намеренное исправление по замечанию пользователя, не новая baseline.
- Чистый шаблон `DirectTemplate02`: 4 формы/11 столбцов/списки/нули/reopen PASS.
- Подготовка листа Справки в `Prepared01` завершилась COM InvalidCast при
  Update-SectionRecipeGuide в том же PowerShell-процессе, где перед этим
  записывались scalar Value2. Рабочая книга не менялась. `Prepared02` повторяет
  с checkpoint после Add-SettingsInstructions; если снова отказ, выполнить
  updater короткого guide отдельным процессом, сохранив уже готовую Справку.
  Prepared02 скопирован до окончания импорта последнего исправления центра:
  перед приёмкой **обязательно обновить его все изменённые VBA-компоненты**
  и проверить source equality. Не считать один checkpoint готовым выпуском.

## Выполнено и подтверждено

- Общий построитель принимает необязательный последний `baseOffset = 0`,
  сохраняет прежние вызовы, группирует по `GEOM_TOLERANCE = 1e-9 мм`,
  считает нормальные и касательные цепочки отдельно в пределах группы.
- `ValidateRowOffset` передаётся в копию правила; исполнитель включает
  проверки обоих дополнительных рядов активного семейства. Другие семейства
  сохраняют прежние политики. Стержень после законного слияния сохраняет
  строгого участника, повторно проверяет старых соседей и проверяет новых.
- Общий узел определяется по совпавшим исходным концам разных линий,
  без Comment/AnnotationGroup. Новое самостоятельное совпадение запрещено
  до слияния. Контроль дуги использует тот же выбор сегмента/касательной,
  что AtDistance, и запрещает неположительный радиус нормального переноса.
- Четыре рецепта читают 11 столбцов; в рабочих рецептах нет старых шести
  ключей Circle. Отступы хранятся числами в структурах ввода, options создаются
  только в AddReinforcement. Ввод пустого отступа отдельно трактуется как 0.
- Компиляция 11 обновлённых компонентов в `ContactCandidate.xlsm` прошла.
- `ContactDirected`: 97 прежних + 98 новых + 5 входных проверок, 0 отказов.
- `GeometryDirected`: 97 + 98 + 92, 0 отказов. Проверены реальные линии/дуги,
  комбинации привязок, 100/118, касание/пересечение, полный диск, схлопывание
  и инверсия дуги, оба порядка самостоятельного совпадения и позднего

- Геометрия начинается в H; прежние именованные охваты:
  Circle H87:K98, RectSet H101:P128, Rounded H131:P152, Hollow H156:P183.

## Текущие незавершённые вопросы

1. Общий мигратор `DependentRowsConfig.ps1` и обёртка
   `Update-DependentRowsWorkbook.ps1` уже переносят фактические таблицы через
   native Cut в промежуточный лист; он удаляется. Исходная книга не меняется:
   сохраняется только новая копия после успешного повторного вызова.
   Пока **не доказана** полная сохранность формул/метаданных и правой цепочки.
   Надо добавить проверки синтетических правых таблиц, скрытых списков,
   объектов, изменённой/смешанной/повреждённой схемы, сохранения/reopen.
2. В миграторе пока проверить/доработать: узнавание трёх подблоков уже нового
   Circle; форматированные пустые правые области; hidden/width/objects при
   переносе; примечания и формульные пояснения Circle; недопустимые пересечения
   и безопасный отказ. Не объявлять эти пункты готовыми.
3. После native Cut нельзя повторно использовать закэшированный объект
   назначения Range для AddComment: в этой автоматизации получался
   0x800A01A8. Получение ячейки заново через Sheet/Row/Column устранило отказ;
   все исходные попытки LayoutCandidate..03 сохранены как диагностика.
   Новые PS1 требуют UTF-8 BOM для Windows PowerShell 5.1.
4. Проверить/адаптировать оставшиеся существующие тесты со старыми адресами
   (особенно modTestGeometryConfig и адресные helpers WorkbookInterface),
   инструменты сборки и справку. При переносе нельзя ослаблять ожидания
   нулевой геометрии; адреса меняются, координаты совпадают побитно.
5. Выполнить G/V/U по ТЗ с реальными новыми отступами для всех рецептов,
   единицами и формулами, наклонными сторонами и смещённым отверстием;
   проверить реальный расчёт/схему/сохранённые Results на нескольких случаях.
6. Обновить Справку/API, визуально проверить конечный макет, выпустить
   проверенную книгу и ALL CODE вместе, повторно считать встроенный VBA.
   Основная книга пока **не заменена**, ALL CODE пока прежний.

Все три защищённых SHA256 по-прежнему совпадают с Before.json, включая
пользовательский execution_report. Новые рабочие VBA-классы не добавлялись.
