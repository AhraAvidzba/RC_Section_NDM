# Общие операции, измерения и диагностика: этап 12.10.2026

Это технический отчёт этапа. Он не заменяет полный гайд/API-каталог ТЗ 10.5
и не означает завершение приёмки всей задачи. Основной output пока прежний.

## Выполнено

- CSectionDefinition хранит именованные скалярные привязки и SourceMap.
  Anchor/PathAnchor/TransformAnchor задают точки во внутренних мм;
  PathAnchor использует ID сегмента и параметр [0;1]. Изменение возвращённых
  координат не изменяет опубликованное определение. Source хранит строку
  происхождения, не ссылку на Excel. Аннотации проверяются до построения сетки.
- DistributionScope=PerPath теперь явное поле options/правила, default PerPath.
  Другие значения отклоняются. Независимые пути группы не соединяются.
- Общий OffsetPath смещает непрерывную аналитическую цепочку: положительный
  offset идёт слева от обхода, противоположный знак — справа. Гладкие line/arc
  стыки сохраняют касание; line/line получают miter. Негладкий стык с дугой
  требует согласованного RoundedPolygon и даёт адресный отказ. Исчезновение
  и изменение топологии дают ошибку; наиболее длинная часть не выбирается.
  Miter пересчитывает параметры связи с исходными линиями.
- ConstrainLine ограничивает/продлевает одну прямую двумя поперечными
  плоскостями nX*x+nY*y=bound. Bound в мм при единичной нормали. Порядок
  плоскостей соответствует направлению исходной линии. Это отдельная операция
  перед StartSetback/EndSetback. Hollow Ro=0 использует её, сохраняя соседние
  геометрические as, в том числе при отключённых соседних рядах. Побитный
  геометрический diff с предыдущим этапом не обнаружил изменений.
- Dimension поддерживает Horizontal/Vertical/Aligned между привязками;
  VerticalDistance — явный вертикальный размер. Radius/Diameter измеряют
  конкретный аналитический сегмент, PathLength — точную длину пути/группы,
  Text — модельную привязку текста. Extent остаётся полным габаритом выбранной
  геометрии, независимо от setbacks арматуры. Новые измерения не добавлены
  автоматически к четырём прежним схемам.
- Results writer сохраняет измерения; reader читает сохранённые единицы.
  MEASUREMENT_LABEL/TEXT_ANNOTATION рисуются общим layout вместе с размерами.
  Layout применяет существующие настройки шрифта/масштаба. Выбор разнесённых
  привязок и направления измерения остаётся явным в рецепте.

## Проверяемая диагностика

CGeometryDiagnostic хранит Code, EntityID, RelatedEntityID, Reason,
Detail1/Detail2 и SourceReference. Query/path сохраняют прежние Err.Number
5401/5520; facade/rules — 5530. Коды новых отказов назначаются непосредственно,
без разбора русского текста. Например OFFSET_DISAPPEARED содержит исходный
радиус и offset, CONSTRAINT_DISAPPEARED — две станции ограничителей,
BAR_OVERLAP — отрицательный геометрический зазор и диаметр. SourceMap фасада
или SourceReference правила добавляют исходную ссылку.

Исполнитель сообщает Requested/Created/Merged/Skipped/Conflicts/BarOverlaps.
Created считает действительно добавленные физические стержни, в том числе
при отказе в середине построения. Новый ранний отказ обнуляет отчёт предыдущего
запуска. PositionRuleID/PathID/SourceID/PhysicalOwner сохраняют принадлежность
каждой заявленной позиции, включая объединённые позиции.

RuleStepBounds возвращает численные границы шагов и хорд; RuleTrace/DiagnosticsText
дают текстовый отчёт. Замыкающий интервал учитывается для кольца; независимые
пути не соединяются. StationStep — длина вдоль пути (для DependentOffset —
исходного пути), CenterStep — хорда между центрами. Это разные величины.

Проверка соседей использует пространственный индекс кандидатов и исходные
Double для зазора. Касание допустимо. ReportOverlap сохраняет историческую
раскладку и сообщает пересечения дисков; RejectOverlap явно запрещает их.
Это геометрическая политика, не нормативный минимальный зазор. Полная проверка
диска относительно бетона остаётся отдельным PlacementCheck=CheckFullDisk;
default прежних рецептов CheckCenter не ужесточён молча.

Подробных образцов хранится до 128; полные счётчики не сокращаются.
DiagnosticRecordsOmitted явно сообщает число остальных событий;
LastDiagnostic содержит последнее событие независимо от лимита образцов.

CSectionModel хранит скалярную диагностику и происхождение. В Results оно
сохраняется как Geometry.RecipeDiagnostics в свойствах и RecipeTrace в Comment
физического элемента. Разделители %, |, ;, =, CR/LF в ID экранируются.
Таблица геометрии сохраняет прежние 15 колонок; контуры не дублируются.
Metadata не меняет геометрическую revision, A/I, источник сетки или НДС.

## Направленные проверки

Native workbook: GeometryDeclarative_2026-10-12/DeclarativeApi/RC_Section_NDM.xlsm.
Основные entrypoints: modTestRecipeOperations.RunRecipeOperationTests и
RunRecipeDiagnosticTests; modTestRecipeAnnotations.RunRecipeAnnotationTests,
RunRecipeAnnotationSnapshotTests и DumpRecipeAnnotationPreview.
Используется Run-Audit03Watchdog с отдельной книгой; основная книга защищена hash.
Проверки и их фактические результаты перечислены в DECLARATIVE_API_EVIDENCE.json.

Сравнение с ConfigSetbacks: 20376 записей, exact, без INPUT, три намеренные
мутации координаты/диаметра/роли обнаружены. Формат Config ранее проверен
независимой XML-сверкой, текущий этап его не меняет. Аннотации проверены через
writer/reader в mm/cm/m, реальный PNG и save/reopen Results. Пример со всеми
измерениями использует разнесённые модельные привязки; плотная ранняя схема
сохранена как probe, не объявлена качественным оформлением.

Пользователь разрешил только направленные проверки. Полные тяжёлые on/off
и Excel UI матрицы не запускались. Нормативная верификация не подменяется
числом assertions. Незавершены полный API manifest/гайд в последнем разделе
Справки, один-класс-пример, окончательная адресная интеграционная приёмка,
производительность и обновление основной книги/VBA_All_Code.txt.
