# Audit03: Защитные Контракты Ввода

Дата: 2026-10-02. F07/K02 review, отдельный directed gate.
Статус: направленная приемка пройдена; полный F07/K02 audit еще не завершен.
Никакая расчетная методика либо нормативная формула здесь не меняется.

## Проверяемые Входы

| Контракт | Public Call Path | Ожидаемая Реакция |
| --- | --- | --- |
| Boolean | Config Range -> SettingsReader.LoadFromRange -> GetBoolean | Все утвержденные Yes/No aliases читаются; явное Maybe/TODO/пустое значение не становится False/default. |
| Целое число | Config Range -> GetLong | Точные Long границы принимаются; дробь не округляется молча, overflow не превращается в runtime 6. |
| Таблица Config | SettingsReader.LoadFromRange / AppendSettingsRange | Nothing, scalar Value2 или меньше обязательных колонок отвергаются адресной ошибкой структуры до UBound/indexing. |
| Таблица профилей | ProfileCatalog.LoadFromRange | Scalar Value2 не вызывает runtime 13; ошибка структуры имеет понятную причину. |
| Геометрия сетки | CFiberMeshBuilder.BuildMesh | Nothing проверяется до geometry.IsValid. |
| Размер сетки | BuildMesh -> axis/product -> ReDim | Непредставимое число ячеек отвергается до Long conversion, умножения и выделения памяти. |
| Boundary subdivisions | BuildMesh | Недопустимое значение не заменяется 1 без сообщения. |
| Потребители | CSectionSolver.ApplySettings / Registry.MeshBoundarySubdivisions | Неверный Boolean, дробный счетчик, нулевой/пустой/TODO subdivisions отклоняются на настоящем маршруте настройки. |

Отсутствующий необязательный key и явно неверное введенное значение различаются.
Default-параметр публичного getter-а нужен для оговоренных optional/test/старых
схем; он не разрешает исправлять неверный явный ввод молча. Требование о каждом
required key проверяется отдельно в его reader/consumer, без массовой подмены
всех настроек одним новым правилом.

## Тест И Изоляция

`modTestWorkbookInterface.RunAudit03InputContractTests` вызывает тот же набор,
который входит в полный UI suite. Рабочая книга - независимая test fixture.
Временный лист `__Audit03Input` удаляется даже после ошибки; Config, validation
и пользовательские формулы не меняются. В отчете выводятся фактический error
code и reason, а не только флаг наличия исключения.

## Фактическая Приемка

- Negative v31: `f07_k02_input_negative_v31_2026-10-02.txt`, 22/17 на
  неизмененном v29 production с импортом только нового тестового модуля.
  Подтверждены молчаливые Boolean/default, округление дроби, runtime 6/9/13/91
  вместо адресной ошибки и нормализация subdivisions=0. Это не PASS.
- Positive v33: `f07_k02_input_positive_v33_2026-10-02.txt`, 54/0, source
  unchanged=True. Дополнительно проверены пустое/TODO разбиение через registry
  и максимальное Long-разбиение: отказ до умножения/выделения массива.
- Full Off v33: 8444/0; Full On v33: 8445/0 по всем восьми suites. Физические
  expected и tolerance прежние; изменения исходной пользовательской книги нет.
- Guards находятся в существующих SettingsReader/ProfileCatalog/Registry/Mesh.
  Новых классов и новых расчетных правил нет. Ошибка дробного Long больше не
  превращается в округление; все утвержденные Boolean aliases сохранены.

Не утверждается закрытие всех Array/optional-объектов F07 или поведенческое
покрытие всех настроек K02. Ошибка нехватки памяти при представимом, но слишком
большом массиве также не покрыта этими тестами. Необязательные пустые диаметры
и количества арматуры сохраняют свой утвержденный смысл и не заменены общим
запретом пустого значения во всех численных getter-ах.

## Переключатели Расчетного Профиля

`CCalculationProfileCatalog` самостоятельно читает четыре обязательных
переключателя `Calculation.Strength.DirectState`, `Calculation.Strength.Capacity`,
`Calculation.Crack.Width`, `Calculation.Stability.Enabled`. Общая защита
`CSystemSettingsReader.GetBoolean` этот маршрут не покрывала.

Сохранены варианты Yes/True/1/Да и No/False/0/Нет. Незнакомое значение, пустая
ячейка, ошибка формулы и отсутствующая строка теперь отклоняются ошибкой
3988 с указанием ProfileId и key. Они не должны молча отключать раздел расчета.
Обычный численный результат включенного/выключенного расчета не меняется.

Контрпример `k02_profile_input_negative_v40_2026-10-02.txt`: 32/40 на
неизмененном production с импортом только теста. Positive v40: 72/0.
Тест копирует фактический диапазон профилей на временный лист, проверяет каждый
флаг готового CCalculationProfile и удаляет fixture; пользовательский Config
не изменяется. Full v40 Off 8516/0 и On 8517/0; те же полные показатели
подтверждены отдельной чистой сборкой v42. Это не закрывает все numeric/enum
контракты остальных настроек.
