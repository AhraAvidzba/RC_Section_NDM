# Нормативная трассировка

Программные проверки не заменяют независимую сверку с нормами. До ее завершения результаты не следует объявлять окончательно верифицированным расчетом по СП 35 и СП 63.

## Источники

Основные документы находятся в `norms/`. Методика НДМ принимается по СП 63, специальные требования мостовых конструкций - по подтвержденным положениям СП 35. Спорные трактовки фиксируются в [OpenNormativeQuestions.md](OpenNormativeQuestions.md).

Для каждого нормативного параметра или формулы необходимо указать документ и редакцию, пункт/таблицу/формулу, единицы, область применимости, программный ключ или метод и независимый контрольный пример. Инженерные обобщения для произвольного сечения обозначать отдельно от прямых требований СП.

## Области проверки

| Область | Где проверять |
|---|---|
| TwoLine/ThreeLine диаграммы бетона и арматуры | Материальные параметры Config, профили `rngCalculationProfiles`, контрольные точки диаграмм |
| Равновесие и предельные деформации | Общая постановка N + Mx + My, решатели НДС и несущей способности |
| Образование нормальной трещины | Модель CrackInitiation, критерий и универсальный путь LoadPath |
| Раскрытие по СП 63 | Справка книги; [методический отчет](reports/methodology/CrackWidthMethodology_SP63.md) |
| Раскрытие по СП 35 | Справка книги; [итоговый отчет](reports/cracks/NDM_SP35_Implementation_Final_Report_2026-10-06.md) |
| Продольные трещины | Коэффициенты и пределы, независимая проверка по фактическому НДС |
| Устойчивость СП 35/СП 63 | [Методика](../SP63_SP35_SECOND_ORDER_STABILITY_DISCRETE_AUDITED.md), таблицы Config, [ручные примеры](examples/) |

Численные значения шаблона не подтверждают нормативное происхождение. Актуальный источник значений - каталог настроек сборки и Config, а не дублирующая таблица в документации.

[Отчеты аудитов](reports/README.md) подтверждают программные контракты и сценарии на указанных в них версиях. Закрытие программного аудита не закрывает автоматически нормативные вопросы.
