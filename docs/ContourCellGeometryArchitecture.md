# Общая геометрия бетонных элементов

Рабочая ветка: `codex/contour-cell-geometry`, исходная согласованная версия `main` на `1a0c03a82ecb2fdbbabdbdb1e2bff8f554136516`. Это проект архитектуры и перечень её обязательной приёмки; наличие документа не означает завершение реализации или PASS.

## Требования

1. В разделе Config «Геометрия и сетка» появляется `Mesh.CellGeometry`: `Adaptive` по умолчанию сохраняет прежнее поведение и все его параметры; `Contour` использует фактическое пересечение базовых ячеек с бетоном. Оба режима используют существующие Auto/User и StepX/StepY.
2. В Contour учитываются точные прямые и круговые дуги наружных контуров и всех отверстий. Несвязные части одной базовой ячейки становятся отдельными элементами. Эквивалентные прямоугольники в новом режиме запрещены.
3. `rngNDMSectionGeometry` сохраняет общие свойства, единицы и стабильные расчётные ID `C1…`. Фактические границы хранятся по ElementID в отдельном `rngNDMElementGeometry`, последнем среди таблиц Results. Общие Outer/Opening в `rngNDMSectionContours` не дублируются и сохраняют прежние 17 колонок.
4. Схема читает сохранённую фактическую форму, уменьшая только рисунок коэффициентом 0,7; сохранение/чтение снимка и AutoCAD используют ту же геометрическую сущность. При потере обязательной геометрии новый элемент отклоняется, а не превращается в прямоугольник.
5. Каждый бетонный элемент — отдельный неизменяемый `CConcreteElement` со своими характеристиками и геометрией. Это один новый рабочий класс; набор классов по режимам или типам фигур не создаётся. Единицы, знаки, диаграммы материалов и математическая постановка решателя сохраняются. Существующие файлы старого режима остаются читаемыми.

## Ответственность компонентов

| Компонент | Ответственность |
|---|---|
| `CConcreteRegion` и `TRegionEdge` | Единая область: ориентированные замкнутые линии/дуги, Outer/Opening, несколько компонентов |
| `CSectionGeometryQuery` | Пересечение окном, компоненты, A/c/I по фактической границе, распознавание настоящего прямоугольника, проекции |
| `CGeometryRegion` | Подготовленная бетонная область для сетки и проверки точек, без Excel |
| `CFiberMeshBuilder` | Выбор правила построения ячейки по настройке; выдача единого массива свойств и фактических областей |
| `CSectionModelBuilder` | Перенос готовых ячеек в модель без собственных формул геометрии |
| `CSectionModel` | Единственное назначение C1/R1; свойства, обязательная фактическая область Contour-элемента и версии кэшей |
| `CConcreteElement` | Канонический неизменяемый объект одного бетонного элемента со всеми данными; замена создаёт новый экземпляр |
| `modMeshConfiguration` | Чтение Config и перевод ручного шага через CUnitSystem |
| `CNDMResultsWriter` / `modSectionSnapshot` | Блочная запись/чтение свойств и геометрии, связь по ElementID и адресная валидация |
| `CCalculationSnapshot` / существующий файловый кодек | Снимок без потери фактической геометрии, валидация до изменения Results и совместимость старых файлов |
| `CSectionPlotDataReader` / `CSectionPlotter` | Подготовка сохранённых областей и отображение; быстрый путь настоящего прямоугольника является оптимизацией формы |
| `CAutoCADSectionModelImporter` / `modAutoCADStressExport` | Преобразование внешнего COM в общую область и обратно; WCS, свои временные объекты и очистка |

Вводится один рабочий data-класс `CConcreteElement`. Дополнительных классов по режимам не вводится. Различается только получение геометрии ячейки: адаптивный прямоугольник или пересечение. Ни снимок, ни схема, ни экспорт не строят отдельные параллельные модели по названию режима. Массивы X/Y/A в модели — подготовленная числовая проекция объектов для горячих циклов, а не второй изменяемый источник данных.

## Контракт элемента и сохранения

Для Contour-элемента `ConcreteGeometry(i)` возвращает фактическую `CConcreteRegion`; `SetConcreteGeometry` проверяет согласованность площади, центра и собственных инерций с общими свойствами. `GeometryInterpretationStatus = Contour` — обязательный признак наличия фактических строк, в том числе для прямоугольного элемента нового режима. Настоящий прямоугольник распознаётся общей геометрической проверкой для быстрого рисунка/экспорта.

Только прежний режим допускает компактный Rectangle/Equivalent rectangle/Equivalent square и прежнюю интерпретацию старых AutoCAD Region. Для него общая геометрическая API создаёт область прежней оболочки; это не объявляется точным восстановлением исходного произвольного Region.

`rngNDMElementGeometry`: RunID, LoopID, SegmentID, Sequence, LoopRole, SegmentType, StartX, StartY, EndX, EndY, CenterX, CenterY, Radius, SweepAngle, SourceID, Comment, LengthUnit, ElementID. Точный прямоугольник задаётся четырьмя линиями. Ключ сегмента относится к своему ElementID; границы сечения остаются отдельными. Перед восстановлением проверяются типы, единицы, владельцы, замкнутость, роли и численные свойства. Необязательные комментарии/происхождение не определяют наличие обязательной формы.

Новая таблица включается в снимок отдельной матрицей. Старый снимок без неё допустим только для прежних элементов; потеря таблицы/строк Contour-элемента запрещает приёмку до записи Results. Повторный расчёт переносит готовые границы без новой генерации или AutoCAD.

### Таблица обязательной геометрии

Якорь новой таблицы при сборке — `rngNDMElementGeometry`, `Results!CR156`; она находится после аннотаций. Рабочий код получает фактическое положение через имя, поэтому диагностика и проверка вместимости не зависят от этого адреса. Шапка содержит ровно 18 полей в указанном выше порядке; фактическое имя поля единиц — `LengthUnit (SectionXY)`, угла — `SweepAngle, rad`.

- `ElementID` ссылается на существующую бетонную строку `rngNDMSectionGeometry` с маркером `Contour`. Пустой, неизвестный, арматурный или принадлежащий прежнему типу владелец отклоняется. У каждого `Contour` должна быть хотя бы одна полная замкнутая область.
- `SegmentID` уникален внутри `ElementID`. `LoopID` также относится к своему элементу: одна замкнутая граница не может быть разделена между разными LoopID, а одним LoopID нельзя назвать раздельные границы. `Sequence` — общий непрерывный порядок строк всей таблицы, начиная с 1; он не начинается заново у следующего элемента.
- `LoopRole` — `Outer` или `Opening`, проверяемые по фактической вложенности. Сохранённая строка не вправе превратить наружный материал в отверстие. Допускаются только `CONTOUR_LINE`, `CONTOUR_CIRCLE`, `CONTOUR_ARC`. Дуга задаётся началом, центром и знаковым углом в радианах; радиус и конец восстанавливаются общим ядром. Сплайны и другие неизвестные кривые не подменяются отрезками.
- Каждая строка имеет обязательный непустой `LengthUnit (SectionXY)`: поддерживаемую `CUnitSystem` единицу `mm`, `cm` или `m`. Все координаты относятся к той же системе SectionXY, что и общие свойства; при чтении переводятся в мм. Пустота не включает текущие единицы Config и не означает метры по умолчанию.
- В общих свойствах точного элемента обязательны единицы X/Y/Width/Height, площади и собственных инерций. Координатные поля имеют согласованную единицу длины, три инерции — согласованную единицу длины в четвёртой степени, поворот — радианы. Единица площади может выбираться независимо от единицы длины. Прежние файлы продолжают читаться по прежнему контракту.
- `RunID` каждой строки совпадает с владельцем и общим запуском снимка. До записи в Excel дата может иметь тип VBA Date; после записи и в файле это её числовое представление Double. Date разрешён только для RunID, а не для координат, площадей или инерций.
- Числа из Excel проходят существующий строгий разбор без предположений о системном десятичном разделителе и без интерпретации разделителей тысяч. В файле они сохраняются исходными Double. Boolean, даты в физических величинах, ошибки формул, нечисловой текст и пустые обязательные величины отклоняются.
- `SourceID` и `Comment` — необязательные сведения. Они не определяют форму и не участвуют в геометрической проверке; повреждённая дополнительная подпись не становится обязательным входом расчёта. Основная таблица сохраняет отдельные необязательные `Comment`/`ExtraData`; обязательная граница в JSON не прячется.

`ReadConcreteBoundaryMap` строит по матрицам словарь `ElementID → CConcreteRegion` во внутренних единицах. `ReadSavedConcreteBoundaries` читает данные блочно и принимает уже загруженную основную матрицу, чтобы не читать её из Excel повторно. Замкнутость, пересечения и дуги проверяет общий `BoundaryRegion`; согласованность A/c/I — тот же `CSectionModel.SetConcreteGeometry`, который принимает геометрию генератора и AutoCAD. Ошибка указывает ячейку через текущий именованный якорь; в самостоятельном файле — имя таблицы и относительную строку/колонку.

### Файлы версий 04 и 05

Оба расширения `.ndm` и прежнее `.ndms` читаются независимо от версии содержимого. Если оба имени существуют, `.ndm` имеет приоритет: повреждённый новый файл не заменяется молча старым. Текущий писатель использует `.ndm`.

| Содержимое | Заголовок и окончание | Числовая версия | Поведение |
|---|---|---:|---|
| Прежняя компактная геометрия без строк собственных границ | `NDMSNP04` | 4 | Сохраняется прежний формат; новая пустая шапка не требует версии 05 |
| Обязательные фактические границы бетонных элементов | `NDMSNP05` | 5 | Дополнительная обязательная матрица не может быть незаметно проигнорирована прежним читателем |

Текущий читатель принимает обе пары сигнатуры и версии, но требует совпадения заголовка и окончания. Существующий SHA256 проверяется до выделения таблиц; матрицы сохраняют прежний плотный кодек чисел и UTF-16 строк. Версия 04 с непустыми строками фактической геометрии отклоняется. Версия 05 не отменяет проверку состава: если основная строка имеет `Contour`, отсутствие матрицы или связанной границы остаётся ошибкой. Прежний читатель, принимающий только `NDMSNP04/4`, отвергает `NDMSNP05/5`, вместо восстановления эквивалентного прямоугольника.

`CCalculationSnapshot.BaseKeys` добавляет седьмую техническую таблицу только при её наличии в файле; старый снимок с шестью таблицами остаётся допустимым. В режиме File геометрические таблицы, включая новые границы, всё равно остаются на листе Results; внешний файл убирает с листа большую таблицу состояний, но не обязательную геометрию. Обновление сохранённого времени меняет только поле времени и SHA256, сохраняя исходную сигнатуру 04 либо 05.

### Порядок проверки и очистки

Загрузка файла и `CCalculationSnapshot.Validate` проверяют состав, даты, владельцев и фактические области до изменения Results. Обёртка `UpdateSectionResultsForWorkbook` выполняет эту проверку до восстановления; публичный `CNDMResultsWriter.RestoreSnapshotBase` также вызывает её самостоятельно до первой очистки. Направленный негативный тест удаляет обязательную матрицу из настоящего Contour-снимка и сравнивает все семь ранее показанных таблиц Results после отказа.

Формирование и расчёт проверяют вместимость семи блоков заранее, включая число аналитических сегментов. Восстановление старого снимка явно очищает новую таблицу до пустой шапки, чтобы не оставить границы другого, ранее показанного Contour-снимка. Повторный расчёт переносит неизменённые обязательные поля и обновляет только RunID; рисунок и экспорт читают одну и ту же сохранённую геометрию. AutoCAD экспорт сначала восстанавливает модель из Results и проверяет её границы, а затем подключается к чертежу и создаёт объекты.

## Расчёт и отображение

Точные A/c/I готовятся один раз. Горячий цикл решателя по-прежнему получает массивы площадей и расчётных точек, а не обходит криволинейные границы на каждой итерации. Это точная геометрия ячеек, а не заявление о точном интеграле нелинейного напряжения по крупной ячейке. Сходимость по основному шагу остаётся обязательной инженерной проверкой.

Гомотетия рисунка 0,7 не изменяет свойства элемента и сохранённый контур. Для вогнутой области она не гарантирует вложенности в исходную ячейку. Отверстия должны оставаться прозрачными; белые накладки, скрывающие соседние элементы, недопустимы. Круговые дуги сохраняются аналитически; Excel отображает их кривыми с контролируемой визуальной аппроксимацией, AutoCAD получает фактические прямые/дуги.

## Проверка завершения

- Аналитические A/c/I для прямоугольника, круга, четверти, скруглений и отверстий; большие смещения, поворот, малые дуги, касания и несколько частей в ячейке.
- Баланс суммы площадей, статических моментов и инерций ячеек относительно исходной области; отсутствие наложений и пропавших частей.
- Прежний Adaptive: прежние размеры, количество, свойства и рабочие расчёты без ослабления ожиданий.
- Новый Contour: Auto/User, разные StepX/StepY, внутренние/пограничные ячейки, все типы сечений и Outer/Opening AutoCAD.
- Excel/File и экспорт/импорт снимков: точные линии/дуги/отверстия/ID, старые форматы, единицы, обе десятичные локали, сохранение и reopen; потеря обязательных строк отвергается без изменения прежних Results.
- Нативная схема Excel: фактическая форма, прозрачные отверстия, общий масштаб, коэффициент 0,7 и сохранение после reopen.
- Настоящий AutoCAD: оба режима, WCS, реальные Region/дуги/отверстия, обратный импорт и очистка только своих временных объектов.
- Актуальная сборка, настройки/списки/рамки/заголовки, WorkbookLayout, полный нативный экспорт компонентов и AllCode; пользовательские данные сохранены.
- Отчёт, компактные доказательства, commit/push в рабочую ветку; main остаётся исходной до принятия результата пользователем.

Долгие полные ON/OFF и целые UI запускаются только после отдельного согласия с указанием состава и длительности. Направленные проверки не переименовываются в полный PASS.

## Существенные ограничения и оставшаяся проверка

- Двоичный файл по-прежнему ограничен 2 ГиБ существующим кодеком. На листе действует фактический предел строк с учётом положения именованного якоря. Четыре линии на точный прямоугольник и дополнительные дуги увеличивают число строк; этот объём нельзя считать бесплатным даже при уменьшении числа элементов.
- Точная геометрия не устраняет ошибку интегрирования нелинейных напряжений одной расчётной точкой крупной ячейки. Сравнение старой и новой сетки не является обещанием одинаковых напряжений или предельных нагрузок; нужна проверка сходимости по основному шагу.
- Площадь, центр и инерции сверяются с общими допусками модели, включая ограничения представимости больших WCS-координат. Это не математическое сравнение двоичных значений геометрических интегралов без допуска.
- Excel показывает круговую дугу конечным числом кривых Безье. Аналитические данные снимка от этой визуальной аппроксимации не меняются. Вогнутая форма после гомотетии 0,7 не обязана целиком лежать внутри исходной формы.
- Чистые матричные тесты проверяют единицы и правила строгого чтения, но сами по себе не доказывают работу настоящего AutoCAD, повторного открытия книги или второй Windows-локали. Эти утверждения требуют отдельных первичных нативных журналов. Завершение реализации и общий PASS устанавливаются по фактическому составу приёмки, а не по наличию этого документа.
