# МСК При Импорте И Экспорте AutoCAD

## Принятый Контракт

- Перед импортом и экспортом пользователь включает мировую (глобальную)
  систему координат МСК/WCS: `_UCS`, затем `_World`.
- Документный entrypoint импортера проверяет машинный признак `WORLDUCS = 1`
  до обращения к `ModelSpace` и `Layers`. Имя ПСК не используется для допуска:
  оно не позволяет надежно различить МСК и несохраненную локальную ПСК.
- При локальной ПСК импорт запрещен с понятной инструкцией. Невозможность
  прочитать признак или некорректный ответ также запрещают импорт.
- Программа не переключает ПСК, не меняет исходные объекты и не заменяет
  прежний Results при таком отказе. Запись Results в пользовательском сценарии
  начинается только после успешного возврата модели из импортера.
- Для экспорта правило внесено в инструкцию. Дополнительный запрет экспорта
  не вводился: запрос на программную блокировку относится к импорту.
- Геометрия по-прежнему передается в мм; поворот самого сечения в мировой
  плоскости XY допустим. Solver, search, материалы и расчетные формулы не менялись.

Значение машинного признака подтверждено в первичной документации
[Autodesk WORLDUCS](https://help.autodesk.com/view/ACD/2026/ENU/?caas=caas%2Fdocumentation%2FCIV3D%2F2014%2FENU%2FfilesACD%2FGUID-2513B817-8652-49C9-87CE-9F44166F4453-htm.html).

## Отверстия Без Наружного Контура

Этот ранее принятый контракт сохранен, а не заменен новой геометрической веткой:

- Импортированный `Opening` остается достоверным, с явной ролью и точными
  линиями/дугами в `CSectionModel.Contours` и в снимке Results.
- Если наружный контур не задан или его слой пуст/отсутствует, общий
  `CSectionGeometryQuery` получает наружную границу по оболочкам бетонной сетки
  и вычитает точные отверстия. Источник области: `ElementBoundaryLoops+KnownOpening`.
- Несколько отверстий обрабатываются тем же универсальным контейнером.
- При неизвестном outer сохраняются и прочие пустоты самой сетки. Точное
  отверстие вычитается из нее, но не добавляет бетон на месте отсутствующих
  элементов; совпадение или пересечение с приближенной сеточной пустотой
  не вызывает отказа импорта.
- Отверстия не делают наружную границу достоверной: габариты по сетке
  остаются приблизительными. При известном outer, напротив, сеточная граница
  не используется; отсутствие заданных отверстий означает сплошной бетон.
- Эти правила явно сформулированы в справке по `OpeningContourLayer`.

## Проверки

Доказательства текущего выпуска сохраняются в
`docs/regression/Performance/WorldCoordinates_2026-10-08/`.

Адресные проверки включают отказ до чтения геометрии, ошибку COM, некорректные
типы ответа, настоящий AutoCAD 2023 со смещенной/повернутой ПСК и успешным
импортом в МСК. В отдельном native-сценарии два круговых отверстия без outer
проверяются по аналитической площади, точным пересечениям, ролям, габаритам
сетки и сохранению/чтению Results. Пользовательские чертежи не используются.

Полные старые On/Off и полный Excel UI suite не запускаются: расчетный код
не меняется. Перед публикацией проверяются компиляция, актуальность всего
VBA, воспроизводимая сборка, оформление Config и сохранность данных книги.

Первый кандидат не прошел компиляцию из-за зарезервированного VBA-имени
`local` в новом native-тесте. Имя заменено на `localUCS`; этот кандидат
сохранен в `CompileFailure01`, не опубликован и не считается успешной проверкой.

Первый native-прогон 218/1 остановился на настройке ПСК в новом тесте:
COM-свойство `ActiveUCS` требует присваивания через PROPERTYPUT, а не `Set`.
Тестовая установка исправлена по примеру Autodesk; production-проверка
`GetVariable("WORLDUCS")` от этого не менялась. Неуспешный прогон сохранен
в `NativeSetupFailure01` и не считается доказательством приемки.

Второй native-запуск завис при первом чтении Documents из Excel до создания
тестового чертежа. Остановлен только собственный AutoCAD PID 3452; RPC-ошибка
сохранена в `NativeLaunchFailure02`. Runner теперь заранее создает пустой
документ по стандартному `acadiso.dwt` в своем COM-процессе перед вызовом VBA.

## Финальный Self-Audit

1. Единственный рабочий вызов импорта из Excel проходит через
   `ImportFromActiveDocument -> ImportFromDocument -> RequireWorldCoordinateSystem`.
   Проверка расположена до получения ModelSpace и Layers; writer вызывается
   позже, только после успешного импорта. Обхода guard в пользовательском
   сценарии нет. Низкоуровневые методы остаются адаптерами проверенной геометрии,
   а не альтернативными кнопочными сценариями.
2. Допуск в МСК основан только на машинном WORLDUCS. Имя ПСК, тексты ошибок,
   комментарии или неудача чтения не используются для разрешения импорта.
3. Не добавлены автоматическое переключение ПСК, изменения пользовательского
   DWG, повторное решение НДС или совместимость с прежними снимками.
4. Точные Opening без outer остаются явными контурами. Наружная область
   определяется сеткой; источник и точные дуги сохраняются через Results.
   Обработка нескольких отверстий не зависит от типа сечения.
5. Расчетные алгоритмы, нормативные формулы, материалы, единицы и знаки
   не менялись. Проверка трещин, сборка области взаимодействия и правила
   неделимых арматурных групп остались прежними. Полные старые On/Off и
   полный Excel UI suite не повторялись.
6. Проверены фактические output-файлы, а не только исходники. У текущего
   запроса нет незавершенных обязательных проверок; нормативный статус
   всей программы этим техническим выпуском не переопределяется.
