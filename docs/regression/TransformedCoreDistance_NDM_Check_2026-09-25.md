# Проверка Transformed.CoreDistance по фактическому НДС NDM

Дата проверки: 2026-09-25.

Проверялось несимметричное RectSet / LSection с перекошенным армированием из пользовательского примера:

- `H1 = 550 мм`, `B1 = 250 мм`, `H2 = 250 мм`, `B2 = 600 мм`;
- сетка бетона `50 x 50 мм`;
- на гранях `H1/B1` арматура `d12`, на гранях `H2/B2` арматура `d32`;
- расчетное сжатие `N = 100 тс`, пользовательские моменты `Mx = 0`, `My = 0`;
- устойчивость отключена, проверялся `StrengthState`;
- точка приложения нагрузки задавалась через `Load.ReferenceOffsetX/Y`.

## Контроль воспроизведения расчетного НДС

Перед поиском границ ядра был воспроизведен сохраненный в книге расчет `StrengthState` автономным расчетчиком по данным из `Results`: бетонные элементы, арматура, диаграммы `StrengthState/StateExtension` и та же внутренняя система знаков.

Сохраненное в книге состояние:

| Величина | В книге | Автономная проверка |
|---|---:|---:|
| `epsilon0` | `-0.00029241970589636543` | `-0.00029241970589636527` |
| `kappaX`, 1/мм | `2.3682942567328885E-07` | `2.3682942567328872E-07` |
| `kappaY`, 1/мм | `2.099116927925996E-07` | `2.0991169279259936E-07` |
| max `epsilon_c` | `-6.164677012123166E-05` | `-6.164677012123165E-05` |
| max `sigma_c`, МПа | `-0.6370166245860593` | `-0.6370166245860587` |

Совпадение практически до машинной точности, поэтому дальнейшая проверка действительно идет по тому же НДС, который считает программа.

## Исходные справочные значения

| Величина | Значение |
|---|---:|
| Ц.Т. бетонного сечения, X | `216.304 мм` |
| Ц.Т. бетонного сечения, Y | `316.304 мм` |
| Ц.Т. приведенного сечения, X | `227.930 мм` |
| Ц.Т. приведенного сечения, Y | `289.732 мм` |
| `Transformed.PrincipalAngle` | `0.4766616999 рад` |

Текущая точка пользователя `Load.ReferenceOffsetX = 11.625 мм`, `Load.ReferenceOffsetY = -107.264 мм` соответствует положению:

```text
X = Transformed.CentroidX
Y = Transformed.CentroidY - Transformed.CoreDistanceYMinus
```

То есть пользовательская точка была поставлена ровно на границу `Transformed.CoreDistanceYMinus`, если мерить от выведенного центра тяжести приведенного сечения.

## Причина расхождения

Формулы и знаки `Transformed.CoreDistance...` проверяются корректно для своего смысла: это ядровые расстояния приведенного сечения, посчитанные через обычные модули `Eb/Es`.

В текущем коде это явно сделано в `CNDMResultsWriter`: для геометрического приведения берутся обычные модули `Eb` и `Es`, а не наклон фактической диаграммы `StrengthState`.

Для проверяемого расчета:

| Параметр | Значение |
|---|---:|
| `Eb` для приведенного сечения | `32500 МПа` |
| `Es` | `200000 МПа` |
| `Es / Eb` | `6.154` |
| Наклон сжатой ветви `StrengthState` около нуля | `10333.333 МПа` |
| `Es / Ediag` для фактического НДС | `19.355` |

Из-за этого фактический `StrengthState` работает с другой относительной жесткостью арматуры и бетона, чем справочное приведенное сечение `Transformed.*`. На перекошенном армировании это сильно смещает эффективный центр жесткости и ядро. Поэтому особенно заметно расходятся направления, чувствительные к несимметричной арматуре, например `Y-`.

Дополнительная проверка показала, что найденные фактические границы НДС совпадают с линейной проверкой по касательной жесткости самой диаграммы `StrengthState`. То есть расхождение не похоже на ошибку знака или перестановку `Plus/Minus`; это сравнение разных расчетных моделей:

```text
Transformed.CoreDistance  -> справочное приведенное сечение по Eb/Es.
Фактическое StrengthState -> НДС по диаграмме прочности и ее текущей жесткости.
```

## Вывод

1. Ошибка в направлении `YMinus` по текущему расчету ядровых расстояний не подтвердилась.
2. Расхождение около 20-32% для части направлений реально воспроизводится, но причина в том, что проверка по фактическому `StrengthState` использует другую жесткость материалов, чем справочное `Transformed.CoreDistance`.
3. Если пользователь ожидает, что ядровые расстояния на листе будут границей отсутствия растянутого бетона именно для выбранной диаграммы `StrengthState`, это должен быть отдельный набор выходных величин с другим названием. Подменять текущие `Transformed.CoreDistance...` нельзя: сейчас они соответствуют справочным характеристикам приведенного сечения по обычным модулям.
