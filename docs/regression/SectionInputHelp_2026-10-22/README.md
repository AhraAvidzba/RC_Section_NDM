# Проверка справки сечений

Исходная книга: коммит `2291a24ba2f953acd41f891c955d5eb8d18bee7d`, SHA256
`2A27AEEAAE7B8D9CE59830EF1264DED104E561F6A88068CF8C8604B3A7980525`.
Итоговая книга и нативный ALL CODE находятся в workbook/output.

- Acceptance.json и PublishedVerification.json проверяют реестр, четыре таблицы,
  исходные ссылки и четыре новых перехода, точный текст каталога и сохранность
  частей XLSM. Новые имена и строки не вводились.
- NativeCheck.json: восемь переходов через настоящий Hyperlink.Follow, видимость
  целевой строки после сворачивания, цвет/подчёркивание и Workbook_Open.
- Structure.json: 27/0. VbaEquality.json: 168 компонентов неизменны; в событии
  книги заменён только литерал заголовка. Расчётные тесты не выполнялись.
- Evidence.zip: два нативных экспорта VBA, нативные изображения, каталог и точные
  адреса/высоты изменённых абзацев, хеш скомпилированного VBA-проекта. Манифест хешей —
  EvidenceFiles.json. Копии XLSM с пользовательскими данными в архив не включены.

Для повторной проверки распакуйте Evidence.zip сюда, положите исходную книгу
указанного коммита в Baseline.xlsm и выполните Package.py --verify с путём
проверяемой книги, затем VerifyVba.py. Оба сценария используют bundled Python.
Скомпилированный VBA берётся из проверяемой книги и сверяется с зафиксированным
хешем; второй экземпляр этого большого бинарного файла в архив не включён.
NativeCheck.ps1 открывает указанную книгу только для чтения и проверяет реальные
ссылки; расчёт/генерация/AutoCAD не вызываются.

Обновление делалось на частной копии через Update-SectionInputHelp.ps1.
Excel использован для компиляции событий и нативного вида; конечный пакет
собран точечно, чтобы сохранить остальные части и пользовательские данные.
Одна предварительная попытка остановилась на строгом сравнении регистра
идентификаторов, который редактор VBA меняет автоматически. Данные не менялись;
сравнение исправлено с сохранением проверки точной единственной замены в книге.
