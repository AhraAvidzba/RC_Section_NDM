# Проверка Transformed.CoreDistance для ThreeLine при N = 100 тс

Дата проверки: 2026-09-25.

Проверялось то же несимметричное `RectSet / LSection` с перекошенным армированием, что и в предыдущих проверках ядровых расстояний. Нагрузка:

```text
N = 100 тс
Mx = 0
My = 0
```

Для бетона в модели прочности использована трехлинейная диаграмма `ThreeLine`, построенная по текущим параметрам книги:

```text
(-0.0035; -15.5 МПа)
(-0.0020; -15.5 МПа)
(-0.000286153846; -9.3 МПа)
(0; 0)
```

Начальный наклон сжатой ветви:

```text
Ediag = 32500 МПа
Es / Ediag = 200000 / 32500 = 6.153846
```

То есть начальный наклон диаграммы совпадает с модулем `Eb`, через который считаются справочные характеристики `Transformed.*`.

## Вывод

При `ThreeLine` с начальным наклоном `Eb` сходимость аналитического `Transformed.CoreDistance...` с фактической границей НДС становится практически идеальной: по реальной границе бетонных элементов отличие меньше 1% по всем направлениям.

Оставшаяся небольшая разница объясняется дискретизацией:

- `Transformed.CoreDistance...` считается по геометрическим характеристикам с учетом локальных инерций бетонных элементов;
- проверка НДС ищет нулевую деформацию на границе прямоугольных КЭ;
- выводимые поэлементные напряжения в таблице относятся к центрам КЭ, поэтому по центрам граница получается дальше на 6-11% при шаге сетки 50 мм.

Гипотеза подтвердилась: когда фактическая диаграмма работает с тем же начальным отношением модулей `Es/Eb`, что и аналитическое приведенное сечение, ядровые расстояния хорошо совпадают с фактическим НДС.
