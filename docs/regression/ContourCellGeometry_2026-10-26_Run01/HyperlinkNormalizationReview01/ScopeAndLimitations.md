# Граница проверки повторного создания Hyperlink

Исходная книга для контролей — `ReleaseCandidate05`, SHA256 `86368D1AE3A8DAF0C734DB7573F4ACAC1406C59A95671D2A501B8C6CC96F285F`. Её отдельная строгая проверка пользовательских данных, формул и оформления против принятой main-книги имеет `PASS` в `ReleaseCandidate05/DataPreservation.json`.

После повторного создания 151 уже существующей ссылки `HyperlinkNative05` и `HyperlinkNative06` имеют одинаковые **164** различия нормализованных стилей, вплоть до ячеек и хешей. Строгий верификатор оставлен без изменений, оба первичных результата остаются **REVIEW_REQUIRED**. Успешный выход COM-проверки не переименовывает их в PASS.

Различия ограничены представлением рамок в XML: владельцем общей стороны соседних ячеек и сохранением чёрного цвета как RGB либо эквивалентного indexed 8. Шрифты стилей, заливки, числовые форматы, базовые стили, дочерние параметры выравнивания и apply-флаги в этих 164 парах совпадают. Проверка физических сторон с учётом соседей и объединённых областей сравнила **501 грань** для каждого результата: **0 изменений, 0 конфликтов** (`HyperlinkNative05/SharedEdgePaletteDiagnosis.json`, аналогичный файл для Native06).

Есть также четыре изменения сырого XML rich text на листе «Сечения» A2/A21/A59/A91. Один пробел перед «(Подробнее)» получил явный Calibri 16, bold, black вместо наследования того же шрифта ячейки. Это не нулевое число raw-изменений. Посимвольная проверка с наследованием шрифта и разрешением фактической/стандартной indexed-палитры дала **0 различий эффективного оформления** у обоих результатов (`RichTextAppearance.json`).

Обычный Open/Save исходного кандидата без пересоздания ссылок прошёл прежний строгий верификатор с нулём различий. Безусловное восстановление всех атрибутов ранее добавляло 345 XML-различий, условное сократило их до 164. Более узкое сравнение семантики рамок не изменило оставшиеся 164. Поэтому нельзя доказанно объяснять остаток завершающими Font setter-ами или продолжать исправления рабочего форматирования только ради совпадения стилей XML.

Root выполнил два отдельных контроля того же неизменённого кандидата без VBA. CaptureOnly прочитал атрибуты 151 ссылки дважды без записи и изменения Hyperlink: строгий верификатор дал **PASS, 0 различий**. LinkOnly выполнил только Delete/Value2/Add без захвата и восстановления: получен **REVIEW_REQUIRED, 233 различия стилей**, включая все 233 шрифта и 54 заливки. Чтение getter-ов само по себе не объясняет остаток; API пересоздания ссылок действительно требует восстановления формата. Один конкретный COM-вызов, отвечающий за все 164 остаточных XML-различия после восстановления, этим контролем не выделен. Ограничение касается сохранения сырого представления стилей после всей операции, а не доказанной потери внешнего вида. Полные результаты — `HyperlinkCaptureControl01.Preservation.json`, `HyperlinkAddControl01.Preservation.json`, `LinkOnlyStyleDiagnosis.json`.

До доказанного изменения внешнего вида, данных или действий пользователя дополнительных правок VBA/геометрии/математики из этой нормализации не следует. Исходник SettingsCatalog SHA256 `38DC197C560B6EDA65B3C446440731D65135CEC891B49D3CA76B6970439ED67B` заморожен для FullBuild02. Готовая публикация не должна подменяться диагностическими книгами Native05/06. Полная сборка и финальная нативная проверка имеют собственные gates; эта ограниченная проверка не даёт общий полный PASS проекту.
