# Явные исходы и реальные локали Windows/VBA

Статус: исправления, профильная приёмка, реальные локали и нативная книга проверены; публикация фиксируется коммитом. Исходный опубликованный commit — e5fa63d339232c2d6e9830157429d27ef571cdee, книга AFF765CB9D7126158534C1752DDF0BEE475C3C3765111C66CFD84B4C4AC38698. Полный PASS этой исходной книги сохранён отдельно; новым изменениям он не присваивается.

## Подтверждённые причины и правки

1. `CLimitSearchResult.AddLoadPathHistory` и `CCrackFormationCalculator.LimitSearchFinishLoadPath` прежде пропускали смену статуса при пустой истории. Теперь координатор передаёт явный факт предыдущих попыток через существующий интерфейс. История и диагностика меняют только пояснения; порядок путей, поиск и найденные числа не изменены.
2. `CLoadCombinationReader` устанавливает накопленный Boolean при обнаружении каждой ошибки, отдельно от `errorText`. Нулевые LC и пустые ID обрабатываются по прежним правилам. Дополнительные длительные нагрузки используют `rowHasError`, установленный по результату чтения компоненты. `CSystemSettingsReader` хранит Boolean ошибки ячейки параллельно её пояснению, очищает и расширяет оба массива вместе; отложенная ошибка активного поля не становится default при пустом сообщении.
3. Оба потребителя выбранного НДС — схема и экспорт AutoCAD — проверяют наличие `Epsilon0`, `KappaX`, `KappaY`, `ExtensionUsed`, `Status`, а также прежние проверки значений. Причина отсутствия указывает поле, сочетание и фактический адрес именованной таблицы. Геометрия без НДС разрешена. Структуры Results и файлов не изменены.

В режиме File отсутствие строк НДС непосредственно на листе Excel штатно. Проверяется объединённый логический снимок: `ReadAnchoredResultTable` читает `CurrentCalculationSnapshot.ResultTable` из файла. Проверка не требует дублировать файл на листе. Если обязательного поля нет в самом выбранном НДС, вывод этого НДС отклоняется; это не отсутствие одной геометрии.

## Реальные локали

Использованы временные региональные форматы Windows текущего пользователя `en-US` и `ru-RU`, каждый в новом собственном Excel, No/Yes. Это не подмена через один `Application.DecimalSeparator` или `SetThreadLocale`. Подтверждены Windows locale name/реестр и фактические `CStr(0.5)` / `Format` в VBA: `0.5` и `0,5`. Системная ANSI-кодовая страница и язык интерфейса Windows не менялись, перезагрузка не выполнялась.

Серия WindowsLocales03: 4 окружения × 13 наборов = 52, без ошибок. Проверены строгие числовые границы, реальные Config/таблица LC (880 случаев каждого окружения), duration, интерполяция СП35, оба потребителя снимка, бинарное/Excel-сохранение и повторное чтение, поддерживаемые старые форматы. Все 11 baseline-записей / 39 assertions каждого окружения совпали с исходным полным прогоном, кроме времени.

Первое переключение остановилось до профильных тестов из-за унаследованного Excel `UseSystemSeparators=False`. Ошибка восстановления типа Binary в диагностическом помощнике исправлена; исходные значения/типы всех сохранённых ключей реестра затем восстановлены точно. Вторая попытка выявила ошибку тестового oracle: после строгой проверки СП35 сам тест вызывал `CDbl` для исходной строки `1,5` под en-US и получал 15. Production-интерполяция уже нормализовала свою локальную копию правильно. Исправлен тест; добавлено сравнение реального `Calculate` на Double и строках с точкой/запятой без изменения исходной матрицы. Исходные неуспешные журналы сохранены.

Исходные региональные настройки: `ru-RU`, нестандартная десятичная точка, NBSP для разрядов, `;` для списков. После серии восстановлены исходные значения и типы, а не стандартные значения ru-RU. Собственные экземпляры закрываются по PID и UTC startTicks; пользовательский Excel не закрывался.
