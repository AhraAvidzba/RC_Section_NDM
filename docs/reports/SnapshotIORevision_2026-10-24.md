## Изменения

Исходная сетка, контуры, аннотации и происхождение сечения захватываются при начальном чтении модели, профили — до решателя. После решения полный файл собирается из готовых результатов и этих входных массивов. Повторного чтения Results для сборки файла нет. Подробные таблицы и схема используют тот же готовый снимок в памяти; ручное обновление читает сохранённый снимок. Автоматический путь из памяти существовал уже в исходной книге: новое ускорение не выдаётся за первое включение этого механизма.

Убраны промежуточная пятиколоночная матрица каждого состояния, копия общей матрицы при сериализации, повторная очистка большой таблицы и чтения только что записанных шапок/статусов. Одноцветные соседние строки форматируются непрерывными диапазонами с сохранением пропусков. Чтение небольших двоичных полей буферизуется по 64 КиБ; строки читаются непосредственно в конечный BSTR. Крупные словари UTF-16 записываются единым блоком, дополнительная память ограничена 8 МиБ. Повторение ElementID проверяется точно во всех блоках перед быстрым кодированием. Формат NDMSNP04, порядок данных и точность Double сохранены.

Первый вариант прямого UTF-16 с промежуточной строкой отклонён: он замедлял крупную запись. Выбран вариант с конечным BSTR и блочной записью словарей. Проверка шести синтетических файлов на 50/5000/50000 элементах и 1/5 состояниях дала побайтное совпадение; это измерения IO, без решателя. Для 5000–50000 элементов запись ускорилась на 9,5–30,7%, чтение — на 9,7–14,4% относительно первого кандидата с общими оптимизациями. Эти проценты относятся к кодеку, полное время расчёта приведено отдельно.

## Что остаётся на листе и в памяти

В File сетка, общие геометрические характеристики, использованные диаграммы, аннотации и верхние подробные сводки восстанавливаются на Results. Три информационные строки File удалены: в этом режиме диапазон пуст. Сохранение и кнопка загрузки берут имя из Results.SnapshotName; начальное значение NDM_Snapshot, расширение .ndms добавляется автоматически.

Во всех окончательных автоматических запусках — ноль десериализаций снимка и ноль физических чтений Results между решателем и сохранением. Контрольная старая книга отвергается на первом позднем чтении. Хеширование файла для защиты целостности сохраняется и учитывается во времени; ноль десериализаций не означает отсутствие системных чтений контрольной суммы.

## Сочетания и справка

Пустой CombinationID отключает строку даже с заполненными или ошибочными нагрузками. Заполненный номер с точно нулевыми N/Mx/My пропускается без ошибки; малое ненулевое усилие сохраняется. Исходные строки и формулы не стираются, адрес активного сочетания остаётся адресом его исходной строки. При отсутствии активных сочетаний расчёт не запускается и прежние Results и файл остаются неизменными. Правило включено в основной набор таблицы сочетаний и штатного расчёта и описано в справке.

Справка также объясняет применение отдельных снимков для разных опор и последующего просмотра/оформления без решения НДС. Оформление 151 блока, 736 пунктов, 136 ссылок и 76 изображений проверено нативно вместе со списками, рамками и переходами. Пять стадий формирования/расчёта/обновления сохранили оформление входных листов: по 49940 условий.
