# Единый выбор выводимого сочетания — 28.10.2026

## Результат

Схема Excel и экспорт AutoCAD используют общие `Output.CombinationMode` (`Worst`/`User`) и `Output.CombinationID`. При Worst читается определяющее сочетание сохранённого расчёта, пользовательский ID не используется. При User читается точный ID; отдельного служебного пункта Worst в списке ID нет. Предварительная геометрия не требует выбора рассчитанного сочетания.

Блок Config называется **[Нагрузки, сочетания и диаграммы материалов]**. Его подразделы: **[Нагрузки]**, **[Выводимое сочетание]**, **[Диаграммы материалов]**. Порядок выбора: режим → `General.WorstCombinationCriterion` → пользовательский ID. Заголовки раздела и всех подразделов нативно сверены с аналогичными заголовками Config: шрифт, цвет, заливка, выравнивание, перенос, границы и высота строк совпадают. Нативное изображение просмотрено; длинный заголовок виден полностью.

Пустой подраздел [Импорт] удалён. Список ID напрямую ссылается на `H71:H100`, ProfileId — на видимые имена профилей `J39:M39`. Изменение источников сразу отражается в проверке данных. Удалены скрытые копии списков сочетаний и профилей; список четырёх типов сечения теперь встроен в проверку данных. Служебного имени `rngSectionRecipeTypes` и скрытых столбцов больше нет.

Встроенная Справка, руководство `docs/NDM_User_Guide.md` и комментарии описывают общий выбор. Изменение критерия Worst требует нового расчёта; схема и экспорт сами его не пересчитывают.

- Новые проверки выбора Worst/User, неиспользуемого пустого/ошибочного ID, буквального ID Worst, ошибок активных полей с адресом, сохранённого Worst и прежних допустимых резервных источников; динамические списки и сохранность настроек при обновлении типов сечения. - Всего **39 269/0** в принятых первичных журналах; каждый журнал прочитан полностью. Выход всех собственных Excel подтверждён по PID и UTC-времени запуска, принудительное завершение не применялось. Пользовательские приложения не закрывались. Независимая проверка и сборка шли параллельно только после проверки общего запаса памяти (около 14,6 ГиБ RAM и 19,5 ГиБ commit).
- Readonly-проверка обеих точных книг без импорта/компиляции/сохранения: 175 исходных и 6 документных компонентов, равенство исходникам и шаблону событий, буквальное равенство всех 181 тел Main/Ready, действительные единицы, списки, рамки и стили. 165 остальных нативных компонентов совпали с прежним AllCode без нормализации чисел, кроме регистра кода. Математика, единицы и расчётные алгоритмы не менялись.

Первая адресная проба сохранена отдельно как неуспешная: она выявила преждевременное чтение ошибочного, но выключенного ID и ошибку нового тестового сравнения сохранённых матриц. Условное поле переведено на существующее отложенное чтение настроек; исправлен тестовый индекс матрицы. Все затронутые проверки затем прошли; ожидания не ослаблены.
