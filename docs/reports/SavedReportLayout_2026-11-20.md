# Оформление расчётной книги — 20.11.2026

В основную книгу установлено оформление из сохранённого пользовательского файла.
Все изменения перенесены в `CalculationPresentation.zip`, `WorkbookLayout.json`
и соответствующие исходники сборки. Полная сборка с нуля проверена в Excel.

1. Заголовок Results имеет ровно две строки: «Нагрузки с учётом продольного»
   и «изгиба (если применимо)». Обе записи `CBatchResultWriter` исправлены;
   проверены расчёты Excel/File и последующее восстановление файлового снимка.
2. Отсутствующий Worst даёт прочерк в ID и зависимых полях прочности,
   трещин и устойчивости. Числовой 0 и допустимый ID 0 сохраняются.
   Неожиданные ошибки ссылок и арифметики не скрываются общим IFERROR.
3. Нагрузки в таблицах сочетаний отображаются с одним десятичным знаком;
   точность хранимых чисел не меняется. ID, напряжения и деформации сохраняют
   собственное назначение и точность. Формат сохраняется при расчёте и загрузке снимка.
4. Жёлтая заливка N — RGB(255,217,102) — означает растяжение.
   Условное форматирование трёх входных столбцов N прямо читает INPUT-знак
   из `rngSignConventionSettings`. Проверены оба знака, положительные,
   отрицательные и нулевые значения, в сохранённой и повторно открытой книге.
5. Четыре иллюстрации типов сечений и «Общие_иллюстрации» встроены из
   обновлённых PNG; все пять проверены побайтно в рабочей и чистой книгах.
6. Сохранены поле «Радиус взаимодействия», его положение и размер схемы.
   `SLS.Crack.SP35.InteractionRadiusMode` ссылается на `Расчет!AA40`.
   Список содержит `3d,5d,6d`; пользователь подтвердил работу списка сообщением
   «выпадающий список работает». Полный автоматический UI PASS не заявляется:
   захват окна завершался тайм-аутом. Нативно проверены наличие списка и связь настройки.
7. Проверены все 4034 существующие печатные границы в области четырёх страниц:
   цвет RGB(128,128,128), включая эквивалентные тематические цвета. Тип и
   толщина линий сохранены. Все четыре страницы просмотрены после нативного экспорта.
8. Чистая сборка имеет `SLS.Crack.Code=SP35` и `Stability.Code=SP35`.
   Выбранный пользователем СП63 для трещин в рабочей книге сохранён.
9. Во всех восьми оформленных ячейках статуса прочерк сохраняет зелёную
   заливку, а FAIL — предупреждающую. Ссылки одиночных правил закреплены
   абсолютно, чтобы Excel не смещал их относительно активной ячейки.

Направленная приёмка: 97 проверок рабочей копии, 99 проверок полной чистой
сборки; три штатных сценария заголовка — расчёт Excel, расчёт File и
восстановление File. Исходные формулы/значения 3504 пользовательских ячеек
Config, «Сечения» и «Расчет» сохранены. Сверены 203 нативных компонента VBA
с согласованным коммитом `23b1a731`: единственная рабочая разница — две
строки заголовка `CBatchResultWriter`. Экспорт `VBA_All_Code.txt` актуален.

При первой проверочной сборке снимок раскладки включил служебное имя функции
Excel `_xlfn.IFNA`, не являющееся перемещаемым диапазоном. Его отбор исправлен;
полная сборка повторена успешно. В первой частной проверке File-сценария
геометрия была сформирована только в Excel. Правильный отказ при отсутствии
файла не изменялся: подготовка теста теперь отдельно формирует GeometryPreview
для каждого носителя. Исправленный полный направленный сценарий прошёл.
