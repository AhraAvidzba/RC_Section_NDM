# Совместная работа NDM с другими книгами Excel

По фактическому коду подтверждена работа с данными своей книги и защита от
повторного пересчёта посторонних книг при записи результатов. Полной изоляции
книг в одном экземпляре Excel нет. Утверждение об отсутствии существенных
задержек потребовало бы замеров с конкретными тяжёлыми книгами; таких замеров
в этой проверке не было.

## Проверенные действия кода

Кнопка расчёта передаёт `ThisWorkbook` в `RunSectionCalculationForWorkbook`.
Настройки, входные таблицы, нагрузки и вывод привязаны к переданному объекту
книги. В производственных исходниках не найдено выбора `ActiveWorkbook`,
перебора `Application.Workbooks`, вызовов общего `Application.Calculate`,
`CalculateFull` или `CalculateFullRebuild`. При математическом решении
используются подготовленные объекты и массивы.

`CExcelAppStateGuard.Enter` до подготовки модели сохраняет пять свойств
Application и временно устанавливает ручной пересчёт, отключает события,
обновление экрана и предупреждения. Прерывание переводится в обработчик VBA.
Поэтому запись Results не запускает автоматический пересчёт всех открытых
книг на каждом изменении ячейки.

Явный пересчёт выполняется для входной таблицы в
`CSectionInputSnapshotReader.Capture` и для листа Results в
`CalculateResultsSheet`. Эти обращения привязаны к книге NDM.

В начале проверки сохранённая книга имела SHA256
`1824ea710f54481126dea53ee05eb3501afb15614f21ebf75a5d9e2d676b4a76`,
ALL CODE — `b95b07062bb1dff5ad490178dbbce5b52917d91714b49a16150b62443d7652b1`.
Это принятая и экспортированная версия предыдущего этапа. В контейнере
сохранённой книги отсутствуют части `xl/externalLinks/` со связями на другие
книги. Возможные ссылки на NDM из посторонних книг здесь не проверялись.

## Взаимное влияние, которое сохраняется

Свойства Application общие для всех книг одного экземпляра Excel. На время
макроса другие книги тоже находятся в ручном режиме, без событий и обновления
экрана. VBA-команды выполняются в основном потоке Excel, поэтому длительный
макрос может задерживать работу интерфейса других книг этого экземпляра.
Это свойства среды Excel, а не раздельные настройки каждого Workbook.
[Общие настройки расчёта](https://learn.microsoft.com/en-us/office/vba/excel/concepts/excel-performance/excel-improving-calculation-performance),
[выполнение VBA](https://learn.microsoft.com/en-us/office/client-developer/excel/multithreaded-recalculation-in-excel).

`Restore` возвращает исходный режим Calculation. Если он был автоматическим,
Excel может пересчитать накопившиеся изменения и функции, которые обновляются
при каждом пересчёте, в других открытых книгах. Такая задержка возможна даже
при отсутствии прямых связей данных между книгами.

Поле времени выполнения NDM записывается перед `CalculateResultsSheet` и
`excelGuard.Restore True`, поэтому задержка возврата автоматического режима
в него не входит. Для оценки влияния других книг нужен замер от нажатия кнопки
до полного возвращения управления пользователю.

Посторонние книги также занимают память. Фоновые обновления данных и нагрузка
на процессор не отключаются этим механизмом. По одному исходному коду нельзя
определить их влияние на конкретном компьютере.

## Результат проверки

Новых ошибок сохранения и восстановления настроек не обнаружено. В ранее
принятой версии прошли 185 направленных проверок этого механизма и восемь
проверок рабочих сценариев, включая отказ ввода. Механизм сохранён: каждое
свойство восстанавливается независимо, временный отказ повторяется, исходная
ошибка расчёта не заменяется ошибкой записи отчёта.

Изменения, отключающие расчёт в посторонних книгах, оставляющие Excel в ручном
режиме после макроса или автоматически переносящие NDM в другой процесс,
не вносились. Они требуют отдельного выбора пользователя, поскольку меняют
поведение Excel и других книг.

Раздельные процессы Excel позволяют разделить настройки Application и
выполнение макросов. Microsoft документирует запуск нового процесса командой
`excel.exe /x`; отдельное окно книги само по себе не означает отдельный процесс.
Память и процессор компьютера при этом остаются общими.
[Отдельные экземпляры Excel](https://learn.microsoft.com/en-us/office/vba/excel/concepts/programming-for-the-single-document-interface-in-excel).

## Пояснения к примеру рецепта

После каждой из 13 строк минимального примера в `modSectionRecipeApiGuide`
добавлен комментарий с конкретным смыслом операции. Объявление переменной
отделено от создания объекта; размеры, координаты, ряд из пяти стержней,
группа подписи, размер B и завершение описания пояснены непосредственно
в примере. Обновлён генератор, чтобы пояснения сохранялись при пересборке.
Это изменение комментариев; расчётная логика и общие настройки Excel не менялись.

Проверенная версия перенесена в основную книгу. Проверены 107461 ячейка,
27 именованных диапазонов и 150 VBA-компонентов. Изменились только комментарии
`modSectionRecipeApiGuide` и контрольная строка `Справка!A612`. Данные, формулы,
оформление, рисунки и выполняемый код сохранены. Все 13 команд имеют пояснение
непосредственно в следующей строке. Сопоставление 145 исходных компонентов
с фактическим нативным экспортом опубликованной книги прошло без различий;
4730 текстовых ячеек и 122 элемента справочника прошли проверку самостоятельности.
Расчётные тесты повторно не запускались: изменение состоит из комментариев.
