## Почему path возвращается из facade и затем используется в нём

Это последовательное заполнение одного описания сечения. Например:

```vb
Set path = facade.RectanglePath("Boundary", 0#, 0#, 600#, 1000#)
facade.Outer "OUTER", path.ID
```

Первая команда создаёт точную замкнутую линию и сразу сохраняет её в описании
под именем Boundary. Вторая назначает уже сохранённой линии роль наружной
границы бетона. Она передаёт имя линии, а не повторно создаёт или добавляет
объект. Возвращённый path позволяет прочитать ID, длину и другие свойства.
Линия сама не хранит ссылку на facade и не вызывает его обратно.

Аналогично LinePath создаёт линию центров арматуры, а RebarByCount объявляет,
сколько стержней какого диаметра надо разместить на этой линии. Физические
стержни появляются позднее, при общей сборке. AddPath нужен только для
линии, отдельно подготовленной через CGeometryPath или геометрический сервис.
Повторная регистрация результата RectanglePath/LinePath ошибочна и отклоняется.

## Ответственность и взаимодействия

В состав проверки включён прежний полный аудит 37 классов и пяти модулей
границы интеграции; изменённые контракты повторно проверены по актуальному
коду и в Excel. Добавлен один математический модуль, новых рабочих классов нет.

| Компонент | Ответственность |
|---|---|
| CSectionInputSnapshotReader, CSectionInputTable, CSectionRecipeContext | Снимок значений, адресов и единиц; отделение ячеек Excel от рецепта |
| CUnitSystem | Преобразование единиц и знаков; независимая закрытая копия для контекста |
| ISectionRecipe и четыре штатных CSectionRecipe… | Декларации одного типа сечения по снимку ввода |
| CSectionTypeRegistry | Одна регистрация и выбор рецепта; без геометрических алгоритмов |
| CSectionDefinitionBuilder | Удобные команды создания и регистрации линий, ролей, правил и аннотаций |
| CSectionDefinition | Хранение деклараций и их ссылок; закрытие описания и проверка его инвариантов |
| CGeometryPath | Точная последовательность прямых и дуг; чтение после Seal |
| modGeometryPrimitives | Единственные низкоуровневые формулы сегментов; без модели, состояния и Excel |
| CSectionGeometryQuery, CConcreteRegion, CGeometryRegion | Общие аналитические операции, топология и запросы к бетонной области |
| CRebarRuleExecutor, CRebarLayout | Проверка правил, координаты и физические владельцы стержней |
| CFiberMeshBuilder | Общая бетонная сетка по готовой области |
| CSectionModelBuilder, CSectionModel | Единая расчётная модель и расчётные имена элементов |
| CSectionAnnotationBuilder, CRebarGroupAnnotationBuilder, CSectionAnnotations | Размеры и подписи по готовой геометрии; без изменения арматуры |
| CSectionPropertiesCalculator, расчётные и трещинные потребители | Свойства и инженерные расчёты по общей модели и запросам |
| Results writer/reader, CSectionPlotter, AutoCAD import/export | Сохранение и представление модели; экспорт и схема читают сохранённые данные |

Основной маршрут: снимок ввода → рецепт → завершённое определение → общий
CSectionBuilder → проверка и размещение арматуры → бетонная сетка → модель →
аннотации. Далее расчёт, Results, схема и экспорт используют общие данные.

Разделение соответствует практическому смыслу ООП/SOLID: инварианты защищены
владельцами данных, новый тип подключается через ISectionRecipe и реестр,
геометрическая математика не зависит от Excel, а потребители не выбирают
алгоритмы по типу сечения. Не вводились интерфейсы и классы на каждую формулу.
CSectionGeometryQuery сохраняет операции над областями и контекст запроса к
модели: такое разделение согласовано ТЗ, его алгоритмы не переписывались.

## Закрытие замечаний

| Пункт | Статус и решение |
|---|---|
| 1 / A05: CGeometryPath ↔ CSectionGeometryQuery | Исправлено. Path больше не создаёт query; оба используют modGeometryPrimitives. Перенесены 13 существующих операций, арифметика и допуски сохранены |
| 2 / A02: запись аннотаций в CRebarLayout | Исправлено. Привязки локальны одному Build аннотаций, повторный запуск не накапливает и не использует прежние направления |
| 3: изменяемые Mesh/Rebars/Rules | Исправлено. После успешной сборки изменения запрещены; выдаются те же объекты без копирования больших массивов. Диагностика доступна |
| 4: жизненный цикл, регистрация и повторная геометрия | Исправлено. Создающие команды сразу регистрируют линию; Finish закрывает описание. Убраны повторная подготовка уже готовой границы и построение неиспользуемой разности parent/opening |
| 5: обёртка ConcreteCoverFromPointAlongDirection | Уже исправлено до этой задачи. В CSectionPropertiesCalculator отсутствует; действующие потребители используют query |
| A01: units по внешней изменяемой ссылке | Исправлено. Контекст хранит независимую закрытую копию всех 15 настроек единиц и знаков |
| A03: неиспользуемый axisDistance у подписей | Исправлено. Удалён только аргумент команд подписей; вызовы и справка синхронизированы. as для геометрии арматуры сохранён |
| A04: проверки правил после сетки | Исправлено. Единственный исполнитель проверяет и размещает арматуру до сетки; повторная ValidateOptions убрана. Finish проверяет топологию и ссылки, а не обещает проверку размещения |
| Двойной учёт memberships в подписях | Не подтвердилось как ошибка: сохранено ранее согласованное владение физическим стержнем, memberships служат происхождению |
| Переименование CreateRecipe реестра | Не требуется: зарегистрированные штатные рецепты не хранят состояние сборки; API не переименован |

Каноническая итоговая область по MaterialContours сохранена: она нужна для
прежнего порядка границ и численных свойств. Оптимизация не подменяет её
альтернативной областью. CSectionModel остаётся рабочей изменяемой моделью
с ревизией. Если её геометрия изменена после сборки, getters сборщика
отклоняют старые данные; уже полученная ссылка остаётся закрытым снимком
прежней сборки. Новый Build создаёт новые объекты.

Спорные численные или нормативные изменения не потребовались. Штатные
подписи, группы, контуры, координаты и порядок арматуры сохранены. Исправлены
контрпримеры повторных аннотаций и перенастройки внешних units из аудита.

- Baseline: read-only экспорт 150 компонентов; совпадение 145 исходных
  компонентов и пяти модулей книги/листов. Сохранён архив исходников.
- Первый этап математического выделения: 2731 assertion, все успешны;
  шесть исходных полных снимков побайтно совпали (43 999 634 байта).
- Итоговые 20 геометрических/API-наборов: 4078 assertions, все успешны.
  Включены повторные подписи, смена направления, независимость units,
  защита публикации, жизненный цикл, определения, топология, правила,
  сетка, 92 сценария количественных подписей и примеры API.
- Независимые суммы N/Mx/My для скруглённых и полых сечений, включая
  крайние формы: 1512 assertions, все успешны.
- Учебный рецепт через отдельную регистрацию и общий builder: 356
  assertions, все успешны. Учебный тип не добавлен в рабочий реестр книги.
- Итоговые шесть полных геометрических матриц совпали. Исключены только
  прежние строки ANCHOR — удалённый временный буфер layout; фактические
  строки ANNOTATION сравнивались полностью.
- Десять моделей и 120 прямых решений НДМ (три расчётных назначения,
  N, N+Mx, N+My, N+Mx+My): все решения сошлись, все записанные Double
  побитно совпали с baseline. Baseline не пересчитывался новым рабочим кодом.
- Results → reader → plotter: девять схем Excel совпали по структуре,
  координатам, текстам и пикселям PNG. Полая и смешанная скруглённая формы
  дополнительно просмотрены визуально.
- Итоговый кандидат скомпилирован; read-only экспорт содержит 153
  компонента и совпадает с 148 исходными компонентами плюс пять документов.
  Последние изменения только комментариев проверены отдельно: исполняемый
  код точно соответствует версии, на которой выполнены регрессии.
- XML-приёмка: 107 461 ячейка, 27 имён, настройки, списки, формулы,
  рамки, заголовки, чертёжные объекты сохранены. Кэшированные значения

  девяти разделах. Каталог 278 публичных членов, сигнатуры и ссылки на

Ошибки подготовки тестов не скрыты: исправлены неверные аргументы новой

ожидания геометрии и численные baseline не менялись.

## Выпуск и пределы проверки

Код и кандидат приняты. Публикация основной книги, фактический readback
ALL CODE и заключительный Git-коммит с push — следующий этап; до него
окончательная приёмка распространённой книги не объявляется завершённой.
Чужой RC_Section_NDM_execution_report.txt сохранён и не включается в коммиты.

Полные длительные ON/OFF, ручная Excel UI-приёмка всех экранов и новый
AutoCAD-прогон не запускались по последней редакции цели. Проверки доказывают
сохранность затронутых маршрутов и выбранных решений, а не полную нормативную
верификацию всех возможных входов. Изменения публичных контрактов защитных
методов и удалённого аргумента axisDistance отражены в гайде; неизвестный
сторонний VBA-код должен использовать актуальные сигнатуры.
