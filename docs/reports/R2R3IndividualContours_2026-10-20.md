# Индивидуальные отступы дополнительных рядов: реализация и проверки

Безопасная точка: локальный тег `ndm-before-r2r3-individual-contours-20261020`,
коммит `e75ba9b728193bd4bdb379e8d576b2659fcb7558`.

## Согласованное правило

Пользователь выбрал сохранение координат с допустимыми негладкими стыками.
Координаты Main не меняются. Для R2/R3 сохраняется исходный перенос по нормали,
после проверки применяется прежний сдвиг по касательной. На скруглении
сохраняется точная концентрическая дуга с отступом её исходного участка.
При разных отступах соседей несовпадающие концы соединяются явно прямым
отрезком; касание в этом соединении не обещается. Соседние непараллельные
прямые соединяются пересечением продолжений. Замкнутость, самопересечения,
площадь и направление проверяются до фильтрации стержней. Невозможное
построение является адресной ошибкой, а не основанием массово пропускать ряд.

## Исходный механизм до исправления

- PrepareDependent смещает весь OffsetBoundary одним NormalOffset выбранного
  ряда, поэтому соседние стороны не получают собственных отступов.
- Rectangles создаёт самостоятельные LinePath без OffsetBoundary. Связь с
  общим наружным контуром и исходным прямоугольником нужно передать явно.
- Ветка нескруглённого отверстия HollowRectangle создаёт ограниченную прямую;
  её сохраняем и добавляем только связь с исходным контуром.
- В правилах нет явного общего соответствия R2/R3 разных сторон. Его нужно
  хранить как метаданные, без распознавания суффиксов ID или порядка граней.
- Main имеет разные as по сторонам. Значения передаются через общую связь
  с исходной геометрией; геометрическое совпадение проверяется однозначно.

## Реализация

Затронутые рабочие компоненты:

| Компонент | Ответственность изменения |
| --- | --- |
| CGeometryVariableOffset | Точный замкнутый контур с отдельным отступом каждого участка |
| CRebarOffsetContours | Связи Main/R2/R3 с границами, подготовка областей и соседство граней |
| CSectionDefinition, CSectionDefinitionBuilder | Хранение явных связей и декларативные методы фасада |
| CRebarRuleExecutor | Проверка нормальной позиции, объединение соседних дополнительных стержней и предупреждения |
| CRebarContactBuilder | Включение новой проверки при положительном пользовательском отступе |
| CSectionGeometryQuery | Вызов прежней проверки принадлежности без повторного копирования границ |
| CSectionRecipeCircle, CSectionRecipeRectangles, CSectionRecipePointedSection, CSectionRecipeHollowRectangle | Только передача связей через фасад |
| modSectionRecipeTypes, modSectionRecipeApiGuide | Структура метаданных и описание API |

`CGeometryVariableOffset` строит точную замкнутую проверочную границу.
`CRebarOffsetContours` собирает индивидуальные отступы всех её участков,
отдельно для R2/R3, наружной границы и каждого отверстия. Принадлежность
берётся из `TRebarContourLink`, сохранённого в `CSectionDefinition` через
`CSectionDefinitionBuilder.RebarContour`. `RebarContourBaseline` передаёт
известный as ограничителя без активного Main, в частности у отверстия R=0.

Метаданные содержат исходную замкнутую фигуру, заданный as, явные имена
Main/R2/R3 и при необходимости исходные сегменты и направление в бетон.
Направление устраняет неоднозначность Main посередине сечения. Имена правил,
тип сечения и порядок сторон не используются для угадывания геометрии.
Исчезнувший при as сегмент определяется по сохранённой геометрической
привязке `HasCollapsedSegmentID`, а не по условному названию угла.

`CRebarRuleExecutor` проверяет нормальную позицию до касательного смещения,
сохраняет прежнюю формулу координат, ID и диагностику. `CRebarContactBuilder`
включает новый режим при любом положительном базовом отступе; оба нулевых
отступа оставляют прежнюю ветку. Контактные 2,5 мм, Stacked/SideBySide,
EachBar/EverySecondBar, проверка полного диска и пересечений сохранены.
Рецепты Circle, Rectangles, PointedSection и HollowRectangle передают только
связи; собственного смещения контура или фильтрации стержней в них нет.

Прежние `CGeometryPath`, `CSectionGeometryQuery.OffsetPath` и
`OffsetRoundedPolygon` не изменены. Main, бетон и расчётное ядро не менялись.

## Уточнение пользователя: исчезновение скругления

Исчезнувшее при отступе скругление не является ошибкой. Оно удаляется,
а соседние прямые продолжаются до пересечения. Оставшиеся точные дуги
не аппроксимируются. Если исчез весь круг или после сопряжения получается
вырождение либо самопересечение всей области, построение завершается
адресной ошибкой. Ошибки невозможного контура не заменяются массовым
пропуском стержней. Фактическое наложение стержней проверяется отдельно.

Для примера пользователя B=300, H=500, R=100 мм, полный отступ сверху
с обеими дугами 60 мм, боковые отступы 20 мм:

- верхние дуги имеют R=40 мм;
- справа разрыв закрывается отрезком (280;400)—(240;400), слева —
  (60;400)—(20;400), по 40 мм;
- все пять угловых/средних позиций верхнего R2 сохраняются без перемещения;
- при полном верхнем отступе 100 мм дуги исчезают, верх становится
  отрезком (20;400)—(280;400);
- при 120 мм верх становится отрезком (20;380)—(280;380).

Координаты указаны от левого нижнего угла. Оба направления обхода проверены.
Если 60 мм заданы как a2 сверх as, полный отступ включает также as и
контактную поправку своей группы; его нельзя отождествлять с 60 мм от бетона.

OneRect: верх 150/200 мм отдельно, затем все четыре стороны; прямой и
обратный обход, EverySecondBar. Без соседних дополнительных рядов верх
сохраняет пять позиций, со всеми сторонами — три, при EverySecondBar — одну.
Каждый пропуск записан с кодом OFFSET_POSITION_SKIPPED, источником и
координатами. Верхние позиции не получают боковой отступ выбранного ряда.

исходного Main. Отдельно проверены Stacked/SideBySide, выключенный R2,

Сохранённый пример PointedSection проверяет R80/as40: при 39,99/40 мм
создаётся пять стержней, при 50/80 мм — четыре с одним предупреждением.

## Объединение и фактические подписи

По отдельному указанию пользователя любое пересечение дополнительных
стержней соседних граней в новом режиме допускает объединение. Остаётся
первый фактически добавленный стержень с его координатами, диаметром и
материалом, даже при разных диаметрах. Второй не добавляет площадь или
инерцию. Соседство определяется общей геометрической вершиной разных
исходных участков одной бетонной границы; имена граней не разбираются.
Main, несоседние грани и разные ряды одного Main под это исключение не попадают.
Простое касание без пересечения не вызывает объединения.

Исполнитель сохраняет связь обоих правил с первым физическим стержнем,
счётчик Merged и предупреждение OFFSET_NEIGHBOR_MERGED. В подпись входит
только основная группа фактического владельца: дополнительная связь
не добавляет количество у второй грани. Пустая группа не получает подпись.
Шестнадцать комбинаций проверяют совпадение/частичное пересечение/касание,
оба порядка добавления, разные диаметры, R2/R3 и наличие основных групп.
Проверены точные тексты, итоговая площадь и отказ у противоположных граней:
264 проверки без отказов в каждом режиме.

## Скорость и границы оптимизации

Вся подготовка остаётся в общих классах. Рецепты дополнительных циклов
не получили. Для проверки точек массив границ подготавливается один раз;
новый ContainsPreparedPoint вызывает прежний ContainsRaw без копирования.
Операции OffsetPath и OffsetRoundedPolygon не изменены.

Правила и бетонные границы индексируются по точным ID; R2/R3 хранят готовые
номера правил. Участки индексируются по семейству и бетонной границе,
соседство запоминается после первой проверки пары. Массивы новых связей,
участков и результирующих рёбер растут с удвоением. Поиск пересекающихся
стержней использует существующие координатные ячейки; прохода по всем
ранее добавленным стержням нет. Среди подходящих выбирается первый
физический владелец, независимо от порядка обхода ячеек индекса.

Контроль 100/1000/5000 исходных стержней даёт 300/3000/15000 фактических
стержней с двумя дополнительными рядами. Полная сборка геометрии и рядов
занимает приблизительно 0,06/0,4/2,0 с. Сетка, НДС и вывод не входят в этот
узкий замер. Побитно совпали 18 300 записей координат и диаметров до/после
оптимизации. Разброс отдельных измерений порядка нескольких процентов;
существенное ускорение по этим коротким замерам не заявляется.

Сопоставление исходных геометрических участков и проверка самопересечений
при однократной подготовке могут включать попарные проверки рёбер.
Для штатных форм число таких рёбер невелико. Дополнительные сложные
геометрические индексы ради этого не вводились; зависимости от квадрата
числа стержней в добавленном обычном проходе нет.
Проверка принадлежности одной позиции проходит по рёбрам подготовленной
области: для B стержней и E рёбер её стоимость O(B*E). При очень большом
пользовательском контуре она также может стать заметной; измерения
100/1000/5000 относятся к штатной границе с фиксированным числом рёбер.
