# Задержки формирования и расчёта — 28.10.2026

## Результат

Замедление лёгкого сечения подтвердилось при сравнении с кодом до точных границ элементов. Сам решатель не стал медленным: в измеренном случае Auto 0.1 он занимает около 0,03 с. Основная добавка возникла при восстановлении и проверке точных границ, подготовке сохранённого снимка и чтении схемы. Генератор сетки при повторном расчёте не вызывается.

Убраны повторный поиск одних и тех же колонок/единиц и создание двух рабочих COM-словарей для каждого элемента. Один проверенный заголовок и рабочие словари используются в пределах одного чтения. Общий геометрический валидатор, проверка топологии, площадей, центров, инерций и все числовые допуски сохранены. Между действиями кэша нет; доверительный режим и пропуск проверок по хешу не вводились.

Дополнительно исправлен подтверждённый дефект File: номер запуска контуров из файла сравнивался с номером запуска справочной геометрии на Results. Теперь обе матрицы читаются через общий источник Excel/File. Устаревший RunID на Results больше не блокирует правильный файл. Добавлены проверки для Adaptive и Contour.

## Где расходовалось время

Для Auto 0.1 до исправления измерены примерно 0,278 с восстановления геометрии, 0,214 с проверки подготовленного снимка и 0,266 с чтения данных схемы. Подготовка числовых результатов занимала около 0,035 с, решатель — около 0,031 с. Настройки читались примерно за 0,006 с. Поиск заголовков и создание рабочих словарей внутри каждого элемента повторялись при этих чтениях.

Восстановление настроек Excel занимало около 0,010 с. В отдельной пробе настоящей кнопки `RunSectionCalculation` основная функция заняла 0,904 с; форматирование сообщения — 0,00070 с. После фактического возврата MessageBox по OK оставшийся код завершился за 0,000023 с, обработка очереди Excel — за 0,0405 с. Ready=True, CalculationState=0. Открытое сообщение ожидало ответа 20,18 с; это не вычислительное время. Длительную работу после OK не воспроизвели.

Начальный общий пересчёт входных формул сохранён: он нужен для актуальности зависимостей. В измерительном Excel была одна книга; стоимость пересчёта других книг в том же экземпляре этим опытом не оценивалась. Холодная загрузка VBA и текущая нагрузка Windows также могут менять ощущаемую паузу.

## Блочное чтение и запись

- `ReadPhysicalResultTable` получает всю прямоугольную таблицу одним `Resize(...).Value2`; размеры определяются блоками 1024–32768 ячеек, а не запросом к каждой строке.
- `CNDMResultsWriter` и четыре writer-а сводок передают готовые двумерные массивы. В наблюдаемом восстановлении семь нижних таблиц дали семь присваиваний массивов, а не присваивание каждой строки.
- `CCalculationSnapshotStore` кодирует колонки в памяти; плотные Double-массивы передаются целыми блоками. `CBinarySnapshotFile` объединяет мелкие записи и чтения в буферы по 64 КиБ; большие блоки проходят напрямую. Отдельного системного ReadFile/WriteFile на каждую ячейку нет.
- Отдельные скалярные операции для времени, выбора сочетания и заголовков остаются. Фигуры схемы создаются поэлементно; это отрисовка, не построчное чтение расчётных данных.
