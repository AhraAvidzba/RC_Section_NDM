# Названия сечений, настройка формы и сообщения об ошибках

Рабочая книга заново собрана из исходников. Пользовательский ввод перенесён
из сохранённой перед работой копии; прежние Results очищены полной сборкой.
ALL CODE выгружен из опубликованной книги. Направленная приёмка завершена;
полные ON/OFF и часовой расчётный план по просьбе пользователя не запускались.

## Изменения

- `PointedRect` переименован в `PointedSection`, класс —
  `CSectionRecipePointedSection`, таблица — `rngPointedSectionGeometry`.
  Видимое название — «Клиновидное сечение».
- `RectSet` переименован в `Rectangles`, класс — `CSectionRecipeRectangles`,
  таблица — `rngRectanglesGeometry`. Заголовок —
  «Набор прямоугольников (Г-сечение)».
- Заголовок HollowRectangle — «Пустотелый прямоугольник».
- Все четыре ссылки «Подробнее» над таблицами имеют шрифт 12 pt.
  Положение таблиц, высоты строк и размеры объектов задаёт сборщик.
- У PointedSection удалены `Left.Type` и `Right.Type`, включая выпадающие списки.
  Каждая сторона определяется только своим W: 0 — без выступа; положительное
  значение — с выступом. R1 задаёт верхнее и нижнее скругления стороны;
  R2 используется только у вершины включённого выступа. Отрицательные,
  пустые и текстовые W дают ошибку ввода, а не скрытый выбор формы.
- У Rectangles оставлены только `TwoRect` и `OneRect`. TwoRect строит два
  прямоугольника с заданным XOffset; OneRect — первый прямоугольник,
  игнорируя размеры, армирование второго и XOffset. Прямоугольники TwoRect
  должны соприкасаться по участку ненулевой длины. Ограничение B1 < B2
  прежнего LSection больше не нужно. Старые варианты и aliases отвергаются.

Рецепт по-прежнему только описывает геометрию. Проверка допустимости скругления
находится в общем `CSectionGeometryQuery`: проверяются угол поворота, различимость
концов дуги с точностью ядра, пересечение соседних скруглений и всего контура.
Малое положительное W не приравнивается к нулю. Недопустимая дуга даёт понятную
причину, адреса исходных размеров и возможное исправление. Радиусы автоматически
не уменьшаются; отдельной формулы проверки W в рецепте не добавлено.

Ошибки геометрии оформляет общий `SectionRecipeErrorText`: сначала «Адреса ячеек»,
затем название сечения/стороны, конкретный ряд или стержень и причина;
«Возможное решение» выводится отдельным абзацем. `WorkbookErrorMessage` отделяет
операцию и технические сведения и так же оформляет сообщения обычных настроек
Config. Для отсутствующей строки адрес не придумывается: показывается раздел.
Коды ошибок, статусы и расчётные причины сохранены.

Обновлены реестр, рецепты, комментарии, Справка, API, сборочные инструменты
и действующие тестовые данные. В рабочем VBA нет адаптера старых настроек;
перенос сохранённого ввода выполнен отдельным внешним инструментом один раз.
Исторические отчёты и исходное ТЗ не переписывались.

## Сохранение данных и проверки

До замены сохранена локальная копия `Before.xlsm`. Проверены 707 перенесённых
полей Config/«Расчёт» и все 292 редактируемых поля геометрии/армирования.
У прежней Simple-стороны W установлен в 0; у прежнего LSection — XOffset = 0:
именно эти размеры раньше фактически использовались. Остальные значения
сохранены. Пользовательский `execution_report` не изменён и не включён в коммит.

На фактическом VBA Excel:

| Проверка | Результат |
|---|---:|
| Направленные проверки геометрии, ввода и материалов | 33 992, без отказов |
| W и оформление сообщений, в том числе обе стороны и мм/см/м | 64, без отказов |
| Обязательные геометрические поля | 922, без отказов |
| TwoRect/OneRect, отрицательные/пустые поля и удалённые варианты | 309, без отказов |
| Расположение, размеры и оформление книги | 1 720, без отказов |
| Поля по умолчанию независимой сборки | 296 |
| Формулы единиц / варианты списков | 54 / 170 |
| Исходные компоненты / всего компонентов VBE | 155 / 161, полное совпадение |
| Члены полного API-каталога | 322, сигнатуры и примеры сверены |

Строки с 64, 922 и 309 проверками входят в 33 992; они не суммируются повторно.
Также прошли 14 проверок независимого анализатора и защиты полноты будущего
полного набора. Восстановлена его тестовая зависимость SciPy; книге она не нужна.

Независимая сверка native-снимков: 24 клиновидных и 18 прямоугольных схем,
203 790 числовых полей совпали побитно. Сохранены контуры, бетонная сетка,
координаты/диаметры стержней, свойства и аннотации. Из строковых полей изменены
согласованные названия сечений; отдельное сравнение входных таблиц учитывает
удаление строк Type и изменение вариантов Shape. Расчётные допуски не менялись.

В ранних проверочных запусках были исправлены два ошибочно записанных имени
entrypoint-ов, восемь ожиданий подписи круга после переноса строки и 25 ожиданий
записи места обычной настройки: её reader пишет «лист Config, ячейка …», а reader
геометрии — `Config!…`. Проверки фактических адресов сохранены. Один итоговый
контроль хеша столкнулся с открытием исходного проверочного файла для подготовки
копии; итоговые запуски используют неизменяемые источники. Эти попытки не выданы
за успешные и сохранены в архиве доказательств.

`RunSharedConfigPreflightTests` в раннем Directed04 превысил 420 с. Он остаётся
на повтор в составе отложенной полной приёмки. Общий PASS полного ON/OFF не
объявляется. Набор для следующего полного запуска обновлён до 144 suites
(включая новый W-тест в обоих режимах) и обязательного часового плана;
ничего из этого автоматически не запускалось.
