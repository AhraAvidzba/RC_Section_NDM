# Текущие результаты Excel и полные снимки File — 24.10.2026

По согласованному с пользователем решению Excel хранит текущие результаты,
а независимое полное восстановление подробных таблиц и переключение сохранённых
расчётов доступны только в File. Пользователь отдельно разрешил вернуть читаемые
LC-строки в прежние таблицы свойств и аннотаций.

`rngNDMLoadCaseResults` удалён из книги, сборщика и WorkbookLayout.json.
Удалены его сериализация, Base64, чтение и временные файлы MSXML. Дополнительного
архива в Excel больше нет. Старый одноразовый Update-CalculationSnapshot.ps1,
создававший этот диапазон, удалён. Исторические доказательства не изменялись.

После обычного расчёта оба режима сразу заполняют все верхние таблицы из готовых
массивов в памяти. В Excel состояния элементов записываются на лист, LC-свойства
и поле деформаций — читаемыми строками в таблицу характеристик, области трещин —
в аннотации. Ручная кнопка обновляет схему по Results, не восстанавливая и не
перезаписывая верхние таблицы. Results.SnapshotName и прежняя файловая привязка
не используются для такого чтения; контекст расчёта после операции освобождается.

В File сохранён прежний полный NDMSNP04: 16 матриц, численные значения без
округления, Unicode, SHA256 и атомарная замена одного .ndm. Кнопка читает выбранное
в Config имя и восстанавливает все результаты. Смена файлов, прежний суффикс
.ndms, проверка повреждения и сохранённые профили остаются доступны. Текущие
входные данные при загрузке файла не заменяются. Справка обоих параметров теперь
явно различает эти действия. Имя по умолчанию NDM_Snapshot, без расширения.

Шесть нижних таблиц расположены в порядке: сетка, характеристики, диаграммы,
состояния, контуры, аннотации. Контуры перенесены с BC в AY, аннотации с BV в BR;
между фактическими границами каждой соседней пары ровно два свободных столбца.
Верхние якоря не менялись. Ширины назначаются сборщиком, рабочий расчёт их не меняет.
