# Audit03: Структура Несмежных Config-Диапазонов

## Scope И Подтвержденные Дефекты

Срез после `91cdddb0`. Проверяются существующий CSystemSettingsReader,
именованные таблицы материалов и автономный LoadFromRange. Новых классов,
расчетных формул, правил Search и численных допусков нет.

Frozen negative v246: 93/64. Настоящий Excel Union.Range имеет две области,
но его Value2 возвращает только строки первой области. Во всех двенадцати
прямых сценариях reader принимает этот неполный массив без ошибки; контрольная
строка второй области не читается. Это подтвержденная потеря части ввода,
а не предположение по документации Excel.

В данной среде Excel не разрешает созданные объединенные Name через
RefersToRange. Обязательные таблицы уже получают контролируемую ошибку 4316;
этот существующий механизм не изменен. Однако существующие поврежденные
имена двух таблиц материалов раньше молча пропускались как отсутствующие.
Последующий запрос параметра давал ошибку отсутствующей строки 4311 вместо
ошибки поврежденной ссылки таблицы. Проверены оба положения каждого имени.

V239-v245 не являются отрицательными production gates: они завершились 0/1
при создании или разрешении тестовой объединенной ссылки, до проверки reader-а.
Попытки записи RefersTo/RefersToLocal и Range.Name сохранены в журналах как
setup failure/NotRun. Окончательный fixture сохраняет прямой Union.Range
отдельно от недоступного Name; ошибки подготовки не объявляются дефектами
программы или успешными проверками.

## Изменения

- AppendSettingsRange проверяет Areas.Count до чтения Value2. Таблица должна
  занимать одну непрерывную прямоугольную область. Ошибка содержит текущие
  лист/адрес и действие для восстановления ссылки.
- AppendNamedSettingsRangeIfExists различает отсутствие имени и поврежденную
  ссылку существующего имени. Отсутствующая необязательная таблица по-прежнему
  допускается reader-ом; ее обязательные параметры проверяет потребитель.
  Существующая недоступная таблица материалов дает ошибку структуры 4316.
- Новый тест добавлен в существующий modTestConfiguration и общий интерфейсный
  suite. При тестировании не вызывается НДС и не меняется пользовательская книга.
- Справка объясняет непрерывность таблиц, восстановление Name, допустимость
  перемещения целой таблицы и отличие отсутствующего optional-ввода от
  существующего поврежденного имени.

## Реальные Проверки

Шесть форматов: Units, Signs, Concrete, Steel, System и Annotations. Вход
копируется из настоящих таблиц собранной книги в собственный InputConfig.
Для каждого формата проверены исходное положение и CH800, две области,
оба entrypoint-а, исходный typed error, восстановление и отсутствие solve.
Всего 24 ошибочных сценария; assertions считаются отдельно от сценариев.

Адрес проверяется у прямого Range, который действительно доступен reader-у.
Для недоступного Name адрес физической ячейки не угадывается: проверяются
имя таблицы, причина и действие. Этот runtime опыт не доказывает выполнение
ветки Areas.Count через Name.RefersToRange в данной среде.

## Ограничения И Следующий Объем

Новые поля Config не получают acceptance только по структурному guard-у.
Реестр остается 707/1064 active-reviewed, 53 editable pending,
fullAcceptance=False. Края всех значений, pairwise/mutation, геометрические
шапки/ключи и прочие неразрешимые geometry Names остаются отдельными задачами.

Этот срез не является полным восьми-suite On/Off, пиксельной UI-приемкой или
проверкой DWG. Общий выпускной gate сохраняется. Main output, audit specification
и пользовательский Excel PID 23476 сохранены; новые архитектурные задачи
не вводились. Итоговый Audit03 и final report еще не завершены.
