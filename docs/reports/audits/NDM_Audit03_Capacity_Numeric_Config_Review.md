# Audit03: Численные Настройки Capacity

Дата: 2026-10-04. Направленная приемка семи полей Config; не финальный выпуск.

## Границы Среза

Проверяются Capacity.SolverMaxIterations, ToleranceStrain, MaxLambda,
InitialLambda, ToleranceLambda, MaxRetries и BaseLoadSteps. Нагрузки задаются
во внутренних единицах, а реальные ячейки System/Units/Profiles читаются
штатными reader-ами. Модель: круг диаметром 300 мм, 12 стержней диаметром
16 мм на радиусе 120 мм; N = 130000 Н, Mx = 5200000 Н*мм, My = 2600000 Н*мм.
Путь NMxy выбран явно. Материалы берутся из фактического Config, не из
тестового заменителя Search. Настройки таблицы проверяются в исходном месте
и после переадресации имени на CH800.

## Подтвержденный Дефект

Ошибки диапазона семи численных настроек классифицировались как InputErr,
но сообщения низкоуровневого CapacitySolver не содержали фактическую ячейку.
Для SolverMaxIterations терялись также ключ и конкретное действие пользователя.
Writer уже выгружал готовые комментарии; он не был причиной потери адреса.

Воспроизводимый negative v249: 2318 passed / 34 failed, watchdog exit=1,
source unchanged=True. Все 34 failures относятся к этому дефекту.
Предшествующий v248: 2196/38; четыре дополнительных failures были ошибками
нового test oracle, а не production. Они сохранены, не объявлены приемкой:
одна итерация Newton включает несколько оценок Якобиана/line-search;
строгий финальный контроль равновесия вправе привести к одинаковой точке
при разных допустимых ToleranceStrain.

## Исправление

CCapacityCalculator.ValidateSettings проверяет диапазоны собственных численных
параметров. CBatchSectionCalculator передает прочитанные настройки и вызывает
этот gate перед решателем. CSystemSettingsReader.InputErrorMessage добавляет
адрес из текущей named-таблицы. Новых классов, схем статусов и writer-логики нет.
При некорректном Config сохраняется ошибка ввода до выполнения Search, без
фиктивного предела или подстановки нулевых расчетных результатов.

Положительные величины и неотрицательный целый MaxRetries остаются допустимыми.
Дробные счетчики отвергает существующий GetLong. Автономные низкоуровневые
API и их защитные проверки не удаляются. Принятые фабричные defaults отсутствующих
optional numeric keys не изменяются этим срезом; явные blank/TODO/неверные
значения не заменяются defaults. Это не доказательство полной приемки
контрактов отсутствующих ключей каждой настройки.

## Поведенческие Проверки

- MaxLambda = 0.125 ограничивает последнюю пробу, возвращает
  SEARCH_BOUND_REACHED без подставной физической точки.
- InitialLambda = 0.125 меняет первую положительную пробу и число точек,
  сохраняя физический предел в прежнем допуске.
- ToleranceLambda = 0.001 вместо 0.000001 уменьшает число проб Bisection;
  конечная точка независимо проверяется по равновесию и физическому диапазону.
- BaseLoadSteps = 1/3 подтверждается реальными step=1/step=3 в solver-диагностике
  одной и той же малой положительной lambda-точки, без retries.
- MaxRetries = 0/2 при действительном лимите одной итерации НДС меняет
  реальные попытки 0 против 0/1/2; попытки 3 нет, ложной предельной точки нет.
- SolverMaxIterations = 1 вместо 60 ограничивает Newton и дает typed
  numerical failure без limit point; число оценок плоскости не подменяется
  счетчиком Newton-итераций.
- ToleranceStrain проверяется и реальным Search с сохранением его физической
  точки, и настоящим критерием остановки Capacity-контекста. Дополнительный
  реальный batch с damping = 0.5 изолирует влияние деформационного допуска:
  изменение только ToleranceStrain дает 216 -> 256 оценок и lambda
  4.70865403902652 -> 4.71145166569015. Component-specific допуски этого
  отдельного fixture заданы до прогона: 1000 Н, 100000 Н*мм; старые тестовые
  допуски и эталоны не менялись. Обе точки остаются физически допустимыми.
  Для сохраненной
  плоскости определяется действительный критический материал/знак, затем
  rLimit = 0.001 принимается грубым допуском и отвергается строгим.
  Этот контрольный residual не публикуется как предельное состояние.
- Пять допустимых одномерных параметров не меняют успешный UltimateStrain.
  Все семь допустимых Capacity-параметров не меняют Formation и число solve
  в PR2, где несущая способность не запрошена; ширина и sigma_s совпадают точно.
- В двух положениях таблицы проверяются blank/TODO/text/CVErr/negative/zero,
  дробные счетчики и recovery. MaxRetries = 0 является корректным отключением.
  ResultComment проверяется в соответствующих detailed-блоках и batch summary.
