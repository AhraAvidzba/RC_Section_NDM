## Метод Измерения

`tools/build_workbook/Run-Audit03PerformanceComparison.ps1` запускает реальные
VBA-расчеты через Excel COM на временных копиях двух книг. Исходные книги
проверяются SHA-256 до/после. Счетчики не входят в production-код. По пять
повторов каждого сценария; быстрые Hollow/Tapered проверки выполняются пакетами
по 25 повторений. Для пяти наблюдений верхний эмпирический P95 равен максимуму.

Сохраняются существующие физические expected values и tolerance. Проверки
критерия, равновесия, конечности результата и отсутствие неподтвержденного
physical outcome не заменены одним `Converged=True`.

Измеряются отдельно geometry/core/packaging/write, solve, iterations, retries,
probe/state reuse, размеры модели и повторные эквивалентные solve-attempts.
Попытки сравниваются по точным scalar options, target, исходной плоскости и
нагрузке, идентичности сечения/материалов, без строкового округления Double.
Одинаковый target с другим стартом не считается дубликатом. Это диагностический
индекс попыток, а не кэш failed physical states.

Среда логов v2-v4: Excel 16.0, build 10417, 32-bit; Windows 10, PowerShell 5.1.
Полные версии среды, SHA книг и effective Extension записаны в исходных логах.
Штатные test fixtures явно задают собственные настройки; общий mode не
переопределяет исторические explicit-On сценарии.

Кеш инвалидируется каждым поддерживаемым Initialize. Проверены
valid-invalid-valid, сохранение причины, новая пустота, fresh-object equivalence,
граничные точки, area и арматура штатными suites. ValidateCurrentGeometry
содержит прежнюю проверку без изменения числа сегментов и геометрических допусков.

Первое exact-grid сравнение v22/v24 не прошло: одна нижняя граничная строка

контрольной книги использовала округленный текст, свежий импорт текущей книги

константы одинаково округленными. Импорт полного неизмененного литерала v26

## Точная Эквивалентность Retry P01

Десять повторов Asymmetric оказались одинаковыми active-set retries при
возврате к ранее неудачной высокой lambda после улучшения соседней точки.
Основной solve использует новый полезный warm start и не должен пропускаться.
Но отдельные direct retries строят прежнюю плоскость и прежние options.

Runner хранит только короткие записи численных неудач одной capacity-search
session: identity материалов/сечения, revision сечения, target, плоскость,
начальная нагрузка и полный набор solve-options. Другая плоскость/options
дает новую попытку. Успешные states и terminal ошибки сюда не записываются;
shared StateRepository не используется. Максимум 64 scalar-записи, вытесненная
запись не запрещает повтор. Завершение поиска уничтожает session.

`p01_retry_session_v29_2026-10-02.txt`: 22/0, в том числе другой target,
plane/tolerance/load steps/line search/context/revision, recovery, terminal
configuration, ограничение памяти и повтор после вытеснения. Полный Off v29:
8390/0 и On 8391/0; source contracts 101/101, 0 ошибок.

P03: строки residual retry форматируются только при DiagnosticsEnabled.
Добавлен независимый счетчик FormatNumberInvariant во временной benchmark-копии
для сценария diagnostics_off.

Счетчик duplicate attempts для сценариев, содержащих несколько независимых
расчетов, не используется для оценки допустимого reuse между запросами: object
addresses могут переиспользоваться после освобождения fixture. Asymmetric -
один конкретный capacity request; именно его scope был отдельно подтвержден.
В обычных случаях нет необъясненных тяжелых регрессий; короткие времена находятся
в диапазоне timer/Excel шума. Бounded-memory/recovery acceptance: RETRY 22/0.
