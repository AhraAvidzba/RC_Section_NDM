# Audit03: Восстановление Геометрии Из Results

Дата: 2026-10-04. Срез v200-v204 после checkpoint `59987235128fce0661069239a43d675cf5bbca9c`.

## Рабочий Контракт

`modAutoCADStressExport.ReadSectionGeometryFromResults` восстанавливает
`CSectionModel` не только для экспорта: этот же публичный маршрут используется
при расчете с `Geometry.Source = AutoCAD`. Поэтому поврежденное число в
сохраненном снимке нельзя молча превратить в ноль или числовой префикс.
Текущие INPUT/OUTPUT units не заменяют единицы уже сохраненной таблицы Results.

`CSectionPlotDataReader` читает тот же снимок для geometry-only preview и
визуализации готового состояния. Эти операции не запускают solver и не
переимпортируют AutoCAD. Диаметр бетона и отсутствующая прямоугольная оболочка
могут быть пустыми; координаты, площадь и диаметр арматуры обязательны.

## Контрпримеры И Исправления

| Проверка | Отрицательное Доказательство | Изменение Текущего Контракта |
| --- | --- | --- |
| Последняя строка листа | v200b: последний элемент не восстанавливался | Граница определяется через `Rows.Count - anchor.Row`, последняя строка включена. |
| Последний столбец листа | v202: чтение выходило за границу листа | Число столбцов ограничено фактическим остатком листа. |
| Нечисловые geometry cells | v200b/v202: числовой префикс, ноль либо raw error | Явное различение пустоты, `CVErr`, `Null`, Boolean/Date и числа до `CDbl`; сообщение содержит поле, текущий адрес и действие. |
| Preview и готовое State | v202: `SafeDouble` скрывал повреждение геометрии | Обе ветви проверяют численные поля до добавления элемента. |
| Заголовок формы | v200b: missing/raw failure | `GeometryInterpretationStatus` и `ShapeType` поддерживаются явно; отсутствие обоих дает сообщение с именем отсутствующего столбца, листом Results и действием восстановления снимка. |
| Поздний LC comment | v200b: ограничение offset 1000 | Чтение продолжается до первой пустой строки таблицы либо конца листа. |
| Пересчет единиц | Private factor tables дублировали `CUnitSystem` | Все масштабы делегированы существующему адаптеру с явной сохраненной единицей; порядок арифметики кривизны сохранен. |

Ошибки новых test fixtures сохранены отдельно, а не объявлены production bugs:
v200 `0/1` имел двухколоночную settings table; единственный отказ v201 `566/1`
ожидал ширину 125 при неизменной площади и высоте. Исправленный numeric-text
fixture использует исходную согласованную ширину 123.75. Исторические
численные expected/tolerance не изменены. Locale-дефект на текущей машине не
заявлен: десятичные значения уже читались точно.

Отдельно воспроизведено, что VBA может преобразовать `CVErr` в числовой код
ошибки через `CDbl`. Поэтому обработка formula error нужна до числового
преобразования, а не только в обработчике исключения.

После проверки карты вызовов удалены неиспользуемые private unit wrappers,
`ReadFirstExportLoad` и его два private helper-а. Публичные расчетные,
импортные и экспортные entrypoint-ы сохранены; новых классов нет.

## Границы Оставшейся Проверки

Live Region/DWG и реальные окна AutoCAD этим fixture не проверены. Оставшиеся
настройки draw/export, поврежденные численные свойства/строки State, полный
general Plot и annotation behavior входят в дальнейший gate. Статическое
чтение не подменяет runtime-доказательства.

`ResetReaderState` дополнен сбросом `mProfileCrackWidthEnabled`; обычный успешный
`ApplyVisualizationProfile` и раньше перезаписывал его. Отдельное пользовательское
падение из-за этого private флага не заявлено.

Protected Excel PID 23476 не используется. COM-прогоны создают собственный
экземпляр Excel и закрывают только его; инфраструктурный сбой не классифицируется
как `NumFail` расчетного ядра.
