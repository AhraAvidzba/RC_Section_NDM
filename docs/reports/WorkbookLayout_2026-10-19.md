# Сохранённое расположение книги и оформление — 19.10.2026

Задача выполнена. Рабочая книга сохраняет пользовательские данные; полная сборка с нуля воспроизводит утверждённое расположение и создаёт значения по умолчанию. Направленная приёмка пройдена.

## Изменения

На листе «Сечения» каждый из четырёх типов разделён голубой полосой RGB(155,194,230), как в образце: строка 21 pt, заголовок 16 pt, активная ссылка «Подробнее» 9 pt с синей подчёркнутой надписью.

Фактическое расположение взято из последней сохранённой пользователем книги, SHA256 `4E3B99A3615408BFE6ECB3FE659EEF744B88B7ADA15EC001B0CF7EF97794BE5B`. Оно хранится в `tools/build_workbook/WorkbookLayout.json`: 26 именованных диапазонов, дополнительная таблица контрольных точек диаграмм, 84 объекта (3 диаграммы, 5 кнопок, 76 формул-картинок), все ширины/скрытие столбцов и высоты/скрытие строк, порядок листов и области печати.

В частности, сохранены таблицы сочетаний Config!H70:N100, нагрузок устойчивости P70:S100, оформления схемы H103:M117, СП35 X60:AE78 и контрольных точек диаграмм X1:AC54. Служебные динамические списки остаются в BQ:BS. Изменённые пользователем ширины, включая H и N, больше не заменяются прежними значениями при сборке.

`Build-Workbook.ps1` применяет расположение один раз перед сохранением. Формулы, проверки данных, именованные ссылки и ссылки Справки при переносе сборочных таблиц сохраняются через Excel; временный лист удаляется. Для пустой новой книги создаётся пустая диаграмма схемы в сохранённом месте. Расчётные результаты старой книги в новый шаблон не копируются. Для дальнейших сборок исходная пользовательская книга не нужна.

Если пользователь утвердит новое расположение, его сохраняют командой из корня проекта:

```powershell
tools/build_workbook/Capture-WorkbookLayout.ps1 -WorkbookPath workbook/output/RC_Section_NDM.xlsm
```

Сценарий читает книгу без изменения данных и обновляет только описание для сборщика. В распространяемой книге этот файл не требуется.

## Оформление во время расчёта

В рабочий VBA код оформления входных листов не добавлялся. Просмотр всех исходников и шести модулей книги/листов подтвердил: ячейки оформляют только CBatchResultWriter, CStrengthSummaryWriter, CCrackSummaryWriter, CStabilitySummaryWriter и CNDMResultsWriter на Results; цвета статусов предоставляет modStatusFormatting. CSectionPlotter оформляет саму диаграмму на «Расчет», не ячейки листа. Обработчики книги управляют раскрытием Справки и переходами по ссылкам, а не повторным оформлением после расчёта.

На отдельной копии выполнены два штатных расчёта с построением схемы и два последующих обновления схемы. Перед запуском на Config, «Сечениях», «Справке» и «Расчет» специально изменены ширина столбца, высота строки, цвет шрифта и заливка. После каждого этапа сравнивались все сохранённые форматы ячеек, размеры строк/столбцов, объединения и условное форматирование вне Results: 48 712 проверок на этап, без изменений. Первый расчёт занял 3.87 с, второй — 1.18 с; это два направленных случая, не оценка всех сочетаний.

## Приёмка и сохранность

- Рабочая книга: 1716 проверок расположения; новая независимая сборка: 1720, отказов нет.
- 298 полей по умолчанию, 54 формулы единиц для mm/cm/m, 175 вариантов выпадающих списков — PASS.
- Значения и формулы всех 60 095 ячеек рабочей книги сохранены; кэши формул тоже не изменились. Изменение оформления ограничено четырьмя полосами заголовков.
- Имена, проверки данных, гиперссылки и рисунки пользовательской книги сохранены. В новой сборке нет ошибочных формул Excel, #REF! или ссылок на временный лист.
- Старое ожидание Config!O3 заменено чтением заголовка относительно rngLoadCombinations. Пять проверок этой таблицы прошли; точные адреса отдельно проверяются по сохранённому расположению.
- VBA рабочей книги и новой сборки совпадает со всеми 155 исходными компонентами (161 с модулями книги/листов). Рабочий расчётный VBA не изменён; обновлён только тестовый модуль. ALL CODE повторно экспортирован из точной копии опубликованной книги.
- Пользовательская книга заменена атомарно только после проверки SHA256 последнего сохранённого файла. Пользовательский execution_report сохранён побитно и не входит в коммит. Чужие outputs также не включены.

В первой сборке проверка обнаружила четыре расхождения: ширину X, скрытие столбца EF и две области печати. Они устранены в сборщике, окончательная новая сборка прошла все 1720 проверок. При сравнении оформления учитывается реальное содержание стиля столбца: Excel может перенумеровать одинаковые стили. Первоначальная проверка ошибочно считала такую смену номера переоформлением; сравнение исправлено, сами ширины и стили совпали. Исходные неуспешные результаты сохранены в архиве.

Полные ON/OFF, часовой расчётный план и AutoCAD не запускались: изменение относится к сборке и оформлению, математика не менялась. Общий PASS полным прогонам не присваивается.
