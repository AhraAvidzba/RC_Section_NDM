# Генерация бетонной сетки по контурам AutoCAD

Дата: 09.10.2026.

## Реализованный контракт

- При `Geometry.Source = AutoCAD` готовые бетонные Region импортируются как прежде.
- Только при полностью пустом слое бетона сетка создается по достоверному наружному контуру и всем отверстиям. Арматура импортируется из Region.
- Объекты неподдерживаемого типа и Region, отсеянные `MinArea`, не считаются пустым слоем. Ошибка существующей геометрии не скрывается генерацией.
- Без бетонных элементов и наружного контура импорт отклоняется. Одних отверстий недостаточно.
- Используются общие `Mesh.StepX`, `Mesh.StepY`, `Mesh.BoundarySubdivisions` и обычный генератор прямоугольных волокон. Настройки длины переводятся из INPUT в мм; координаты AutoCAD всегда трактуются как мм.
- Наружные границы и несколько отверстий сохраняются в общей модели и Results. После импорта и экспорта выводится отдельное сообщение о генерации сетки по контурам AutoCAD; происхождение сохраняется после закрытия книги.

## Разделение ответственности

`CGeometryRegion` реализует `ISectionGeometry` по неизменяемому точному контуру. В нем нет Excel, COM AutoCAD, материалов или решателей. Пересечения линий и дуг переиспользуют `CSectionGeometryQuery`.

Общий Excel-адаптер `modMeshConfiguration` читает настройки для обоих источников. `CFiberMeshBuilder` создает волокна; `CSectionModelBuilder` переносит их в ту же `CSectionModel`, не меняя импортированную арматуру. Узкий наружный вырез внутри ячейки вызывает ее подразделение даже при четырех углах в бетоне.

Решатели, диаграммы материалов, поиск несущей способности, формулы трещин и устойчивости не изменялись. Метка `Geometry.ConcreteMeshSource` является диагностической, а не переключателем расчетного ядра.

Контрольные формы: круг, прямоугольник, Г-сечение, два смещенных прямоугольника, скругленный прямоугольник и пустотелый скругленный прямоугольник. Проверены подразделения границы 1/2/3, разные шаги по осям, узкий наружный вырез, две круглые пустоты, раздельные бетонные части, единицы мм/см/м и ошибочные входы.

Для прямолинейных форм и круга выполнены поэлементные сравнения Generated и CAD: координаты, площади, размеры, местные инерции и расчетные ID. Дополнительно сравнен прежний генератор из HEAD: все 18 контрольных сеток Generated сохранились поэлементно без изменений.

Выполнены 72 пары решений НДС: шесть форм, четыре сочетания и три состояния материалов. Для Г-сечения дополнительно сопоставлены полный пакет, несущая способность, трещинообразование и ширина по СП 35. Результаты двух моделей совпали:

- Чистое сжатие: общий статус OK, нормальная трещина не образуется; предельный множитель 2,30501310318628.
- N + Mx + My: предельный множитель 0,927993720564389; ширина 0,230788566277072 мм; площадь взаимодействия для трещин 9960,85963547516 мм2. Общий FAIL обусловлен заданной перегрузкой по прочности и продольным трещинам, а не ошибкой импорта или формулы ширины.

Для скруглений Generated использует прежнюю аппроксимацию, а CAD-контур сохраняет точные дуги. Сравнения выполнены с заранее заданным относительным допуском 1%. На проверенных сетках максимальное отличие площади составило около 0,093%, инерций - около 0,081%. Количество волокон у этих двух представлений может различаться. Это не доказательство достаточной точности произвольного пользовательского шага сетки.

Native-проверки выполнены в собственном AutoCAD 2023, в отдельном чертеже: Region и Polyline для всех шести форм, один Region с двумя вырезанными отверстиями, полный экспорт бетонных элементов/арматуры/напряжений, OUTPUT в метрах при экспорте в мм и повторный импорт. Пользовательский чертеж не использовался и не изменялся.
