# Исправление списка типов сечения — 28.10.2026

## Причина и исправление

В `modSectionRecipeSetup.UpdateSectionRecipeTypes` для VBA `Validation.Add` передавался локальный `xlListSeparator` — точка с запятой. Excel сохранял всю последовательность как один допустимый пункт. В VBA теперь передаётся инвариантная запятая. Сборщик импортирует этот же исходный модуль и вызывает тот же метод, поэтому при полной пересборке исправление сохраняется. Рабочий внешний PowerShell/COM-путь проверен отдельно и сохранён с его локальным разделителем: механическая замена разделителя между двумя API некорректна.

Прежний тест нормализовал «;» в «,» и сравнивал строку с таким же неправильно подготовленным эталоном. Эта проверка удалена. Теперь Excel сам проверяет каждый тип через `Validation.Value`, отклоняет склеенную строку и неизвестный тип. Формат строки, возвращаемой `Formula1`, может локализоваться и сам по себе не доказывает правильность раскрытия.

В `AGENTS.md` закреплено правило проверки отдельных пунктов после сохранения и повторного открытия книги, сохранения текущих значений и различения VBA/внешнего COM. Наличие стрелки или совпадение строк не считается достаточным подтверждением.

## Проверки и сохранность

- Новый тест на прежнем рабочем коде дал ожидаемые 13/5: четыре отдельных типа отвергались, склеенная строка принималась. После исправления — 18/0; ожидания отдельных допустимых значений не ослаблены.
- На точных пакетах: No 48/0 и Yes 48/0, включая общий выбор сочетания и прямые списки. Первичные журналы прочитаны целиком, собственные Excel этих проверок завершились штатно.
- Дополнительные 24 нативные проверки: четыре отдельных типа принимаются, склеенная строка и неизвестный тип отклоняются при десятичной точке и запятой. Проверены сохранённая и повторно открытая книга и используемый PowerShell-сборкой способ создания списка. Настройки Windows не менялись.
- Нативно сверены 175 исходных и 6 документных компонентов обеих книг, все 181 тела Main/Ready буквально совпали. 179 прежних компонентов совпали без нормализации чисел, строк и комментариев, кроме регистра исполняемого кода. Изменены только один рабочий модуль и его тест.
- В каждой книге изменены только `vbaProject.bin` и разделители строки проверки данных B26. Все значения, формулы, данные, стили, имена и готовые Results сохранены. Остальные 106 частей основной и 110 частей тестовой книги побайтно неизменны. Скрытые списки не возвращались.

## Ограничения и диагностика служебных процессов

Снимок раскрытого списка через computer-use не получен: собственное окно сначала было минимизировано, захват после активации завершился `FrameArrived timed out`, затем экземпляр перестал быть доступен; при закрытии получен `RPC_E_DISCONNECTED`. Его точный PID отсутствует. Причина этого отдельного обрыва не установлена, визуальный PASS не заявлен. Фактическое поведение списка проверено нативным валидатором Excel и сохранённым представлением четырёх отдельных пунктов.

Windows отдельно зафиксировал `combase.dll / 0xc0000005` у четырёх собственных экземпляров ранней подготовки при завершении. В частном подготовщике ссылки VBE освобождены до закрытия книги и убран `FinalReleaseComObject` приложения с ещё существующими ссылками проекта. Повторная подготовка прошла 18/0, действительную компиляцию VBE 578 и завершение без события Application Error по её PID. Связь прежних сбоев с порядком освобождения COM является выводом по наблюдениям; точная внутренняя причина COM не доказана. Неуспешные подготовительные попытки сохранены, не представлены как PASS.

Текущие адресные проверки сохранённых книг и их readonly-экспорты таких сбоев не дали. Пользовательские Excel/AutoCAD не закрывались, kill не применялся. На наблюдении оставалось около 14,5 ГиБ RAM и 19,6 ГиБ commit. Математика и расчётные алгоритмы не менялись; новый полный набор не запускался, `ndm` не менялся.
