# Нагрузки в верхней сводке Results — 24.10.2026

Добавлен утверждённый блок из шести столбцов: исходные N/Mx/My в точке
приложения и рабочие N/Mx/My после фильтров и продольного изгиба, если он
применим. Блок расположен после минимальных коэффициентов, через один
пустой столбец; расшифровка статусов перенесена вправо. Нового имени диапазона
нет: блок относится к существующей сводке `rngBatchSummary`, её технический
якорь и возможность переноса сохранены. Высоты строк и расчётные таблицы
слева не менялись. Ширина шести столбцов задаётся только при сборке.

Общая шапка занимает две строки, два подзаголовка — следующие две;
«(если применимо)» начинается с новой строки. Далее идут обозначения с
единицами и комментарии. η упомянута только для моментов. Первая строка
данных выделена как строка Worst: все шесть чисел принадлежат тому же
сочетанию, которое выбрано настройкой пользователя и указано вверху сводки.
Оформление проверено на нативном изображении готового расчёта.

## Источник данных

Исходные нагрузки берутся из неизменённого `CBatchSectionCalculator.mInputs`,
рабочие — из уже рассчитанного `mWorkingLoads`. Прежние `UserMx/UserMy`
содержат рабочие моменты, поэтому использовать их для исходного блока нельзя.
Новые свойства дают доступ к оригинальным значениям без нового чтения
Config, фильтрации или округления. Преобразования выполняет `CUnitSystem`.
Ошибка устойчивости не выдаётся за успешно уточнённые нагрузки.

В обоих режимах сразу после расчёта вывод использует готовые данные в памяти.
Повторного чтения только что записанного файла нет. Новая файловая сводка
содержит 33 столбца вместо 26, включая обе тройки нагрузок. При загрузке
выбранного файла используются только его данные и сохранённые единицы;
текущие нагрузки Config не подмешиваются. Другие листы не изменяются.

Старые файлы NDMSNP04 с 26 столбцами читаются. Новые нагрузки в них отсутствуют:
ячейки остаются пустыми, комментарий прямо сообщает об отсутствии данных.
Исходный файл и текущий Config сохраняются. Время берётся из окончательного
поля контейнера снимка, а не из промежуточной копии времени в его матрице.
В режиме Excel блок хранится обычными значениями Results; прежняя семантика
обновления схемы из текущего Results сохранена.

## Проверки

- `RunResultsFormattingTests`: 64/0 в каждом режиме, включая минимальное
  оформление, восстановление шапок, смену единиц и очистку прежних строк.
- Дополнительные реальные сценарии: четыре расчёта в каждом режиме,
  170 нативных проверок на режим. Excel/File, Reformat Yes/No, четыре
  критерия Worst, tf/tf*m и kN/kN*m, отрицательный исходный момент,
  обнуление рабочих моментов фильтром и действительное усиление от устойчивости.
- Восемь переключений двух разных файлов при намеренно посторонних нагрузках,
  иных единицах и недопустимом параметре solver на Config. Два переключения
  выполнены штатной кнопкой после повторного открытия. Вызовов solver — 0.
  Все данные Results и реальные фигуры восстановлены из нужного файла;
  значения, формулы, стили, размеры и проверки ввода прочих листов неизменны.
- Два восстановления настоящего прежнего 26-столбцового файла. Отсутствующий
  блок не заполняется нынешними нагрузками, прежние данные сохранены.
- Независимое сравнение с исходной книгой: 175993 прежних значения совпали,
  включая все матрицы двух файлов. Исключены только новый блок, перенесённый
  словарь статусов, RunID и измеренное время разных запусков. Для физических
  результатов допуск не вводился; в двоичном сравнении допускается только знак
  точного нуля.
- Проверка раскладки: 1209 требований, 0 ошибок. Нативные списки, рамки,
  ссылки, справка, исходные настройки и пустой Results новой основной книги
  проверены. Фактический VBA: 172 исходных + 6 документных компонентов,
  полная компиляция без импорта, `Verify-CalculationSnapshotRelease --fresh` PASS.
  Документация VBA: 177 модулей/5979 методов, нарушений шапок и тестовых имён нет.

При File/Reformat No после расчёта может остаться прежняя шапка подавленной
пустой таблицы элементов; загрузка файла очищает её. Независимый проверяющий
разрешает только удаление десяти точно известных текстов этой пустой шапки,
не исключая никакие расчётные строки. Эта прежняя политика вывода не менялась.

При пересборке все пользовательские числа и формулы Config/«Сечения»/«Расчет»
совпали с исходной книгой. Пять статических пояснений Config синхронизированы
с действующим каталогом. Координаты справки обновлены в WorkbookLayout после
добавленного объяснения нового блока; раскладка входных листов сохранена.

## Промежуточные проверки

Первоначальное расширение самого имени-якоря до прямоугольника оказалось
несовместимым со скалярными потребителями в старых тестах. Сохранён штатный
якорь A1; рабочий writer расширяет область вывода до 33 столбцов. Оба набора
оформления после исправления прошли целиком. Новые нативные тесты также
исправлены для COM-setter/синтаксиса PowerShell 5 и явного Auto-пути в примере
с обнулением моментов. Исходные журналы не переписаны. Ошибки этих промежуточных
проверок не объявлялись успешными, ожидания расчёта не ослаблялись.

Полный долгий ON/OFF не запускался; общий полный PASS не присваивается.
Наблюдение ndm остаётся PAUSED. Существующие исторические полные FAIL сохраняются.
