# Полный снимок расчёта и ускорение вывода

Направленная проверка новой функциональности пройдена. Полный запуск
завершил 162/162 набора и целевой план, сохранив 10 FAIL из трёх причин.
Причины исправлены после его окончания; чистая пересборка повторно дала
по 3622/0 в No/Yes. Полный PASS новой SHA не присваивается на основании
адресных проверок. Разбор: `CompleteSnapshot_FullFollowup_2026-10-24.md`.

## Изменение поведения

После расчёта формируется один полный снимок: сначала он сохраняется,
затем общий механизм восстанавливает таблицы Results и схему. Тот же
механизм вызывается кнопкой «Обновить схему и результаты». Загрузка
сохранённого снимка не вызывает решатель или импорт AutoCAD.

В общих настройках Config добавлены только два поля:

| Настройка | Значение по умолчанию | Назначение |
|---|---|---|
| Results.SnapshotStorage | Excel | Excel либо File; выбор хранения и загрузки |
| Results.SnapshotName | NDM_Snapshot.ndms | Имя одного файла рядом с книгой |

Следующий расчёт полностью заменяет выбранный файл через собственный
временный файл и атомарную замену. Unicode-имена поддерживаются.
Контрольная сумма SHA256 проверяется до восстановления таблиц;
повреждённый, отсутствующий или подменённый файл не уничтожает прежние
Results. Загрузка другого сохранённого расчёта применяется кнопкой;
одно изменение имени в Config не подменяет уже показанную схему.

Оба хранилища содержат одинаковые логические данные: сетку, контуры,
общие геометрические характеристики, использованные диаграммы,
аннотации, все сохранённые состояния элементов, LC-зависимые свойства,
четыре верхние сводки с их шапками, использованные профили и время.
Профиль визуализации доступен из снимка даже при отсутствии его ID
в текущем Config. Числа файла сохраняются как исходные Double.

На Results добавлен ровно один именованный диапазон
`rngNDMLoadCaseResults`: в нём компактно хранится недостающее LC-дополнение.
Прежние технические таблицы в него не дублируются. Параметры точки
приложения и гибкости СП35 перенесены из общих свойств в LC-часть.
Технические порции дополнения не показываются как длинный текст.

Нижние блоки идут по горизонтали: сетка → общие характеристики →
использованные диаграммы → состояния → LC-дополнение → контуры →
аннотации. Верхние таблицы сохраняют прежнее положение и оформление.
Сетка, характеристики и диаграммы остаются на листе при хранении File
и восстанавливаются при переключении между файлами.

При предварительной оценке больше 60000 строк состояний кнопка расчёта
предлагает File, объясняет преимущество и оставляет пользователю выбор.
Ответы Да и Нет продолжают расчёт. Физическая вместимость листа Excel
по-прежнему проверяется до записи.

## Подтверждённые ускорения

`CDiscreteForceIntegrator` использует точное суммирование исходных
дискретных волокон по линейным участкам диаграмм для повторных проб R.
На сетках до 5000 элементов дерево не строится. Подготовка на больших
сетках включается только после накопления проб; K, критические элементы
и итоговые результаты остаются на прежнем пути. Подробности и границы
выигрыша: `ExactDiscreteIntegration_2026-10-23.md`.

В подготовке подробной таблицы постоянные поля состояния вынесены
из элементного цикла. Большие блоки оформляются общим стилем с прежними
атрибутами. Excel получает матрицы блочными присваиваниями; поэлементных
обращений к книге в горячем пути нет.

Проверка файлового пути выявила лишние копии больших Variant-массивов,
повторную проверку неизменённого снимка, повторные полные поиски данных
для схемы и создание сотен COM-словарей для малых шапок и сводок.
Устранены лишние копии; индекс групп состояний живёт только внутри
неизменяемого снимка одной операции. После изменения RunID или добавления
части проверка выполняется заново. Малые таблицы сохраняются напрямую,
повторяющиеся поля больших таблиц — сериями, плотные числовые колонки —
массивами. Двоичный поток объединяет короткие записи в буфер 64 КиБ.

Новый формат файла — NDMSNP04. Он не требует установки библиотек или
дополнительного ПО. Проверены исходные биты чисел, включая +0/-0,
Unicode, Empty/пустую строку, Boolean и плотные/повторяющиеся колонки.
Временные исследовательские книги предыдущих внутренних форматов
не являются опубликованным контрактом.
