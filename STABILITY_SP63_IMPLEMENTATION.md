# Проверка устойчивости сжатых элементов по СП 63 для NDM

Статус документа: архитектурное и нормативное предложение, без реализации в коде.

Основные локальные источники:

- `norms/SP_63/СП 63.13330.2018 Бетонные и железобетонные конструкции. Основные положения...`;
- `norms/SP_35/СП 35.13330.2011 Мосты и трубы...` для уже добавленной проверки продольных трещин по `Concrete.Rb.mc2`.

Цель будущей реализации - добавить учет влияния прогиба/устойчивости сжатых железобетонных элементов перед проверкой прочности, сохранив текущий расчетный конвейер:

```text
Config + LC -> CSectionModel + материалы -> расчет в памяти -> Results snapshot
```

Лист Excel не должен становиться промежуточным расчетным хранилищем. После чтения `Config`, сочетаний и построения `CSectionModel` все величины устойчивости, скорректированные усилия и результаты последующих проверок должны передаваться между объектами в памяти.

## 0. Отдельная текущая правка Rb,mc2

Для бетона B30 значение по умолчанию `Concrete.Rb.mc2` должно быть `14.6 МПа`.

Важно: это значение является только дефолтом в собранной таблице `Config`. В расчетном коде характеристики материалов не должны иметь скрытых fallback-значений. Если пользователь очистил обязательную характеристику материала или диапазон `Config` не содержит нужный ключ, расчет должен завершаться ошибкой исходных данных.

`Concrete.Rb.mc2` вводится пользователем уже как итоговое допустимое значение для проверки продольных трещин с учетом `m_b13` и других применимых коэффициентов условий работы по СП 35. Программа не должна сама домножать это значение на коэффициенты.

## 1. Что сейчас делает NDM

Фактический рабочий поток проекта на момент аудита:

```text
modWorkbookCalculation.RunSectionCalculationForWorkbook
    -> CSystemSettingsReader.LoadFromWorkbook
    -> CUnitSystem.LoadFromSettings
    -> CSectionTypeRegistry / AutoCAD importer -> CSectionModel
    -> CMaterialModelProvider.InitializeFromSettings
    -> CLoadCombinationReader.ReadIntoBatch
    -> CBatchSectionCalculator.ApplyLoadReference
    -> CBatchSectionCalculator.Execute
        -> CStateSolutionRunner.Solve
            -> CStateGuessBuilder
            -> CSectionSolver
        -> CCapacityLoadPath
        -> CCapacitySolver
            -> CSectionSolver
        -> CCrackWidthCalculator
            -> CSectionSolver для внутренних расчетов трещин
        -> CCombinationResult
    -> CBatchResultWriter.WriteSummary
    -> CNDMResultsWriter.WriteResults
    -> CSectionPlotter
```

Сейчас `CBatchSectionCalculator` уже не читает Excel напрямую. Он получает готовые `CSectionModel`, `CMaterialModelProvider` и нормализованные сочетания. Это хорошая точка для вставки расчета устойчивости: устойчивость должна стать еще одним этапом внутри batch pipeline перед проверками прочности.

Текущая точка приложения нагрузки:

- пользовательские `N`, `Mx`, `My` задаются относительно центра тяжести бетонного сечения плюс `Load.ReferenceOffsetX/Y`;
- центр тяжести бетонного сечения считается по бетонной сетке;
- перед solver-ом моменты переносятся к внутренней системе координат элементов:

```text
Mx_internal = Mx_user + N * Yref
My_internal = My_user + N * Xref
```

Для устойчивости это важно: СП 63 в части эксцентриситетов говорит о центрах тяжести сечения. Поэтому в будущем расчете нужно явно фиксировать, относительно какого центра считаются `e0`, `ea`, `M1`, `Ml1` и как это согласуется с текущей пользовательской привязкой к бетонному центру.

## 2. Нормативная методика СП 63

### 2.1 Когда требуется учет прогиба/устойчивости

СП 63, п. 5.2.9: при расчете внецентренно сжатых железобетонных элементов следует учитывать случайный эксцентриситет и влияние продольного изгиба.

СП 63, п. 8.1.2: при расчете внецентренно сжатых элементов следует учитывать влияние прогиба на их несущую способность. Расчет допускается выполнять по деформированной схеме. При расчете по недеформированной схеме допускается учитывать влияние прогиба умножением начального эксцентриситета `e0` на коэффициент `eta`, определяемый по п. 8.1.15.

Для текущего NDM наиболее естественный первый этап реализации - метод недеформированной схемы с коэффициентом `eta`, потому что он сводится к корректировке расчетных моментов перед существующей проверкой прочности.

Предлагаемая область применения первой реализации:

- только сжатые или внецентренно сжатые сочетания первой группы;
- если внутренняя продольная сила соответствует растяжению, проверка устойчивости неприменима;
- для Group2/трещин метод п. 8.1.2 напрямую не применять, потому что он находится в разделе прочности нормальных сечений. Для SLS нужна отдельная согласованная постановка, если ее потребуется вводить.

### 2.2 Случайный эксцентриситет

СП 63, п. 8.1.7: в начальном эксцентриситете внецентренно сжатого железобетонного элемента следует учитывать случайный эксцентриситет `ea`.

СП 63, п. 8.1.7 задает минимальные значения `ea` без отдельного номера формулы:

```text
ea >= l / 600
ea >= h / 30
ea >= 10 мм
```

где:

- `l` - длина элемента или расстояние между его сечениями, закрепленными от смещения;
- `h` - размер сечения в рассматриваемой плоскости;
- `10 мм` - абсолютный минимум.

Для статически неопределимых конструкций по п. 8.1.7 эксцентриситет продольной силы относительно центра тяжести приведенного сечения принимается равным эксцентриситету из статического расчета, но не менее `ea`.

Для статически определимых конструкций по п. 8.1.7 начальный эксцентриситет принимается как сумма эксцентриситета из статического расчета и случайного эксцентриситета.

В будущей реализации нужно явно задать тип расчетной схемы:

- `Indeterminate` - не меньше `ea`;
- `Determinate` - добавить `ea` к расчетному эксцентриситету.

### 2.3 Расчетная длина

СП 63, п. 8.1.17: расчетную длину `l0` элементов железобетонных конструкций допускается определять в зависимости от расчетной схемы. В тексте пункта приведены коэффициенты к длине `l` для типовых закреплений:

| Схема элемента | Расчетная длина |
|---|---:|
| шарнирно опертый на двух концах | `l0 = 1.0 l` |
| один конец защемлен, другой свободен | `l0 = 2.0 l` |
| один конец защемлен, другой шарнирно оперт | `l0 = 0.7 l` |
| один конец защемлен, другой имеет податливую опору | `l0 = 0.9 l` |
| один конец имеет несмещаемую податливую опору, другой свободен | `l0 = 1.5 l` |
| два конца имеют податливые опоры | `l0 = 2.0 l` |
| два защемленных несмещаемых конца | `l0 = 0.5 l` |
| две несмещаемые податливые опоры | `l0 = 0.8 l` |
| два защемленных конца с ограниченно допускаемым смещением | `l0 = 0.8 l` |
| две податливые опоры с ограниченно допускаемым смещением | `l0 = 1.2 l` |

Для произвольной расчетной модели лучше не пытаться автоматически угадывать закрепления. В `Config` нужно дать пользователю либо прямой ввод `l0` по каждой главной плоскости, либо длину `l` и коэффициенты `k0,1`, `k0,2`.

Рекомендация: использовать пользовательские коэффициенты расчетной длины по двум главным плоскостям:

```text
l0,1 = k0,1 * l
l0,2 = k0,2 * l
```

Эта формула является программной записью выбора расчетной длины по п. 8.1.17; отдельного номера формулы в СП для нее нет.

### 2.4 Коэффициент eta и критическая сила Ncr

СП 63, п. 8.1.15, формула (8.14):

```text
eta = 1 / (1 - N / Ncr)
```

СП 63, п. 8.1.15, формула (8.15):

```text
Ncr = pi^2 * D / l0^2
```

где:

- `N` - продольная сила в рассматриваемом сжатом элементе;
- `Ncr` - условная критическая сила;
- `D` - условная жесткость железобетонного элемента;
- `l0` - расчетная длина элемента.

Граничные случаи:

- если `N <= 0` во внутренней системе знаков проекта означает растяжение, устойчивость неприменима;
- если `N >= Ncr`, формула (8.14) становится сингулярной, элемент должен получать статус непрохождения проверки устойчивости;
- если `Ncr <= 0`, это ошибка исходных данных или геометрии;
- если `l0 <= 0`, это ошибка исходных данных.

### 2.5 Условная жесткость D

СП 63, п. 8.1.15 допускает определять `D` по формуле без отдельного номера:

```text
D = kb * Eb * I + ks * Es * Is
```

где:

- `Eb` - начальный модуль упругости бетона;
- `Es` - модуль упругости арматуры;
- `I` - момент инерции площади бетонного сечения относительно центра тяжести в рассматриваемой плоскости;
- `Is` - момент инерции площади всей продольной арматуры относительно центра тяжести сечения в той же плоскости;
- `kb` - коэффициент, учитывающий влияние длительного действия нагрузки, эксцентриситета и характера работы бетона;
- `ks = 0.7` по п. 8.1.15.

СП 63, п. 8.1.15, формула для `kb` дана без отдельного номера:

```text
kb = 0.15 / (phi_l * (0.3 + delta_e))
```

СП 63, п. 8.1.15, формула для `phi_l` дана без отдельного номера:

```text
phi_l = 1 + Ml1 / M1
phi_l <= 2
```

где:

- `M1` - момент относительно центра наиболее растянутого или наименее сжатого стержня арматуры от полной нагрузки;
- `Ml1` - то же, но от постоянных и длительных нагрузок;
- если все сечение сжато, берется стержень у наименее сжатой стороны;
- если арматуры нет, применение этой формулы к текущей модели неочевидно и требует отдельного решения.

СП 63, п. 8.1.15, формула для `delta_e` дана без отдельного номера:

```text
delta_e = e0 / h
```

Ограничения по п. 8.1.15:

```text
0.15 <= delta_e <= 1.5
```

где:

- `e0` - начальный эксцентриситет продольной силы в рассматриваемой плоскости с учетом п. 8.1.7;
- `h` - размер сечения в плоскости изгиба.

### 2.6 Длительные нагрузки

Длительное действие входит в расчет через `phi_l = 1 + Ml1/M1`, но не более 2, по п. 8.1.15.

NDM сейчас хранит в сочетании только итоговые `N`, `Mx`, `My`. Этого недостаточно, чтобы нормативно вычислить `Ml1`, потому что нужно отделить часть усилий от постоянных и длительных нагрузок.

Рекомендуемое решение:

- добавить в таблицу сочетаний отдельные колонки для длительной части: `N_long`, `Mx_long`, `My_long`;
- читать их тем же `CLoadCombinationReader` через `CUnitSystem`;
- если устойчивость включена, а длительная часть не задана, выдавать `InputErr`, либо разрешать явный режим `LongTermMode = Ignore` как инженерное допущение, но не выдавать его за СП.

Автоматически определить длительную часть из текущих данных нельзя.

### 2.7 Две плоскости и произвольное несимметричное сечение

Для произвольного сечения оси `X/Y` могут не совпадать с главными центральными осями. Текущий проект уже считает:

- бетонные свойства;
- приведенные свойства бетон + арматура;
- главные моменты инерции;
- угол главных осей.

Для устойчивости нужно считать две независимые плоскости относительно главных центральных осей выбранного представления сечения:

```text
M1, M2 = TransformMomentsToPrincipalAxes(Mx, My, alpha)
eta1 = f(N, Ncr1, D1, l0,1, e0,1, h1)
eta2 = f(N, Ncr2, D2, l0,2, e0,2, h2)
```

Затем моменты возвращаются в исходную систему:

```text
M1,design = eta1 * M1,with_ea
M2,design = eta2 * M2,with_ea
Mx_design, My_design = TransformMomentsFromPrincipalAxes(M1,design, M2,design, alpha)
```

Знаки и матрица поворота должны быть реализованы через один helper с обязательными round-trip тестами:

```text
Global -> Principal -> Global
```

Важная неоднозначность: СП 63 п. 8.1.7 для статически неопределимых конструкций говорит об эксцентриситете относительно центра тяжести приведенного сечения, а текущий пользовательский ввод NDM привязан к центру тяжести бетонного сечения. Поэтому в реализации нужно:

1. хранить исходную пользовательскую базу как бетонный центр;
2. для устойчивости пересчитать моменты к принятому нормативному центру;
3. сохранить в `CStabilityResult`, какой центр был использован;
4. отразить это в `Results` и справке.

Рекомендация для первой реализации:

- для пользовательского ввода ничего не менять: `Load.ReferenceOffset = 0` остается бетонным центром;
- внутри устойчивости использовать приведенное сечение для эксцентриситетов, `I`, `Is` и главных осей, потому что п. 8.1.7 прямо упоминает приведенное сечение для статически неопределимых элементов;
- отдельно вывести в документе/справке, что это не меняет базу пользовательского ввода нагрузок.

### 2.8 Упрощенный расчет по п. 8.1.16

СП 63, п. 8.1.16 для прямоугольных внецентренно сжатых элементов при `e0 <= h/30` и `l0/h <= 20` допускает расчет по условию:

Формула (8.16):

```text
N <= Nult
```

Формула (8.17):

```text
Nult = phi * (Rb * A + Rsc * As,tot)
```

Эту ветку не рекомендуется включать в первую реализацию, потому что проект поддерживает произвольную дискретную геометрию, не только прямоугольники. Основной универсальный путь должен оставаться через `eta` и существующий НДМ-расчет прочности.

## 3. Предлагаемая архитектура реализации

### 3.1 Новые сущности

Минимально оправданные новые классы:

1. `CStabilitySettings`

   Хранит настройки устойчивости, уже прочитанные из `Config` и переведенные в внутренние единицы. Не считает геометрию и не обращается к Excel.

2. `CStabilityCalculator`

   Выполняет расчет устойчивости для одного сочетания в памяти:

   ```text
   section + materialProvider + исходные усилия + длительные усилия + settings
       -> CStabilityResult
   ```

3. `CStabilityResult`

   Хранит результат для одного LC: статус, исходные усилия, скорректированные усилия, `ea`, `e0`, `eta`, `Ncr`, `D`, `phi_l`, выбранные оси, предупреждения и признак применимости.

Можно обойтись без `CStabilitySettings`, если хранить настройки прямо в `CBatchSectionCalculator`, но это снова перегрузит batch. Поэтому отдельный маленький settings-класс оправдан.

Не рекомендуется добавлять отдельные solver-ы устойчивости: по п. 8.1.15 это не итерационный НДМ-solver, а расчет коэффициентов и корректировка эксцентриситета.

### 3.2 Изменения существующих классов

#### `CSystemSettingsReader`

Добавить чтение нового диапазона или строк в `rngSystemSettings`:

- `Stability.Enabled`;
- `Stability.SystemType`;
- `Stability.ElementLength`;
- `Stability.EffectiveLengthFactor1`;
- `Stability.EffectiveLengthFactor2`;
- `Stability.LongTermMode`;
- возможно `Stability.BiaxialMode`.

#### `CLoadCombinationReader`

Добавить чтение длительной части нагрузок, если принято решение считать `phi_l` строго по СП:

- `N_long`;
- `Mx_long`;
- `My_long`.

Эти колонки должны храниться в `CLoadCase`/batch input в внутренних единицах. Нельзя рассчитывать `Ml1` по данным, уже выведенным на `Results`.

#### `CSectionPropertiesCalculator`

Расширить или добавить метод, возвращающий свойства, нужные именно для устойчивости:

- площадь и центр тяжести бетонного сечения;
- площадь и центр тяжести приведенного сечения;
- главные оси;
- `I` бетонной части по главным осям;
- `Is` продольной арматуры по тем же осям;
- размеры `h1`, `h2` по главным плоскостям.

Текущий `CalculateConcrete` накапливает инерцию по центрам бетонных элементов. Для устойчивости лучше включить локальные инерции бетонных конечных элементов, если они доступны в `CSectionModel` через `ConcreteLocalIx/Iy/Ixy`. Иначе для грубой сетки `I` может быть занижен. Это надо проверить перед реализацией.

#### `CBatchSectionCalculator`

Оставить orchestration:

```text
для каждого LC:
    validate input
    build original internal load vector
    if Stability applies:
        stability = CStabilityCalculator.Calculate(...)
        activeLoad = stability.DesignLoad
    else:
        activeLoad = originalLoad
    run DirectState/Capacity/Crack as сейчас, но на activeLoad там, где нормативно применимо
    aggregate statuses
    store CCombinationResult
```

В batch не должны появляться формулы `eta`, `D`, `Ncr`, `kb`; он только вызывает calculator и сохраняет результат.

#### `CCombinationResult`

Добавить поля:

- `StabilityStatus`;
- `StabilityApplied`;
- `StabilityDesignN`;
- `StabilityDesignMx`;
- `StabilityDesignMy`;
- `StabilityEta1`, `StabilityEta2`;
- `StabilityNcr1`, `StabilityNcr2`;
- `StabilityD1`, `StabilityD2`;
- `StabilityEa1`, `StabilityEa2`;
- `StabilityE01`, `StabilityE02`;
- `StabilityPhiL1`, `StabilityPhiL2`;
- `StabilityStopReason`.

Часть полей можно не выводить в Summary, но они полезны для отчета и `Results` snapshot.

#### `CBatchStatusPolicy`

Добавить формирование пользовательского `StabilityStatus` теми же внешними статусами:

- `OK` - устойчивость проверена или не требует усиления, скорректированные усилия корректны;
- `FAIL` - `N >= Ncr`, превышена применимость или усиление приводит к непрохождению последующей проверки;
- `NumFail` - для устойчивости почти не нужен, только если не удалось вычислить геометрию/оси из-за численной проблемы;
- `InputErr` - отсутствует `l`, `l0`, длительная часть при обязательном режиме или другая настройка;
- `N/A` - LC не сжатый или проверка устойчивости отключена.

#### `CBatchResultWriter` и `CNDMResultsWriter`

Добавить блок `Устойчивость сжатого элемента`:

- `StabilityStatus`;
- `eta1`, `eta2`;
- `Ncr1`, `Ncr2`;
- `ea1`, `ea2`;
- `e0,1`, `e0,2`;
- `phi_l,1`, `phi_l,2`;
- исходные и скорректированные `N`, `Mx`, `My`.

В `Results` snapshot сохранить как исходные, так и расчетные усилия после устойчивости, чтобы схема и AutoCAD понимали, какое состояние было проверено.

#### `CStateSolutionRunner`, `CSectionSolver`, `CCapacitySolver`

Эти классы не должны знать формулы устойчивости. Они получают уже выбранный набор усилий.

Особый вопрос для `CCapacitySolver`: если коэффициент запаса по capacity ищется масштабированием `lambda`, а `eta` зависит от `N(lambda)` и `e0(lambda)`, строгое обновление устойчивости внутри каждой lambda-точки превращает линейный путь `Offset + lambda * Base` в нелинейный путь.

Рекомендуемая первая реализация без усложнения solver-а:

- для расчетной проверки конкретного LC сначала получить скорректированные расчетные усилия по устойчивости;
- `DirectState` и проверку прочности выполнять на этих усилиях;
- directional capacity считать по уже скорректированному направлению как оценку запаса сечения относительно расчетного состояния.

Если потребуется строго искать `lambda` с пересчетом `eta(lambda)` на каждой пробной точке, лучше вводить отдельный `CCapacityTargetProvider`/адаптер. В текущую первую реализацию это не включать, потому что это уже отдельная нелинейная задача, а не простая вставка проверки устойчивости.

### 3.3 Где именно стоит этап устойчивости

Предлагаемая последовательность для Group1:

```text
1. Прочитать LC и перевести единицы/знаки.
2. Перенести моменты из пользовательской точки приложения к внутренней системе.
3. Если Stability.Enabled = Yes и N сжимающая:
       рассчитать ea, D, Ncr, eta по главным плоскостям;
       сформировать скорректированные Mx/My;
       сохранить StabilityResult.
   Иначе:
       StabilityStatus = N/A.
4. На скорректированных усилиях выполнить StateSolution.
5. На скорректированных усилиях выполнить Capacity/Strength.
6. Записать оба набора усилий: исходные и после устойчивости.
```

Для Group2:

```text
1. Устойчивость по п. 8.1.2 СП 63 не применяется автоматически.
2. Crack продолжает использовать фактические эксплуатационные усилия Group2.
3. Если позже будет нужна SLS-постановка второго порядка, ее нужно согласовать отдельно.
```

Это решение сохраняет нормативную трассировку: п. 8.1.2 относится к прочности внецентренно сжатых элементов, а не к текущей методике ширины раскрытия нормальных трещин.

## 4. Исходные данные для Config

### 4.1 Данные, которые действительно должен задавать пользователь

Предлагаемый новый блок `Устойчивость сжатых элементов`:

| Ключ | Смысл | Ед. | Обязательно | Default | Ось | Основание |
|---|---|---:|---|---:|---|---|
| `Stability.Enabled` | Включает расчет устойчивости по СП 63 для сжатых Group1 LC | Yes/No | да | No | общая | параметр реализации |
| `Stability.SystemType` | Как учитывать случайный эксцентриситет: статически определимая или неопределимая схема | `Determinate / Indeterminate` | да, если включено | `Indeterminate` | общая | СП 63, п. 8.1.7 |
| `Stability.ElementLength` | Длина элемента `l` для `ea = l/600` и `l0 = k0*l` | длина | да, если включено | нет | общая | СП 63, п. 8.1.7, 8.1.17 |
| `Stability.EffectiveLengthFactor1` | Коэффициент расчетной длины по главной плоскости 1 | `-` | да, если включено | 1.0 | главная ось 1 | СП 63, п. 8.1.17 |
| `Stability.EffectiveLengthFactor2` | Коэффициент расчетной длины по главной плоскости 2 | `-` | да, если включено | 1.0 | главная ось 2 | СП 63, п. 8.1.17 |
| `Stability.LongTermMode` | Источник длительной части для `phi_l` | `FromCombination / Ignore` | да, если включено | `FromCombination` | общая | СП 63, п. 8.1.15 + параметр реализации |
| `Stability.BiaxialMode` | Как назначать знак `ea` при двухосном изгибе | `ByMomentSign / Envelope` | да, если включено | `ByMomentSign` | общая | параметр реализации, потому что СП явно не расписывает произвольное несимметричное N+Mx+My |

Рекомендация по default: `Stability.Enabled = No`, чтобы не менять результаты существующих моделей до осознанного включения пользователем. Все остальные defaults нужны только для удобства заполненной новой книги; при включенной устойчивости критические значения должны быть явно заданы на `Config`.

### 4.2 Данные, которые надо добавить в таблицу сочетаний

Для строгого расчета `phi_l`:

| Колонка LC | Смысл | Ед. | Обязательность |
|---|---|---:|---|
| `N_long` | Продольная сила от постоянных и длительных нагрузок | Force input | если `Stability.LongTermMode = FromCombination` |
| `Mx_long` | Момент Mx от постоянных и длительных нагрузок | Moment input | если `Stability.LongTermMode = FromCombination` |
| `My_long` | Момент My от постоянных и длительных нагрузок | Moment input | если `Stability.LongTermMode = FromCombination` |

Автоматически получить эти величины из текущих `N/Mx/My` нельзя.

### 4.3 Данные, автоматически получаемые из геометрии

В памяти из `CSectionModel`:

- площадь бетонной части;
- центр тяжести бетонной части;
- площадь приведенного сечения;
- центр тяжести приведенного сечения;
- главные центральные оси;
- `I1`, `I2` бетонной части;
- `Is1`, `Is2` продольной арматуры;
- `h1`, `h2` - размеры сечения в главных плоскостях;
- координаты стержней для определения `M1` и `Ml1`.

Эти величины не должны вводиться пользователем и не должны читаться из `Results`.

### 4.4 Данные, получаемые из сочетаний

Из LC берутся:

- полный `N`, `Mx`, `My`;
- длительные `N_long`, `Mx_long`, `My_long`, если добавлены;
- `CalculationType`;
- пользовательский `CapacityLoadPath`, если нужен downstream capacity.

До расчета устойчивости все эти усилия должны быть уже переведены в внутренние единицы и внутреннюю систему знаков.

### 4.5 Внутренние величины только в памяти

Не хранить на `Config`:

- `ea1`, `ea2`;
- `e0,1`, `e0,2`;
- `delta_e,1`, `delta_e,2`;
- `phi_l,1`, `phi_l,2`;
- `kb1`, `kb2`;
- `D1`, `D2`;
- `Ncr1`, `Ncr2`;
- `eta1`, `eta2`;
- скорректированные `Mx_design`, `My_design`;
- промежуточные моменты в главных осях;
- выбранные точки арматуры для `M1/Ml1`.

Их можно выводить в `Results` для проверки, но источник для расчета - только объект `CStabilityResult` в памяти.

## 5. Проверки применимости и граничные случаи

Перед запуском устойчивости:

- если `Stability.Enabled = No` -> `StabilityStatus = N/A`;
- если LC не Group1 -> `StabilityStatus = N/A`;
- если `N` растягивающая или почти нулевая -> `StabilityStatus = N/A`;
- если нет бетонных элементов -> `InputErr`;
- если нет продольной арматуры, формула `M1/Ml1` по наиболее растянутому или наименее сжатому стержню не имеет прямой реализации -> `InputErr` или отдельное согласованное инженерное правило;
- если `ElementLength <= 0` или `k0 <= 0` -> `InputErr`;
- если не задана длительная часть при `LongTermMode = FromCombination` -> `InputErr`;
- если `N >= Ncr` хотя бы в одной главной плоскости -> `FAIL`;
- если `eta` получается отрицательной или чрезмерно большой из-за близости к `Ncr` -> `FAIL` с подробным `StopReason`;
- если главные инерции почти равны, угол главных осей может быть условным, но результат должен быть устойчив к повороту осей.

Для случайного эксцентриситета:

- при ненулевом моменте знак `ea` рекомендуется принимать по знаку существующего эксцентриситета;
- при почти нулевом моменте в одной из плоскостей рекомендуется режим `Envelope`: проверить оба знака `ea` и принять более неблагоприятный результат;
- это нужно явно зафиксировать как программную реализацию, потому что СП 63 не дает готового алгоритма для произвольного несимметричного `N + Mx + My`.

## 6. Результаты и справка

На `Results` стоит добавить отдельный блок в Summary:

```text
Устойчивость сжатого элемента
StabilityStatus | eta1 | eta2 | Ncr1 | Ncr2 | e0,1 | e0,2 | ea1 | ea2 | phi_l,1 | phi_l,2 | Mx_design | My_design
```

В `rngNDMSectionProperties` нужно оставить справочные геометрические характеристики бетонного и приведенного сечения, но расчет устойчивости не должен читать их с листа.

На листе `Справка` нужно добавить user-guide раздел:

- когда проверка включается;
- чем отличается случайный эксцентриситет от учета прогиба через `eta`;
- какие поля пользователь задает в `Config`;
- почему `l0` задается по двум главным плоскостям;
- как учитываются длительные нагрузки;
- что означает `StabilityStatus`;
- что программа делает для несимметричного сечения и повернутых главных осей;
- какие решения являются прямым СП, а какие являются программной реализацией для общего `N + Mx + My`.

## 7. Тесты перед внедрением

Минимальный набор регрессий:

1. `ea = max(l/600, h/30, 10 mm)` для нескольких `l/h`.
2. `l0 = k0*l` по двум осям.
3. `eta = 1/(1 - N/Ncr)` на известных числах.
4. `D = kb*Eb*I + 0.7*Es*Is`.
5. Ограничение `0.15 <= delta_e <= 1.5`.
6. Ограничение `phi_l <= 2`.
7. Round-trip поворота моментов `Global -> Principal -> Global`.
8. Сравнение результата для симметричного прямоугольника с ручным расчетом по одной плоскости.
9. Проверка `N >= Ncr -> FAIL`.
10. Проверка `Group2 -> StabilityStatus = N/A`.
11. Проверка, что `CSectionSolver` и `CCapacitySolver` не читают настройки устойчивости и получают только готовые усилия.
12. Проверка, что `Results` не используется как источник входных расчетных данных.

## 8. Спорные места перед реализацией

1. Центр для эксцентриситетов: текущий пользовательский ввод привязан к бетонному центру, а п. 8.1.7 для статически неопределимых конструкций говорит о приведенном сечении. Нужно утвердить внутреннее правило пересчета.
2. Знак случайного эксцентриситета при двухосном изгибе и почти нулевом моменте: предлагается `Envelope`, но это программное инженерное решение.
3. Длительная часть нагрузки: без отдельных `N_long/Mx_long/My_long` расчет `phi_l` не является нормативно полным.
4. Строгий capacity safety factor с пересчетом `eta(lambda)` внутри каждой пробной lambda-точки потребует нелинейного target-provider. Первая реализация может ограничиться проверкой текущего LC с последующим расчетом прочности по скорректированным усилиям.
5. Использовать ли локальные инерции бетонных элементов при расчете `I`: для устойчивости это желательно, особенно при грубой сетке.
6. Что делать с сечением без продольной арматуры: формула `M1/Ml1` привязана к стержню арматуры, поэтому нужна отдельная договоренность.

## 9. Рекомендуемый объем первой реализации

Рекомендуется реализовать не весь возможный второй порядок, а ровно проверку по п. 8.1.2 и 8.1.15 в текущем NDM-конвейере:

1. Добавить настройки устойчивости на `Config`.
2. Добавить длительные компоненты в LC или явно запретить расчет устойчивости без них.
3. Добавить `CStabilitySettings`, `CStabilityCalculator`, `CStabilityResult`.
4. Расширить `CSectionPropertiesCalculator` расчетом свойств для устойчивости в памяти.
5. Вставить этап устойчивости в `CBatchSectionCalculator` перед Group1 DirectState/Capacity.
6. Передавать в существующие проверки прочности скорректированные усилия.
7. Не менять `CSectionSolver`, `CCapacitySolver`, `CMaterialModelProvider` без крайней необходимости.
8. Вывести подробные величины устойчивости в `Results` и `Справка`.
9. Покрыть формулы и поворот осей unit-тестами до проверки на реальных сечениях.
